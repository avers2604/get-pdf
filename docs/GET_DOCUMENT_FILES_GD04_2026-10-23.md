# GD-04 — ГЭТ Файлы: первый модуль подключения к сетевым папкам

Дата: 23 октября 2026. Базовая ветка — GD-03B (#14).

## Реализация
- Лаунчер и верхняя панель получили «ГЭТ Файлы». Это **одна вкладка в общем окне**,
  а не новая программа, окно или файловый сервер.
- Сотрудник вводит существующий UNC путь Windows Server 2016
  (пример: `\\\\server\\share`) либо выбирает папку в системном диалоге Avalonia.
  На Linux используются SMB/CIFS каталоги, уже смонтированные в файловую систему;
  перенос на Linux/Samba не меняет файловый API в ядре.
- Нет новых логинов, паролей, пользовательских баз данных, регистрации службы,
  копирования хранилища, облака, телеметрии или внешнего HTTP.
- `RootedFileBrowser` — независимый `net10.0` Core: читает только выбранный
  каталог (без рекурсии), поддерживает вход/выход, сортировку,
  показывает поддерживаемые форматы, ограничивает отображение 400 элементами.
  Для больших папок нужен отдельный серверный поиск — пока не реализован.
- Навигация удерживается внутри выбранного корня, вход через symbolic links/junctions
  запрещён; файлы перепроверяются перед передачей штатному просмотровщику.
  **Это не sandbox**: отзываемые ACL, гонки TOCTOU и сетевые отказы должен обрабатывать
  downstream reader; сервер/ОС остаётся окончательным источником прав.
- Двойной щелчок или «Открыть / перейти» открывает каталог внутри файловой вкладки
  либо документ через существующий DocumentWorkspace.OpenExisting(path).
  Повторно открытый файл не создаёт новую вкладку.
- `FileSystemWatcher` сигнализирует об изменениях папки, но не считается надёжным
  на SMB и Samba. Каждые 30 секунд выполняется повторное перечисление
  выбранной папки; UI освежает список не чаще чем раз в 5 секунд при событиях.
- Фильтр имён работает **только по текущему списку до 400 элементов**.
  Полнотекстовый индекс и поиск по всем сетевым каталогам НЕ заявлены.
- Пути, имена файлов и пароль не сохраняются в журнал/локальные настройки
  этим модулем. В старом WPF приложении свои политики не менялись.

## Наличие и ограничения
ГЭТ Файлы **не редактирует** файлы, не синхронизирует копии, не создаёт версии
и не выполняет скрытые привилегированные операции. Файлы разрешённых форматов
передаются в уже существующие модули PDF, изображения и простого DOCX.
Предпросмотр сложных Office форматов остаётся ограничен существующими адаптерами.

Работа не проверялась на реальном сервере Windows Server 2016 или Samba.
Настройка права файлового сервера / перенос на Linux в данном PR не выполнялись.

## Тесты
До логики были внесены 6 тестов `RootedFileBrowserTests`: один уровень,
неподдерживаемые типы, уход в родительский каталог, переход в подпапку,
ограниченный листинг, символические ссылки Linux и повторная проверка файла.
В доступном окружении `dotnet` CLI отсутствует: тесты **написаны, но не запущены**.

Обязательная локальная приёмка на Windows / Linux:
```sh
dotnet restore GetDocument.slnx
dotnet build GetDocument.slnx -c Release --no-restore
dotnet test tests/GetDocument.Core.Tests/GetDocument.Core.Tests.csproj -c Release
dotnet test tests/GetDocument.Office.Tests/GetDocument.Office.Tests.csproj -c Release
```
Реальная лаборатория: SMB ACL, сотрудник без доступа, отзыв разрешений,
сетевой обрыв, большой каталог, имена на русском, папки на Samba/CIFS,
дублирующее открытие, отмена системного диалога, 30-секундная пересверка,
symlink/junction, обновления в Проводнике и отсутствие сохранённых путей.
GitHub Actions не включать. PR оставить Draft до получения результатов.
