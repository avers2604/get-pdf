# GD-16: Собственный мастер печати «ГЭТ Документ»

**Дата:** 25.10.2026. **Состояние:** реализация в Draft-ветке после GD-15 (#37); сборка и аппаратная приёмка **не проведены**.

## Утверждённое UX-правило

**Не вызывать стандартный PrintDialog Windows / GTK / CUPS.** Все действия пользователя выполняются в *собственной вкладке* «Печать» в едином окне ГЭТ, с брендингом из основной оболочки.

Система не разрабатывает драйверы МФУ. После подтверждения собственных настроек задание передаётся установленным локальным очередям печати Windows (WPF XPS PrintQueue) или Linux (CUPS `lp`). Это сохраняет совместимость с локально настроенными офисными и сетевыми принтерами, но требует настоящих ОС-драйверов и тестов устройств.

### Шаги мастера

1. **Устройство:** список установленного принтерного пула и ручное обновление, пустой список — явная ошибка, автоматического выбора неизвестного «принтера по умолчанию» нет.
2. **Параметры:** все страницы или `1,3-5`, копии 1–99, A4/A3, односторонняя, двусторонняя по длинному/короткому краю.
3. **Подтверждение:** итоговая сводка, число отпечатков, отправка только после отдельного подтверждения. После успешного принятия очередь не вызывается повторно нажатием кнопки. При неясном исходе оператору предлагается проверить очередь до повторной отправки.

В правой части — ограниченный предпросмотр **первой** PDF-страницы. В компактном окне правый блок располагается ниже параметров. Это предпросмотр исходного документа, **не точная имитация печатных полей/прошивки драйвера**.

### PDF-область действия

На GD-16 пока печатаются **сохранённые PDF**, включая исходные PDF в файле, открытом через GetDocument. Для DOCX/XLSX/PPTX требуется штатный движок Office-конвертации/печати с максимальным MS Office roundtrip; не создавать фиктивную «успешную печать» из пустой страницы.

В оригинал PDF, WORM-копию, версионную историю и электронные подписи никаких записей не производится.

## Архитектура и повторное использование

- `PrintJobPlan` в Core — неизменяемый список страниц; строгие ограничения на диапазон и копии; каноническая `CupsPageRange`.
- `CupsPrintArguments` — строит список argv из валидированного задания. Не собирает командную строку для shell, не интерполирует локальный путь в скрипт и не выполняет PowerShell.
- `PrintWizardPane` — отдельная Avalonia вкладка 3 шага. Использует существующий `PDFtoImage` для предпросмотра, `PdfNativeGate` объединяет семафор PDFium с основной PDF-вкладкой.
- Linux — `LocalPrintBroker` вызывает `lpstat -e` (или `lpstat -p` на более старом CUPS) и `lp` через безопасный `ProcessStartInfo.ArgumentList`, с ограниченным временем ожидания. Перед submit ещё раз проверяется существование принтера. Коды ошибок не трактуются как успех; система не меняет CUPS defaults.
- Windows — **отдельный невидимый процесс** `GetDocument.PrintWindows.exe`, WPF `PrintQueue`/`XpsDocumentWriter`/`PrintTicket`. Он запускается из Avalonia без второго окна по локальному стандартному вводу; получает только выбранный путь и настройки, заново проверяет количество страниц, возможности принтера и допустимые настройки. Декодирует страницу по требованию через `DocumentPaginator` вместо загрузки всего PDF в RAM; растры ограничены `PdfPrintRasterPlan` 3200px/10MP. Никаких окон `PrintDialog`.
- **Print spooler confirmation ≠ физически напечатанный документ**. В UI указываем только принятие в очередь; бумага, замятие, состояние МФУ не определяются этим этапом.

### Офлайн-комплект Windows

В Windows release должны поставляться **оба исполняемых файла в одной папке**. Для подготовки выкладки:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify-get-document-windows.ps1
powershell -ExecutionPolicy Bypass -File packaging/publish-get-document-windows.ps1
```

Второй скрипт создаёт `artifacts/get-document-win-x64/application/`, публикует desktop и worker self-contained, **не меняет обработчик .pdf**, не регистрирует принтеры и не ставит корпоративный сертификат. Специальный windows-WPF worker не добавлен в Linux-target `GetDocument.slnx`, чтобы не требовать Windows Desktop targeting pack на офлайн Linux.

Linux необходимо проверить `lpstat`, `lp`, CUPS, драйверы/права; общий локальный runner — `bash scripts/verify-get-document-linux.sh`. После запуска `GetDocument.Desktop` системное окно печати открываться не должно.

## Обязательная аппаратная приёмка

- На Windows: USB, SMB/AD и сетевой принтер (HP, Canon, Bulat, Katyusha по доступности), A4/A3, 1/2/99 копий, стороны, сравнение первой и последней PDF-страниц, кириллица/таблицы/цвет, реальное выполнение задания, очередь/отмена/бумага, ограничения драйвера.
- Linux Astra/ALT/РЕД: CUPS различной версии, отсутствие `lp`/принтера, права на очередь, A3/дуплекс/сетевые принтеры, длинные имена PDF, без стандартного GTK print dialog.
- Инварианты: WORM не меняется; не передавать содержимое документа в облако; повторная отправка после таймаута только после проверки очереди; отсутствие shell injection и скрытого изменения defaults; корректное закрытие вкладки во время чтения/печати; проверка на старом ПК и двух мониторах.
- Виртуальные PDF-принтеры могут открывать **собственный драйверный диалог**; этот вариант печати и обработка сохранения PDF требуют отдельной политики/UX, GD-16 его не гарантирует.
- DPI/landscape/поддержка формата и поля: результаты зависят от драйвера, предпросмотр GD-16 не симулирует реальные поля. Полноценная ориентация, цвет/ЧБ, лотки и 2-up — следующий этап после E2E с оборудованием.

## Написанные тесты

- `PrintJobPlanTests`: полный диапазон, сложные интервалы, дубли, 0/99/100 копий, некорректные строки/принтеры, сортировка.
- `CupsPrintArgumentsTests`: строго argv, путь с русскими буквами/пробелами, бумага и стороны, запрет относительных и не-PDF файлов.
- `PdfPrintRasterPlanTests`: пропорции, длинные/широкие страницы, память <= 10 MP и некорректные размеры.
- Кроссплатформенная компиляция: `dotnet restore GetDocument.slnx && dotnet build GetDocument.slnx -c Release`, MSTest в Core.
- Windows дополнительно: `dotnet build src/GetDocument.PrintWindows/GetDocument.PrintWindows.csproj -c Release`, затем обязательная ручная печать.

**Доступный исполнитель не имеет .NET 10 SDK, Windows print spooler, CUPS и принтеров. Поэтому ни сборка, ни программные MSTest, ни реальная печать не подтверждены. PR держать Draft; merge только после проверки.**
