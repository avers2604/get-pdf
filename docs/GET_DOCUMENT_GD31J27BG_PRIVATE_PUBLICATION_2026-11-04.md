# GD-31J.27bg — приватная временная копия и публикация без перезаписи

**Репозиторий:** `avers2604/get-pdf`. **Ветка:** `feature/gd31j27bg-private-copy-publication`, stacked Draft поверх GD-31J.27bf / PR #171.

**Режим:** исходники и тестовые сценарии; сборка .NET, MSTest, Python unittest, NTFS/Astra/SMB-стенд и GitHub Actions **не выполнялись**. Production `OfficeRecoveryStore`, пользовательские документы, WORM, GUP-2 и native EuroOffice SaveAs не менялись. `releaseReady=false`.

## Разделение проверки и публикации

GD-31J.27bf передавал байты из подтверждённого открытого дескриптора в новый поток и возвращал SHA/ZIP receipt. Он не отвечал за владение результирующим файлом. Передача одного только пути в реальное восстановление могла снова создать TOCTOU-риск, а обычная запись по указанному пользователем имени — риск перезаписи документа.

Создан **не подключённый к приложению** модуль `src/GetDocument.Office/LibreOffice/RecoveryPrivateCopyPublisher.cs` с двумя внутренними типами:

- `RecoveryPrivateCopyPublisher.PublishAsync(session, sha, extension, cancellationToken)` получает уже проверенную `RecoveryVerifiedStreamStage` (синтетические тесты используют `FakeAdapter`; реальные Windows/Linux native identity adapters всё ещё отключены).
- `RecoveryPrivatePublication` удерживает один и тот же открытый `FileStream` после публикации; объект владеет только своей временной копией. `FilePath` — информационное имя **в изолированном временном каталоге**, **не** право восстановить документ и **не** доказательство актуальной идентичности пути при следующем открытии.

### Контракт создания и записи

1. Сначала проверяются расширение `.docx/.xlsx/.pptx`, полный SHA-256 и токен отмены. `RecoveryVerifiedStreamStage` передаётся под владение `using(session)` и всегда освобождается.
2. `Directory.CreateTempSubdirectory("getdoc-recovery-private-")` создаёт **новый случайный каталог в системной временной области**. Пользовательский путь назначения не принимается. Требуется отдельная проверка ACL/режима создания каталога на Windows 10/11, Astra Linux и SMB; название `private` само по себе не является доказательством ограничения доступа.
3. Генерируется новый `Guid.NewGuid().ToString("N")`. В этом каталоге создаётся `GUID.part.docx` (или xlsx/pptx) с `FileMode.CreateNew` и `FileAccess.ReadWrite, FileShare.Delete`, без перезаписи уже имеющихся файлов.
4. `session.StageToAsync` копирует байты именно с удерживаемого source handle, проверяет SHA и ZIP/XML. Затем вызываются `Flush(flushToDisk:true)`, дополнительные проверки ссылки/размера, независимая проверка SHA+ZIP исходного staging-потока.
5. Тестовый внутренний callback `beforeRename` позволяет детерминированно воспроизвести коллизию имени или отмену **перед** переименованием. Не используется production.
6. Только `File.Move(stagingPath, destination, overwrite:false)` переводит собственный файл `GUID.part.docx` в `GUID.docx` **в том же каталоге и на том же томе**. Никаких `File.Replace`, `overwrite:true`, записей в исходный документ или WORM. При занятом финальном имени операция обязана отказать, не заменив его.
7. После rename SHA/ZIP проверяются ещё раз через **тот же открытый FileStream**. Объект `RecoveryPrivatePublication` удерживает дескриптор до `Dispose`. Это временная копия, а **не** опубликованная версия или завершённое восстановление пользователя.

### Ошибки и владение

- Если SHA, ZIP, доступ к staging или перемещение не подтверждены, *receipt публикации не возвращается*. Исходный lease закрывается.
- При ошибке до переименования удаляется только путь созданного в данном вызове `GUID.part.docx`; после успешного rename, но последующей ошибки — только собственный конечный `GUID.docx`. **На конфликт имени с уже существующим файлом назначения нет разрешения его удаления.**
- `TryDeleteOwnRegularFile` допускает очистку только прямого ребёнка собственного каталога, отказывает при link/reparse/каталоге/устройстве. `TryRemoveEmptyPrivateDirectory` использует исключительно `Directory.Delete(..., recursive:false)`, так что посторонние файлы и непустой каталог остаются.
- `RecoveryPrivatePublication.Dispose()` закрывает удерживаемый поток и удаляет собственный временный результат по тем же правилам. Повторный `Dispose` бездействует.

**Ограничение TOCTOU:** очистка по имени даже в случайном приватном каталоге не имеет криптографически доказанной идентичности дескриптора. Если злоумышленник может менять имена внутри этого каталога, путь может быть подменён перед `File.Delete`. Проверка ссылки и локальности пути снижает риск, но не устраняет враждебные гонки. Для production нужны проверенная ACL/0700 и очистка/передача на базе идентичности дескриптора. Пока модуль **не включается** в реальное восстановление.

**Ограничение durability:** `File.Move` в пределах одной файловой системы может обеспечить атомарную смену имени при нормальном поведении FS, но `Flush(true)` и rename без подтверждения синхронизации родительского каталога **не дают общей гарантии устойчивости после power loss**, особенно на SMB. Это предстоит проверить на OS-стенде.

**Ограничение потребителя:** вызывающий код получает `FilePath`, но не должен повторно открывать его как проверенный документ. Удерживаемый stream остаётся внутри `RecoveryPrivatePublication`; непосредственный безопасный API передачи потребителю и атомарный commit в хранилище — отдельный следующий этап, без прав перезаписи исходников/WORM.
