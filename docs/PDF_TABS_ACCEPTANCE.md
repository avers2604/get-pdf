# ГЭТ PDF — архитектура вкладок и Windows-приёмка

## Модель

После PR #2 `PdfViewerWindow` — исторически названный WPF `UserControl`, НЕ настоящий Window. Он содержит PDF state: `PdfPagePlan`, `PdfEditHistory`, `PdfLazyPageStore`, `DocumentSession`, `DocumentRenderScheduler`, `PdfTextIndex`, OCR, print spool и приватный scratch каталог. Это обеспечивает независимость PDF при переключении вкладок.

`PdfTabbedWindow : Window` владеет `TabControl`, заголовками, количеством вкладок, порядком, закрытием и выносом в отдельное окно. `PdfTabRegistry` — чистая модель порядка и идентичности, `PdfTabSessionStore` — атомарное сохранение **только путей** для восстановления при следующем запуске. Запись ограничена 16 PDF; файлы не содержат PDF data.

`Viewer_Loaded` открывает начальный PDF **один раз**; повторная загрузка контрола при переключении WPF ContentPresenter не вызывает re-import. При закрытии есть двухфазный процесс: `CanCloseDocument` проверяет, что задания не выполняются, и спрашивает об изменениях, затем `ReleaseForCloseAsync` останавливает задачи рендера, OCR, индексов и очищает ресурсы одной вкладки. При закрытии всего окна сначала запрашивается подтверждение всех вкладок, только потом производится cleanup.

Вынос в отдельное окно переносит сам экземпляр `UserControl`, а не открывает исходный PDF повторно. `Ctrl+Tab` / `Ctrl+Shift+Tab` переключают вкладки, F11 работает на уровне окна, а не вкладки.

## Корпоративная политика

Пример `%PROGRAMDATA%\\GET-PDF\\policy.json`:

```json
{
  "Version": 1,
  "AllowPdfViewer": true,
  "AllowPrinting": true,
  "RememberRecentDocuments": false,
  "RestoreTabs": false,
  "MaxPdfInputMiB": 1024,
  "MaxDocumentPages": 1000,
  "MaxRecoverySessionMiB": 8192,
  "RecoveryReserveMiB": 256
}
```

При отключении флагов программа не сохраняет соответствующие списки путей и пытается удалить их ранее сохранённые файлы пользователя. Если файл недоступен для удаления, ошибка журналируется, но запуск просмотрщика не блокируется.

## Ограничения / gate

- Код **не прошёл** `dotnet build`, `dotnet test` или WPF-интеграционные тесты — текущий инструмент не предоставляет Windows/.NET SDK 10.
- Восстановление возвращает список путей и активную вкладку, но не сериализует открытые файлы, PDF-байты, search query, историю Undo или внутренние объекты страницы. Редакторские черновики возвращаются по уже существующему механизму восстановления.
- Невозможно обещать отсутствие утечек unmanaged PDFium/NAPS2 памяти без проверки на длинной серии переключений.
- Одновременное закрытие нескольких вкладок, загрузка с UNC и вынос при выполнении OCR требуют реальных Windows-UI тестов.
- Копирование страниц: открыть A и B, включить редактор, перетащить миниатюру A на вкладку B. После подтверждения страница должна появиться **в черновике B**, после выбранной страницы, без изменения SHA-256 файлов A и B. Проверить Ctrl+Z, Ctrl+Y, сохранение итоговой отдельной PDF-копии и повторное открытие.
- Через «Копировать страницу в другой PDF…» выбрать альтернативный пункт «Создать отдельный PDF»: итоговый PDF создаётся новым файлом без изменения черновика B.
- Исходный A с несохранёнными правками не импортируется; изменённый B может принять страницу без потери собственной разметки и порядка страниц (при условии отсутствия неэкспортируемых native-эскизов).
- После вставки в B симулировать аварийное закрытие тестовой VM и восстановить черновик: в нём должна остаться вставленная страница. Проверить Undo/Redo после повторного запуска в пределах поддерживаемой истории.
- Проверить, что повторные вставки создают уникальные sourcePage, а при 10000 исторических источников или достижении MaxDocumentPages вставка запрещается.
- Драг источника, если страница удалена или перемещена: идентификатор должен гарантировать правильный выбор или отказ. Запретить перенос через drag вне режима редактирования.
- Проверить B, которая ни разу не открывалась визуально: операция загружает её ровно один раз и не требует предварительно щёлкать по вкладке.
- Убедиться, что PDF с черновыми изменениями, подписанный или с неподдерживаемой структурой не модифицируется и не даёт ложного сообщения об успехе.
- Копирование страницы из A в ранее не выбранную вкладку B: B открывается ровно один раз; итоговый PDF сохраняется отдельным файлом с правильным порядком страниц и исходными SHA-256.
- Копирование с изменениями в A/B блокируется. Проверить отмену через кнопку задания, удаление внешнего файла в ходе операции, недостаток свободного места и защищённый PDF.
- Автоматические GitHub Actions не используются. Не объединять draft PR с main до локального Windows gate и тестирования печати.
