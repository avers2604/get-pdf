# ГЭТ Документ — лаунчер, общие вкладки, ГЭТ Сканирование, секретная игра

## Рабочий план
1. В одном окне всегда доступна вкладка «Главная».
2. Кнопки «Текстовый документ», «Таблица», «Презентация» создают
   **несохранённый черновик-вкладку**; генерация настоящего DOCX/XLSX/PPTX
   и редактирование появятся после подключения Office engine.
3. Действие «Открыть» создаёт в верхней полосе вкладку для любого
   распознанного PDF, Office-файла или изображения, активирует существующую
   вкладку при повторном открытии того же пути. Формат определяется ПОКА
   только по расширению; содержимое ни разу не парсится и не отображается.
4. Контракт `DocumentWorkspace` живёт в общем `net10.0` Core и не зависит
   от Avalonia, WPF, Windows. На Windows пути сравниваются без регистра,
   на Linux — с регистром. Восстановление путей не записывается по умолчанию.
5. «ГЭТ Сканирование» зарезервировано как отдельная вкладка-интеграция;
   приложение GUP-Scan не копировать в офисный репозиторий.
6. Скрытая игра «Дурак»: 10 быстрых последовательных нажатий на
   официальный знак ГЭТ в левом верхнем углу. Открывается закрываемая вкладка с описанием статуса
   онлайн-игры. ИГРОВОЙ ДВИЖОК И СЕРВЕР НЕ РЕАЛИЗОВАНЫ.
   Gateway — только интерфейс, сеть выключена, публичных URL нет.
   Перед будущим сетевым режимом: согласовать корпоративную политику
   и разрешённый внутрисетевой адрес; не размещать в GUP-2 или GET-system
   скрытую внешнюю передачу данных.
7. Не допускать отдельного окна на каждый формат: вся навигация идёт через
   единый TabControl. Встроенный движок PDF/WPF всё ещё находится в старом приложении.
   Автоматический запуск WPF из Avalonia запрещён, чтобы не нарушить требование.

## Наличие функций
- Реально реализованы: Core таб-реестр, дедупликация вкладок, команды
  навигации и создания *пустых сессий*, скрытый счётчик и начальный UI.
- Не реализованы: создание файлов DOCX/XLSX/PPTX на диске, редактирование,
  PDF/Office/Image renderer в Avalonia, реальная печать через адаптер,
  интра-серверная игра, работа сканера. UI явно показывает заглушки.

## Зависимости
- Добавляются Avalonia.Desktop 12.1.4 и Avalonia.Themes.Fluent 12.1.4
  ТОЛЬКО в отдельный прототип `GetDocument.Desktop`.
- Старые зависимости WPF/PDF остаются без изменений.
- В `GetDocument.Core` нет новых сторонних библиотек.
- Веб-версию по-прежнему не создаём.

## Приёмка
В окружении отсутствует .NET SDK: компиляция и MSTest новых исходников
не запускались. Старые PDF-тесты не подменяют эти проверки.

На Windows или Linux с .NET SDK 10:
```
dotnet restore GetDocument.slnx
dotnet build GetDocument.slnx -c Release --no-restore
dotnet test tests/GetDocument.Core.Tests/GetDocument.Core.Tests.csproj -c Release
dotnet run --project src/GetDocument.Desktop/GetDocument.Desktop.csproj
```
GUI acceptance: создание трёх типов вкладок, открытие нескольких
разноформатных файлов, повторная активация вкладки, закрытие вкладки,
Ctrl+T/O/W, 9 и 10 нажатий на шапку, отсутствие внешнего трафика,
отказ при недоступном SMB и возврат в «Главная».
PDF регрессии старой WPF программы — отдельно, до слияния.
