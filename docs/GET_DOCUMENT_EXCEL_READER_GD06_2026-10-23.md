# GD-06 — ExcelDataReader, первый read-only импорт XLS/XLSB

Реализовано в черновом PR поверх #18, по SOURCE-FIRST; самостоятельный
парсер BIFF/XLSB, таблица формул и редактор Excel **не разрабатывались**.

- `ExcelDataReader 3.9.0` (MIT) — готовый движок чтения XLS, XLSB и XLSX.
  `System.Text.Encoding.CodePages 10.0.0` — старые кодировки XLS на Linux.
  Редактирование XLSX A1:J10 остаётся в ранее принятом прототипе #18.
- Добавлен `GetDocument.Office.Spreadsheets.ReadOnlySpreadsheetPreview` для
  прочтения первого листа без изменения исходного файла/вычисления формул,
  без облака и без запуска Excel/LibreOffice.
- Ограничения: исходник не более 32 МиБ, максимум 100 строк × 20 столбцов
  в UI, ячейка не более 256 символов для отображения. `SinglePassMode=true`
  уменьшает предварительное сканирование, `AsDataSet()` запрещён.
- XLS/XLSB открываются внутри существующей вкладки `TabControl` через
  `SpreadsheetReadOnlyPane` (без кнопки сохранить); XLSX-модуль #18
  продолжает использовать собственную ограниченную сетку для простых таблиц.
- Типы ячеек форматируются для отображения; удаляются управляющие и bidi
  символы. Формулы **не вычисляются** и не экспортируются обратно в Excel.
- Работает с локальными файлами и доступным файловым сервером SMB в контексте
  пользовательских прав; пароли нигде не сохраняются.
- Добавлено 6 MSTest: действительный XLSX от Open XML SDK, кириллица,
  пустая таблица, отказ неподдерживаемого формата, ограничения и очистка
  управляющих символов.
- Реальные бинарные XLS/XLSB тестовые документы пока отсутствуют; поэтому
  это испытание НЕ подтверждает поддержку конкретных производственных файлов.

**Границы безопасности:** ограничения длины/строк не гарантируют защиту
от ZIP-бомб в XLSB/XLSX, вредоносных контейнеров/уязвимостей парсера и
недоступности SMB. Для производственного просмотра недоверенных документов
нужен изолированный worker-процесс, лимиты RAM/времени и проверенные тестовые
образцы. UI пока начальный предпросмотр без лицензированного Excel-движка.

Проверка зависимостей: `Avalonia.Desktop 12.1.4` и `PDFtoImage 5.4.0`
сосуществуют в отдельном UI; при этом они требуют разные major версии
SkiaSharp (Avalonia.Skia >=3.119.4; PDFtoImage >=4.150.1).
До release обязателен restore/build/runtime smoke на обеих ОС и при
необходимости изоляция PDF-рендерера или изменение зависимости.

В рабочей среде нет .NET SDK: **restore, build, MSTest, UI-тесты не запускались**.
Нет сетевого доступа из контейнера для установки SDK или клонирования исходников.

```sh

dotnet test tests/GetDocument.Office.Tests/GetDocument.Office.Tests.csproj -c Release
dotnet test tests/GetDocument.Core.Tests/GetDocument.Core.Tests.csproj -c Release

```
