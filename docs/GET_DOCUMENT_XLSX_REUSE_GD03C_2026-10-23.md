# GD-03C — перенос ограниченного XLSX-редактора из PR #13 (SOURCE-FIRST)

## Основание
Единый план в `main`: использовать уже существующий код прежде, чем создавать новый.
PR #13 базируется на альтернативном DOCX PR #12, тогда как GD-04/05 построены поверх
основной линии #14 → #15 → #16. Поэтому XLSX функциональность перенесена **без переноса
зависимого DOCX-редактора** и без дублирования уже созданной офисной инфраструктуры.

## Что в исходниках
- `src/GetDocument.Office/SimpleXlsxEditor.cs` — переиспользован в исходном виде из PR #13.
  Используется **существующий** `DocumentFormat.OpenXml 3.5.1` через `GetDocument.Office`;
  новых NuGet-пакетов и отдельного Spreadsheet-движка не добавлено.
- `src/GetDocument.Desktop/Preview/SimpleXlsxEditPane.cs` — адаптирован из PR #13
  к текущим контрактам `PreviewFactory` и `MainWindow` из основной ветки (#14–#16).
- Для действительного XLSX при поддерживаемой структуре открывается **вкладка**
  с 10×10 редактируемыми текстовыми ячейками (A1:J10), сохранением новой редакции и
  предупреждением о несохранённых изменениях. Сохранённая редакция открывается
  в собственной вкладке; источник сохраняет прежний путь/байты.
- Значения с `=` остаются **буквальным текстом**, никакого вычисления формул.
- Сложные XLSX (формулы, стили, несколько листов, связанные объекты и объединения)
  не редактируются: в интерфейсе остаётся явный статус о недоступности режима.
- Используются существующий SaveFilePicker и `DocumentWorkspace.OpenExisting`, а
  **не** дополнительный API `BindNewRevision` из PR #13, несовместимый с основной веткой.
- При ошибке/отмене Save As редактор остаётся в состоянии несохранённых правок;
  при успешном сохранении рабочие значения считаются сохранённой контрольной точкой.
- Вкладка или главное окно блокируют закрытие с несохранёнными правками DOCX **и XLSX**.

## Тесты
- 5 тестов `SimpleXlsxEditorTests` буквально переиспользованы из PR #13,
  2 теста добавлены на неизменность оригинала и предельный размер текста в ячейке,
  1 интеграционный тест — две XLSX-редакции во вкладках, без дублирования.
- Набор выполняет проверку структуры OOXML и отсутствия записи формул в текстовые ячейки.
- Тесты **не выполнялись**: в текущей среде нет `dotnet` CLI.
  Их наличие не подтверждает компиляцию и безопасность чтения повреждённых ZIP/OOXML.

## Локальная приёмка и запрет слияния
```sh
dotnet restore GetDocument.slnx
dotnet build GetDocument.slnx -c Release --no-restore
dotnet test tests/GetDocument.Core.Tests/GetDocument.Core.Tests.csproj -c Release
dotnet test tests/GetDocument.Office.Tests/GetDocument.Office.Tests.csproj -c Release
```
Windows + Linux UI: открыть XLSX из лаунчера и «ГЭТ Файлы»; изменить ячейки;
сохранить отдельную редакцию и убедиться, что исходник не менялся;
отменить Save As; закрыть вкладку и всё окно с несохранёнными правками;
проверить SMB/ACL, гонку с внешним изменением, кириллицу, отсутствие формул;
разные файлы одновременно с PDF, DOCX и изображениями.

## Известные риски
- Это **не полноценный Excel** и не поддержка XLSB. Для сложных электронных таблиц
  нужен выбранный после испытаний движок LibreOffice / ONLYOFFICE / Collabora,
  а ExcelDataReader пригодится только для импорта.
- Проверка структуры и ограничения 8 МиБ **не заменяют** изоляцию недоверенных
  ZIP/OOXML. Требуются проверки потенциальных архивных бомб, прав доступа и отмены.
- Собственный простейший редактор не должен заменить полноценный API выбранного
  движка и не должен использоваться для преобразования сложных корпоративных файлов.
- На Linux проверить `FileSystemWatcher`, нативные зависимости PDF/Avalonia отдельно.
- Существующий WPF GetPdf, GUP-Scan и GUP-2 не изменяются.
- Не включать GitHub Actions. Оставить Draft до локального `build/test` и UI-приёмки.
