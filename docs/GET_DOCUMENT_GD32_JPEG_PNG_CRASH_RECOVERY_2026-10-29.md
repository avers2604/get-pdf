# GD-32 — безопасная очистка JPEG/PNG после аварийного завершения

Дата: 2026-10-29. Репозиторий: `avers2604/get-pdf` («ГЭТ Документ»).
Статус: реализация и MSTest-контракты; **локальная сборка и фактический запуск тестов ещё не подтверждены**.

## Проблема

Прежняя реализация `GetDocument.Images.ImageEditService` записывала
`.get-image-{GUID}.png` прямо в выбранную папку и удаляла его через
`finally`. При `taskkill /F`, отключении питания или аварии native-процесса
`finally` не выполняется: в пользовательской папке остаётся неполная копия.
Эти исторические файлы не содержат проверяемого маркера принадлежности,
поэтому **автоматически удалять их нельзя**.

На дату реализации штатное сохранение нового редактированного изображения
существовало только в PNG. В GD-32 дополнительно разрешён JPEG как новый
целевой формат без изменения исходного файла и без перезаписи существующей
пользовательской редакции.

## Реализованный контракт

1. Перед экспортом создаётся только каталог вида
   `.get-document-image-<32 символа GUID N>` внутри папки назначения;
   его имя проверяется строго, без масок для удаления файлов.
2. В каталоге создаётся файл
   `.get-document-image-owner` с точным содержимым
   `get-document-image-export-v1`. Он удерживается через
   `FileShare.None` до конца операции.
3. Кодек пишет строго `stage.png` или `stage.jpg` — расширение задаёт
   действительный формат. На успешном завершении проверяется неизменность
   оригинала и выполняется `File.Move(..., overwrite: false)` на одном томе.
4. `Dispose` удаляет только свой staging-каталог. Если программа была
   принудительно завершена, следующий экспорт **в ту же папку** проверяет
   каталоги старше 24 часов по времени маркера. Нет сканирования всей системы
   или удаления сразу после запуска.
5. Очистка разрешена только когда одновременно выполнены:
   точное GUID-имя, обычный каталог (не symlink/reparse), обычный marker
   с точными байтами, отсутствие активной эксклюзивной блокировки,
   и допустимый полный перечень объектов: marker + максимум один
   `stage.png` либо `stage.jpg`.
6. Незнакомый файл, дополнительная папка, ссылка, неправильный marker,
   неподходящее имя или активная операция означают **не удалять ничего**.
   Удаление строго поимённое и нерекурсивное; ошибки очистки не отменяют
   успешный экспорт. Законченная редакция находится вне staging и не
   участвует в очистке.
7. Никакого автоматического восстановления или публикации неполных
   JPEG/PNG из staging: только безопасная утилизация после выдержки.
   Исходный документ, WORM-оригинал и уже опубликованная редакция не
   изменяются этим механизмом.

Модель заимствует принцип TIFF-staging (изоляция, владелец, lease,
запаздывающая ограниченная очистка), но исходные файлы «ГЭТ Сканирование»
и его репозиторий здесь не модифицируются.

## Проверка

Добавлены MSTest для PNG/JPEG: публикация и удаление private-scratch;
очистка старых каталогов; запрет удаления активного, недавнего,
непомеченного, неправильно названного или содержащего сторонние файлы;
сохранность пользовательских документов и прежних временных файлов;
экспорт JPEG с неизменным оригиналом.

Для .NET 10 в локально одобренном окружении:

```bash
dotnet test tests/GetDocument.Images.Tests/GetDocument.Images.Tests.csproj
```

Обязательный ручной Windows/Linux smoke: прервать экспорт большого изображения
после появления staging; проверить, что конечного неполного документа нет;
после окна 24 часа запустить новую операцию в той же папке, подтвердить
удаление только собственного staging. Повторить для активной блокировки,
пользовательских файлов, reparse/symlink и сетевого хранилища. Проверить
`File.Move` на выбранной ФС и отсутствие перезаписи чужих файлов.

**Ограничения:** безопасность при злонамеренных конкурентных подменах
каталога тем же пользователем требует отдельной OS-specific проверки;
прошлые свободно лежащие `.get-image-*.png` не трогаются из-за отсутствия
достоверного подтверждения владения. Тесты не объявлять пройденными
до реального локального запуска. GitHub Actions не включать.
