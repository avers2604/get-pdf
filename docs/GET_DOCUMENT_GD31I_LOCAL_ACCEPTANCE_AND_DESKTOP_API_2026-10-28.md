# GD-31I — единая локальная приёмка GET Документы и DesktopEditors API-разведка

**Дата:** 28.10.2026. **Статус:** исходники средства локальной приёмки и тесты добавлены, но **полный .NET 10 build и аппаратная приёмка не выполнены**. Основная ветка `main` и GitHub Actions не меняются.

## 1. Зачем нужен новый сценарий

Существующие `verify-get-document-windows.ps1`, `verify-get-document-linux.sh` и `windows-build-get-document.ps1` уже умеют запускать сборку и часть тестов. Их **не заменяем**. Новая опциональная команда для ИТ/QA:
- проверяет конкретный `git HEAD` и `global.json` (Microsoft.Testing.Platform);
- проверяет синтаксис обоих встроенных Python UNO-мостов **без подключения UNO**;
- сверяет **в обе стороны** список разрешённых офисных команд `OfficeFeatureCatalog.cs` / `lo_editor.py`, отказывает при несовпадении;
- требует явный **одобренный локальный NuGet feed**. Восстановление `dotnet restore --source <local path>` не обращается к интернет-репозиториям. Не выполняются `git fetch`, `docker pull`, скачивание SDK, изменения системных сервисов и GitHub Actions;
- в первую очередь запускает unit-тесты **самого acceptance runner**, затем `.NET 10` сборку решения и шесть тестовых проектов; Windows дополнительно проверяет worker печати и legacy GET PDF;
- останавливается на первой ошибке, **оставляя остальные проверки в статусе `not-run`**, не допускает ложного `PASS`;
- создаёт структурированный JSON receipt для каждого запуска. Отчёт записывается как новый файл **без перезаписи существующего** (атомарная публикация через hard-link в той же файловой системе);
- всегда оставляет `releaseReady=false`: формальные результаты автоматических тестов **не заменяют** приёмку редакторов, печати, SSO/ACL, WORM, подписания и установщика.

Средство QA написано на Python stdlib, **не является runtime-зависимостью «ГЭТ Документы»**. Python 3.10+ нужен только на ПК разработчика/тестировщика. Для Windows и Astra Linux добавлены оболочки.

## 2. Использование

Сначала локально переключиться в репозитории на утверждённую для испытаний ветку GD-31I, убедиться, что NuGet-пакеты подготовлены/разрешены ИТ-отделом. Подготовить локальную папку feed с полным набором зависимостей; проверочный скрипт её не скачивает.

### Только посмотреть план, ничего не собирать

```powershell
python scripts/office_acceptance.py --plan
```

### Windows (PowerShell)

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify-get-document-gd31i.ps1 -OfflineNuGetFeed 'D:\\approved-nuget'
```

### Astra Linux / ALT / RED

```bash
bash scripts/verify-get-document-gd31i.sh /srv/approved/nuget
```

### Запуск тестов средства приёмки без .NET

```bash
python -m unittest discover -s scripts/tests -p 'test_office_acceptance.py' -v
```

Выход по умолчанию: `artifacts/local-acceptance/YYYYMMDDTHHMMSS-XXXXXXXXXX.json`. На сетевых ресурсах без поддержки hard-link запись может **отказать безопасно**: хранить первичные отчёты на локальном NTFS/ext4 (не на SMB) и переносить в корпоративное WORM/СЭД утверждённым процессом. Дополнительные поля отчёта: Git SHA, ОС, статус проверок, коды выхода, длительности, ручные блокировки.

**Зелёный JSON означает только** `automatedChecksPassed=true`, `status=automated-checks-passed`, **`releaseReady=false`**. Не подменять проверку реального Excel, Word или PowerPoint: это контроль совместимости *форматов*, пользователи продолжают работать в ГЭТ.

### Предварительные требования

- На QA-машине Python 3.10+, Git, **.NET 10 SDK**, локальный полный NuGet feed, необходимые Windows/Linux SDK/библиотеки (включая Windows print worker на Windows).
- Для реального UNO-интеграционного теста — локальный приватный LibreOffice с Python и разрешёнными правами. Некоторые тесты `Assert.Inconclusive` могут дать общий успешный код; из-за этого офлайн-модуль намеренно **не выдаёт релизное разрешение**.
- Для EuroOffice серверной приёмки отдельно нужны подписанный внутренний HTTPS, SSO/ACL/одноразовые grants, реальный callback и immutable CAS, WORM; этот скрипт не запускает сервер/контейнеры.
- Если локальная сборка невозможна или тесты не пройдены, выпуск заблокирован, а GitHub Draft остаются открытыми.

## 3. Действительное исследование EuroOffice DesktopEditors

Проверены исходники **конкретной ревизии**, закреплённой в GD-31H:
`Euro-Office/DesktopEditors@6a671bb1ad238c61965a64de3a005c420940c814`,
`desktop-sdk@8cc8d747cb48953bf8020c2bfbb67ede6cb55c51`.

Обнаружены исходные интерфейсы:
- `desktop-sdk/ChromiumBasedEditors/lib/include/applicationmanager.h`: `CAscApplicationManager::CreateCefEditor(CCefViewWidgetImpl* parent)` и методы `CreateCefView` / `CreateCefPresentationReporter`. Это C++ API для собственного CEF-view.
- `desktop-sdk/ChromiumBasedEditors/lib/qt_wrapper/include/qcefview.h`: `QCefView : public QWidget, public CCefViewWidgetImpl`, создаваемый c `QWidget* parent`. Содержит зависимости Qt, CEF и на Linux также специфичный код Wayland/GL.
- `desktop-sdk/ChromiumBasedEditors/lib/qt_wrapper/include/qascapplicationmanager.h`: `QAscApplicationManager` — C++/Qt bridge к общему менеджеру.
- `desktop-sdk/ChromiumBasedEditors/lib/include/applicationmanager_events.h`: присутствуют идентификаторы событий сохранения, закрытия, печати и команд. **Наличие event ID не подтверждает готовый безопасный контракт C# / Avalonia и порядок callbacks**.

**Вывод:** внутренний editor-view действительно существует и имеет родительский виджет; это основание для **нативного PoC в отдельном стендовом процессе**, а не доказательство работающей интеграции в `GetDocument.Desktop`. В обнаруженных заголовках нет обещанного стабильного C ABI/C# API для прямой передачи `Avalonia TopLevel` в Qt widget. Нельзя превращать C++ указатели в C# `IntPtr` без собственного межпроцессного или проверенного C-ABI слоя, управления потоками/CEF loop, lifetime и безопасностью ввода/печати. Нельзя включать автоматический fallback между серверными движками.

Следующий узкий эксперимент (отдельным PR после подтверждения необходимых API):
1. Создать *вне* основного GET изолированный Qt+CEF host с `QCefView`, открыть один тестовый локальный DOCX без сети.
2. Уточнить API C++ сохранения в **новый** путь и события, возможность отдать PDF на **собственный мастер печати ГЭТ**.
3. Проверить Win32 HWND/Wayland/X11 surface, DPI, focus, русскую клавиатуру, Ctrl+Z, 2 монитора, повторное открытие, аварийное завершение CEF.
4. Только затем предложить IPC-посредник и контролируемый host для Avalonia с независимой моделью capabilities. **Не** встраивать неизвестный Qt/C++ объект в основной процесс разработки.
5. Оценить AGPLv3/NOTICE и лицензии GUI-графики из исходников (в заголовках также присутствует CC BY-SA для некоторых GUI элементов). Не утверждать правомерность изменения брендинга без полного аудита.
