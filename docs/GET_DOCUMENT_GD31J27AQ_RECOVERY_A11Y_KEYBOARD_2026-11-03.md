# GD-31J.27aq — доступность и клавиатурное управление диагностикой восстановления

**Статус:** отдельная stacked Draft-ветка поверх GD-31J.27ap / PR #155. Изменения внесены в существующий Avalonia 12.1.4 интерфейс «ГЭТ Документ». Настоящие Windows/Astra GUI-тесты, C# сборка, MSTest и работа экранного диктора не выполнялись; `releaseReady=false`, `main` не изменён, GitHub Actions не включались.

## Выявленные проблемы GD-31J.27ap

1. Экран имел единственную кнопку «Обновить сведения», но не поддерживал F5, а при открытии во вкладке не запрашивал клавиатурный фокус. Для навигации с клавиатуры оператору приходилось добираться до кнопки вручную.
2. Сводка `TextBlock` имела **статичное** имя AutomationProperties `"Состояние диагностики"`. У некоторых экранных дикторов фиксированное имя может закрывать изменяющийся текст, особенно при обновлении live-region.
3. Кнопка с пояснением располагались в горизонтальном `StackPanel`, который не переносит дочерние элементы на следующую строку; длинная подпись могла выходить за край узкой панели.
4. Если одновременно `Truncated=true` и обнаружены недоверенные объекты, предупреждение о неполноте **заменяло** предупреждение о подозрительных файлах. Оператор видел не всю информацию.

## Реальные исправления

`src/GetDocument.Desktop/Recovery/RecoveryDiagnosticsPane.cs`:

- Панель получает `Focusable=true` и осмысленное Automation-имя «Диагностика аварийных копий. Только просмотр». При присоединении к визуальному дереву выполняется `Focus()`, без фокусирования временно отключаемой кнопки.
- Клавиша **F5** запускает тот же `RefreshAsync()`, что и кнопка. Обработчик не действует после `Dispose`, выставляет `e.Handled`; уже работающая проверка повторно не стартует благодаря `_busy`. Tab / Shift+Tab остаются стандартными механизмами Avalonia, дополнительных интерактивных действий нет.
- Новый `UpdateAccessibleStatus()` обновляет Automation-имя динамической сводки на **актуальный результат и ограничения**. `AutomationLiveSetting.Polite` сохранён, обновления происходят после изменения пояснения в состоянии ожидания, проверки, ошибки и результата. Результат читается словами, не только цветом.
- Горизонтальный `StackPanel` с кнопкой и длинным текстом заменён на `WrapPanel`, с отступами для естественного переноса на небольшом экране/увеличенном DPI.
- Сборка всех предупреждений отдельными независимыми условиями: `Truncated` и `UntrustedLinkOrNonFile/MetadataUnavailable` могут отображаться **вместе**. Чётко повторяется, что метаданные не подтверждают пригодность аварийной копии.

Фирменные цвета дизайн-системы 4.1 оставлены без изменений. При стандартном белом фоне из `GetTheme.axaml` расчётный WCAG 2.x контраст текста:

| Цвет | HEX | Отношение к белому |
|---|---|---|
| Navy | #24305E | около 12,65:1 |
| Muted | #5C6480 | около 5,85:1 |
| Red | #E4032E | около 4,83:1 |

Все три превышают 4,5:1 на **белой поверхности**. Это статический расчёт, не проверка реального рендеринга при Windows High Contrast, Astra Linux, масштабировании и сглаживании.

## Тесты и ограничения

Создан `scripts/tests/test_recovery_diagnostics_a11y_contract.py` (**6 offline source-only Python тестов**): F5 и единственное действие, правильная работа с фокусом, динамическое Automation-имя, раздельные предупреждения, адаптивная компоновка и математический контраст палитры из актуального GetTheme. Код тестов добавлен в `scripts/office_acceptance.py` **до NuGet restore**. В `scripts/tests/test_office_acceptance.py` закреплено, что `gd31j27aq-recovery-keyboard-narrator-windows-manual-e2e` и `gd31j27aq-recovery-keyboard-screenreader-astra-manual-e2e` остаются `not-run`.

Утверждения по исходникам не являются настоящими MSTest, автоматическим UIA/E2E, NVDA/Нарратор/Astra тестом или проверкой работы на малом дисплее. Нет автоматического удаления, чтения содержимого, публикации SaveAs, WORM и сетевых действий.

Команды после получения разрешённых SDK/офлайн NuGet и тестовых ОС:

```sh
python3 -m unittest discover -s scripts/tests -p test_recovery_diagnostics_a11y_contract.py -v
python3 -m unittest discover -s scripts/tests -p test_recovery_diagnostics_ui_contract.py -v
dotnet build src/GetDocument.Desktop/GetDocument.Desktop.csproj -c Release --no-restore
```

Для реальной приёмки проверить клавиатуру (F5, Tab/Shift+Tab, Ctrl+W), восстановление фокуса после переключения вкладки и закрытия, Narrator/NVDA и доступный экранный диктор Astra Linux, сочетание двух предупреждений, масштабирование 100/125/150/200 %, малую ширину окна, отключение/отмену долгой операции. До этого UI считается **не аттестованным**, несмотря на обновлённые исходники.
