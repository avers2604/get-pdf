# GD-18 — динамические лотки и предпросмотр нескольких страниц

**Дата:** 26.10.2026. **База:** GD-17 / PR #41. **Статус:** Draft, изменения ещё не проходили компиляцию и аппаратную приёмку в этой среде.

## Динамический лоток вместо фиктивных пунктов

Собственный мастер печати ГЭТ продолжает работать в существующей вкладке. После выбора принтера мастер запрашивает его реальные источники бумаги. Первым и исходным пунктом всегда остаётся «Выбор принтера (автоматически)», без подмены системных настроек.

- **Windows:** `GetDocument.PrintWindows.exe trays QUEUE` перечисляет `PrintCapabilities.InputBinCapability`, исключая `InputBin.Unknown`; входное имя очереди сверяется с реальным `LocalPrintServer.GetPrintQueues()`. Перед отправкой `PrintTicket.InputBin` устанавливается только после повторного подтверждения значения через `InputBinCapability`.
- **Linux/CUPS:** `lpoptions -p QUEUE -l` разбирается по доступным объявлениям `InputSlot` или `media-source`. Выбранное значение добавляется в `lp` отдельным `-o InputSlot=value` / `-o media-source=value` без shell.
- Структуры `PrintTrayOption` и `PrintTrayOptions` в Core ограничивают option keys, принтерные значения, длину ответа и количество вариантов; не принимают пробелы/управляющие знаки/посторонние shell-токены.
- **Проверка повторно:** перед отправкой задания Desktop получает свежий список лотков выбранной очереди и отклоняет устаревший/необъявленный вариант. Смена устройства сбрасывает выбор; асинхронные устаревшие результаты игнорируются.
- На принтерах без опубликованных лотков мастер не предлагает угаданные «Tray 1/Tray 2». По умолчанию драйвер сам выбирает бумагу.
- Комбинации размер бумаги/лоток (например, A3 только в определённом лотке) могут иметь дополнительные ограничения по `PrintTicket` и PPD, поэтому их поведение обязательно проверяется на конкретных МФУ.

## Предпросмотр размещения

Вместо увеличенного изображения только первой страницы мастер однократно считывает **до четырёх реальных страниц PDF** с помощью уже применяемого `PDFtoImage`; каждый растр ограничен до 480 пикселей по длинной стороне, используется общий `PdfNativeGate` и отмена при закрытии. Полученные PNG сохраняются только в памяти вкладки.

Режим 1-up показывает первую страницу; 2-up — первые две в вертикальной компоновке для книжной и горизонтальной для альбомной ориентации; 4-up — первые четыре в сетке 2×2. Для документа с менее чем четырьмя страницами пустые фиктивные страницы не создаются. Изменение 1/2/4-up и ориентации перестраивает уже созданные миниатюры без повторной PDFium-декодировки.

**Важно:** это приблизительный *лист компоновки*, а не точная модель физической печати: реальные поля, ориентация при автоматическом выборе, настройки драйвера, выбранный диапазон и особенности CUPS могут привести к различиям. Текущий миниатюрный пример всегда использует первые страницы **всего** PDF. В интерфейсе предупреждение показано явно.

## Новые тесты

- `PrintTrayOptionsTests`: нормальный PPD `InputSlot`, IPP `media-source`, невалидный вывод и непредусмотренные значения, выбор по умолчанию, подтверждённое включение в CUPS argv.
- `PrintSheetPreviewPlanTests`: размещение 1/2/4 страниц, книжная/альбомная ориентация, небольшой документ и строгая валидация числа страниц.

## Использованные стандартные API

- Windows: `System.Printing.PrintCapabilities.InputBinCapability` и `PrintTicket.InputBin` (Microsoft Learn).
- CUPS: `lpoptions -p -l` и `lp -o InputSlot=...` / `media=...`, `number-up` (OpenPrinting/CUPS).

## Исправление 27.10.2026: лотки Windows из драйвера

- WPF-перечисление `InputBin` знает только пять общих значений, поэтому лотки МФУ
  («Основной лоток», «Лоток 2», «Обходной»), которые драйвер описывает своими именами
  (например, `ns0000:_1`), отбрасывались как Unknown. На HP DeskJet 5000 мастер получал
  только `AutoSelect`.
- Теперь `GetDocument.PrintWindows.exe trays` читает XML PrintCapabilities
  (`psk:JobInputBin`, затем `DocumentInputBin` / `PageInputBin`) и показывает название
  лотка из драйвера. Автовыбор не дублируется: его уже даёт пункт «Выбор принтера».
- При печати выбранный лоток передаётся фрагментом PrintTicket через
  `MergeAndValidatePrintTicket`. Если драйвер его отбросил, задание не отправляется,
  а мастер сообщает «не поддерживает выбранный лоток».
- Если у принтера нет ничего, кроме автовыбора (Microsoft Print to PDF, XPS Writer),
  поле «Источник бумаги / лоток» скрыто.
- Проверено на этом ПК: HP DeskJet 5000 → «Основной лоток»; драйвер сохранил
  `ns0000:_1` в проверенном билете (без печати). PDF/XPS — поле скрыто.
  Физическая печать из лотка не проверялась.
