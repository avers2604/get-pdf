# ГЭТ Документ — решения и дорожная карта

**Дата:** 23.10.2026  
**Статус:** зафиксированные продуктовые решения + план, не отчёт о завершённой реализации.  
**Базовый репозиторий:** [avers2604/get-pdf](https://github.com/avers2604/get-pdf)

> **Главное утверждённое правило.** При выборе библиотек и редакторных движков первичны **максимальная функциональность и совместимость с Microsoft Office (Word, Excel, PowerPoint)**. **Весь пользовательский интерфейс — собственный, в стиле ГЭТ**, поэтому готовый внешний вид стороннего редактора не является критерием выбора. При этом лицензионная допустимость и информационная безопасность обязательны.

## 1. Реестр решений

| Направление | Зафиксированное решение |
|---|---|
| Архитектура | Единое приложение «ГЭТ Документ»: самостоятельная Avalonia-оболочка, кроссплатформенное Core-ядро и заменяемые адаптеры движков. |
| Лаунчер | Создать документ Word, таблицу Excel, презентацию, открыть файл; сканирование подключить позднее. |
| Вкладки | PDF, DOCX, XLSX, PPTX и изображения открываются **в одном окне** с общими вкладками. |
| UI / UX | Единый оригинальный стиль ГЭТ, собственные панели и команды; брендбук ГЭТ учитывать при финализации. |
| Функции | Максимально приблизиться к возможностям Microsoft Office. Принимать решения по таблице проверенных функций и реальных тестовых документов. |
| Движки | Не привязываться к одной библиотеке. Основной функциональный кандидат — LibreOffice; ONLYOFFICE и Collabora Online — обязательные сравнительные прототипы; ProEdit — вариант лёгкого редактирования после проверки зрелости. |
| Таблицы | ExcelDataReader использовать для чтения, **не** считать полноценным Excel-редактором. Полноценное редактирование — через выбранный офисный движок. |
| PDF | Сохранить возможности «ГЭТ PDF»: просмотр, выделение, печать, формы, подписи, редактирование в рамках доступных операций. |
| Шаблоны | Scriban + OOXML, корпоративные формы — после утверждения образцов. |
| Изображения | Адаптер обработки на базе NetVips / OpenCvSharp после проверки native-зависимостей. |
| Сетевые файлы | Windows/SMB, конфликты, отслеживание изменений, права доступа и история версий. |
| Документооборот | Защищённая интеграция с GUP-2; контроль ревизий, целостность, аудит; WORM-оригиналы не изменять. |
| Сканирование | Поздняя интеграция с самостоятельным «ГЭТ Сканирование», без переписывания драйверов/модулей. |
| Пасхалка | «Онлайн Дурак» после 10 нажатий в специальной области. Изолировать от рабочих документов, следовать политике закрытой сети. |
| Среда | Windows + Linux, включая отечественные дистрибутивы, адаптивный DPI и работоспособность на слабых ПК. |
| Лицензирование | Использовать открытые компоненты при выполнении лицензий и уведомлений; проверять GPL/AGPL отдельно. Внутренняя установка сама по себе не отменяет авторских прав. |
| Проверки | Сборки, тесты, UI и проверки совместимости выполнять локально; черновые PR не считать готовым релизом. |

## 2. Сравниваемые технологии

| Технология | Роль | Что требуется подтвердить |
|---|---|---|
| LibreOffice Writer/Calc/Impress | Главный функциональный кандидат для DOCX/XLSX/PPTX | Реально доступные функции через UNO / LibreOfficeKit, стабильность отдельного процесса, экспорт и интеграция со своим UI |
| ONLYOFFICE Docs | OOXML-совместимость и совместное редактирование | Локальная инфраструктура, API, функциональные ограничения и условия AGPL/коммерческих сборок |
| Collabora Online | Совместная работа и серверный офисный редактор | Особенности встраивания, лицензирование сборки и производительность |
| ProEdit | Лёгкий встроенный редактор | Уровень поддержки сложных документов, лицензия конкретного проекта, зрелость |
| Avalonia | Собственный UI, лаунчер, вкладки | Рабочая сборка на Windows/Linux, DPI, удобство работы на старых ПК |
| Scriban + Open XML SDK | Шаблоны и генерация OOXML | Round-trip, безопасность шаблонов, права на официальные формы |
| ExcelDataReader | Импорт/чтение XLS/XLSX/XLSB | Не использовать для полноценного редактирования |
| NetVips / OpenCvSharp | Работа с изображениями | Зависимости, форматная совместимость, безопасность |
| GET PDF Core | Просмотр/редактирование PDF | Отсутствие регрессий и безопасная печать/подписи |

**Архитектурный принцип:** Shell → общее пространство вкладок и команд → интерфейсы адаптеров текста, таблиц, презентаций, PDF, изображений → соответствующие движки. Права, версии, аудит и интеграция GUP-2 — сквозные сервисы. Не следует считать, что произвольную функцию движка можно автоматически вывести на свой UI: у каждого действия необходим рабочий API/контракт или отдельная реализация.

| P2 | Сравнительный пилот LibreOffice / ONLYOFFICE / Collabora (ProEdit как дополнительный) | Единая матрица функций, fidelity, API, скорости, затрат и лицензий |
| P3 | Полноценное редактирование Word/Excel/PowerPoint через выбранные движки | Round-trip на реальных корпоративных и сложных тестовых файлах |
| P4 | Сетевые файлы, версии, конфликтный доступ, шаблоны, печать, подписи, GUP-2, WORM | Проверенные ACL, аудит и неизменность оригиналов |
| P5 | Совместное редактирование при наличии локального сервера | Конфликты, одновременная работа, сбои, права |
| P6 | Производительность, DPI, Windows/Linux, безопасная офлайн-поставка, установщик | Полная локальная приёмка и список документированных ограничений |

**Тестовые категории:** сложные DOCX (стили, таблицы, рецензирование); XLSX/XLSB (формулы, сводные, диаграммы); PPTX (шаблоны/макеты/графика); защищённые/повреждённые файлы; PDF формы/подписи; SMB с ACL; WORM; печать. **VBA, ActiveX и надстройки MS Office** — отдельно обозначенные высокорисковые зоны: не обещать полноту без тестов.

## 5. Порядок следующего шага

1. Уточнить реальное содержимое main, веток и PR; убрать дубли и разрешить зависимости без преждевременного merge.
2. Запустить локальные restore/build/test, UI-smoke и тесты на Windows/Linux. GitHub Actions пока не использовать.
3. Сделать параллельный прототип редакторных движков и заполнить матрицу совместимости с Microsoft Office.
4. Выбрать функционально самый сильный интегрируемый стек по форматам и подтвердить лицензирование, API и безопасность.
5. Отразить решения в последующих PR, сохранять обновляемый реестр функций и известные ограничения.
