# GD-07 — SOURCE-FIRST обработка изображений на NetVips

23.10.2026. Веточная зависимость: PR #19 (GD-06), далее GD-07.

## Использованы готовые библиотеки, без собственных алгоритмов
- [NetVips](https://github.com/kleisauke/net-vips) **3.2.0**, исходный код
  и бинарная обёртка **MIT**. Подтверждены реальные методы публичного API
  `Image.NewFromFile`, `Image.Rot`, `Image.Flip`,
  `Image.ExtractArea`, `Image.WriteToFile` (версия v3.2.0).
- [NetVips.Native](https://www.nuget.org/packages/NetVips.Native) **8.18.7**,
  содержащий нативные бинарные libvips для Windows и Linux; **LGPL-3.0-or-later**.
  До выпуска необходим аудит соблюдения LGPL (текст лицензии, notices,
  динамическая линковка, замена библиотеки, источники изменений, если были).
  Пользовательская офлайн-поставка должна включать подходящие RID/native assets.
- OpenCvSharp **не добавлен**: операции поворота, зеркального отражения и
  прямоугольной обрезки уже покрываются NetVips; второй тяжёлый native runtime
  увеличил бы размер, риски и стоимость поддержки без новой функции.
- Изображения визуализируются через **уже существующую Avalonia Image/Bitmap**,
  повторного движка предпросмотра нет. Ни одно средство GUP-Scan не копируется.

## Внесено в исходники
- `GetDocument.Images` — отдельная библиотека `net10.0` с
  `ImageEditPlan` (чистый геометрический контракт) и
  `ImageEditService` (native libvips backend).
- Допускаются входные PNG/JPEG/WebP до 32 МиБ и не более 80 миллионов
  декодированных пикселей, сторона <= 20 000 пикселей.
  **TIFF/SVG/GIF и многостраничные файлы пока только просмотр**; редактор
  их не преобразует без подтверждения сохранности всех кадров/страниц.
- Операции применяются в явном порядке: поворот 0/90/180/270° по часовой
  стрелке → отражение по горизонтали → обрезка по координатам оригинальных
  пикселей уже повёрнутого изображения.
- `ImagePreviewPane` сохраняет одну общую вкладку в Avalonia.
  Операции задаются до сохранения; предпросмотр **пока показывает оригинал**,
  а не конечную композицию. Это явно подписано в UI.
- Результат сохраняется **ТОЛЬКО новым PNG** через новый временный файл в
  целевой папке и `File.Move` без overwrite. Источники и WORM не меняются.
  Новая редакция открывается в соседней вкладке того же окна.
- SHA-256 исходника проверяется при открытии и перед/после обработки;
  при внешних изменениях сохранение отменяется. Это не устраняет все
  сетевые TOCTOU и не заменяет аудит GUP-2.
- Несохранённые операции защищены от закрытия вкладки/всего окна аналогично
  DOCX/XLSX; есть сброс преобразований. При отмене Save As оригинал не меняется.

## Тесты
- `GetDocument.Images.Tests`: 8 unit-тестов геометрии, расширений и лимитов,
  5 тестов сохранения, включая **реальное** декодирование, обрезку и поворот
  PNG 4×3 через native libvips, fingerprint исходника, no-overwrite.
- Скрипты `scripts/verify-get-document-windows.ps1` и
  `scripts/verify-get-document-linux.sh` дополнены запуском тестов Images.

## НЕ готово и release gates
- В доступной среде нет .NET SDK и libvips: **ни компиляция .NET, ни
  native integration test, ни Windows/Linux UI-тесты не запускались**.
- Нельзя выпускать production-сборку с недоверенным изображением в том же
  UI-процессе: потребуются изолированный worker с лимитами памяти/времени,
  тесты JPEG/PNG/WebP/TIFF fuzz/zip bombs и отказов SMB.
- Реальная производительность на слабых ПК, долгие операции/cancellation,
  корректная ориентация EXIF, ICC цветопрофили и качество перекодировки
  требуют проверки. Метаданные исходника при сохранении не гарантированы.
- Для TIFF: многостраничный просмотр, отдельная обработка кадров и
  сохранение без потери страниц; для OpenCvSharp — проверка перспективы,
  шумоподавления, deskew и OCR на реальных сканах; пакетная обработка
  отдельным этапом.
- Направление текущего PDF/Avalonia/SkiaSharp dependency conflict из GD-02
  остаётся отдельным release-blocker, новый модуль NetVips его не исправляет.
- **GitHub Actions не включены; PR оставить Draft.**

## Локальная приёмка
```sh
bash scripts/verify-get-document-linux.sh
```
Windows:
```powershell
.\scripts\verify-get-document-windows.ps1
```
Затем GUI: PNG/JPEG/WebP в общей вкладке, 90°/180° повороты, отражение,
обрезка, ошибка координат, выход с несохранёнными действиями, создание
новой PNG-версии без изменения источника; сопоставление результатов
с референсами и проверки на Samba/Windows Server 2016.
