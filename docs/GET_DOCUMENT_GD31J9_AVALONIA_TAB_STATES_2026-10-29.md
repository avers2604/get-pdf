# GD-31J.9 — состояния EuroOffice во вкладках основного окна ГЭТ

Дата: 29 октября 2026. Продолжение GD-31J.8 PR №77. **Разработка исходников, без лабораторных проверок** по решению пользователя. Не подключать экспериментальный нативный редактор к рабочим файлам. `main` и GitHub Actions не меняются.

## Решение по архитектуре

В существующем `src/GetDocument.Desktop/MainWindow.cs` используется один `TabControl _tabs` с общим `ObservableCollection<TabItem> _items`. Реальные DOCX/XLSX/PPTX продолжают работать через действующие `DocumentWorkspace`/LibreOffice, PDF — через свои существующие компоненты. **Новый Qt/CEF-хост не заменяет эти ветки**.

Вместо параллельного окна создаётся *пассивный тип диагностической вкладки* с данными о нативном сеансе EuroOffice, в том же `_items`/`_tabs`. Нет Qt HWND, QWindow, RenderSurface, P/Invoke либо опасного `SetParent` в новой логике. Наличие вкладки **не означает**, что реальный CEF отрисован или документ открыт.

## Добавлено

**1. `EuroOfficeNativeWorkspaceTabs` в GetDocument.Office.** Подключается к реализованному в GD-31J.8 `EuroOfficeNativeTabRegistry`: отдельные `tabId`, `sessionId`, поколение хоста, заголовок и `Requested / ViewLoadedUnverified / Closed / Failed`. Можно `Register`, `Select`, `Deselect`, `ApplyReceipt`, `HostCrashed`, `Restart`, `Close`, `Get`. Внешние события должны содержать **точно текущий сеанс**. При сбое состояние показывается прямо в вкладке. **Автоматический перезапуск запрещён**, если наблюдались неподтверждённые правки; нельзя молча потерять такую работу. Новая генерация требует нового sessionId. Закрытие сбойного сеанса поддерживается; реестр освобождает его запись.

**2. `NativeOfficeDiagnosticPane`** в `src/GetDocument.Desktop/Office`. Отображает собственную текстовую диагностическую подложку в стиле ГЭТ с указанием состояния, поколения и возможных неподтверждённых правок. Никаких обманных «файл сохранён», «редактирование запущено», «PDF сформирован», кнопок сохранения или прямой печати. В нём нет нативного CEF/Qt кода, загрузки файла или контакта с GUP-2.

**3. `MainWindow`.** Добавлены `_nativeWorkspaceTabs` и `_nativeTabViews`, обработка выбора диагностической вкладки в уже существующем `_tabs.SelectionChanged` **отдельно** от вызова `_workspace.Select(id)` для обычных документов. Не меняется механизм реальных вкладок, печати, печатных PDF или рабочего редактора. Внутренние методы:
- `AddNativeDiagnosticTab` — зарегистрировать статусную вкладку в общем `_items`, но **ничего не запускать и не открывать**;
- `ApplyNativeDiagnosticReceipt` — обновить только диагностический статус при совпадении ID;
- `ReportNativeDiagnosticCrash` — показать понятное сообщение о сбое, без ложного успешного восстановления;
- `RecordNativeDiagnosticRestart` — зарегистрировать уже обеспеченный доверенным супервизором новый sessionId; сам CEF/Qt не запускает;
- `CloseNativeDiagnosticTabAsync` / `CloseNativeDiagnosticTab` — убрать вкладку с предупреждением при неподтверждённых изменениях. Глобальный `Closing` главного окна учитывает диагностические правки в предупреждении.

На вкладке EuroOffice `Ctrl+W` закрывает диагностическую вкладку, а `Ctrl+P` **явно запрещает прямую печать**, не открывая существующий PrintWizard на неподтверждённом PDF. Для реальных LibreOffice/PDF вкладок исходные клавиши продолжают работать.

**Принципиальная граница:** метод создания лабораторной вкладки только `internal` и пока **не вызывается из обычного лаунчера**. Ни пользовательское приложение, ни установщик не начинают автоматически запускать неподтверждённый CEF. Позднее проверенный супервизор процессов сможет вызывать эти методы через UI thread после согласованного IPC; но это отдельный этап, не выполненный здесь.

## Подготовленные, но не запущенные тесты

- `EuroOfficeNativeWorkspaceTabsTests`: независимые вкладки, выбор активной, чужой receipt, два сеанса, восстановление после аварии, запрещённый рестарт с несохранёнными правками, удаление закрытой/ошибочной вкладки, невозможность получить подтверждённое сохранение/печать.
- Дополнение к `EuroOfficeNativeTabRegistryTests`: очистка неиспользуемых записей с защитой от старого session ID.
- `scripts/tests/test_native_tab_shell_contract.py`: проверка отсутствия отдельного окна, использования общего `TabControl`, разделения `DocumentWorkspace`, явного отказа от печати и автозапуска CEF.
- `scripts/office_acceptance.py` включает этот статический тест до `dotnet restore`. Настоящие UI тесты Avalonia с перетаскиванием вкладок, многомониторностью, событиями и восстановлением процесса нужны позже.

| Автоматический супервизор Qt↔ UI | **Не подключён** |
| Открытие настоящих документов в новом embedded view | **Не подтверждено** |
| Сохранение, WORM/CAS, GUP-2 | **Отключены/заглушки** |

**Следующий этап GD-31J.10:** отдельный `NativeEditorSessionCoordinator` (не UI) для передачи состояний из настоящего процессного IPC через Dispatcher без пересечения вкладок; правила таймаутов/cancellation/host lost и отображения предупреждений при сбое. Затем — проверка реального механизма вывода нативного CEF внутри Avalonia для Win32 и X11/Wayland, не используя сырой `QWidget*` или непроверенный window ownership. Прямую публикацию WORM/сервер и отправку на принтер оставляем закрытыми до доверенных адаптеров.
