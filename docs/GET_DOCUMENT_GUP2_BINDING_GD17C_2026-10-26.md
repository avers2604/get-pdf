# GD-17C.1 — Безопасная привязка рабочей Office-копии к GUP-2

Дата: 26.10.2026. Статус: **Draft-код внесён; .NET/MSTest/Windows/Astra GUI не проверены.**

## Почему переиспользован существующий GUP-2

В `avers2604/Gup-2` уже есть `GetDocumentTabBindIssueView` и `GetDocumentTabBindRedeemView`:
- браузер GUP-2 с SSO/CSRF, проверкой живого пользователя, ACL и текущей рабочей копии выдаёт **43-символьный одноразовый код**;
- `POST /documents/getdocument/tab-binding/redeem/` получает только `X-GetDocument-Bind-Code` и `X-GetDocument-File-SHA256`, без файла, без cookies и без JSON тела;
- сервер повторно проверяет права, WORM, SHA-256, версию, выжигает код и возвращает **только метаданные**;
- код действителен до пяти минут; отзыв прав, другая версия или несовпадение SHA не должны давать успешную привязку.

В этом PR не создаются второй реестр документов, другая модель карточек или отдельный авторизатор. GUP-2 сохраняет статус владельца прав/версий.

## Что реализовано в ГЭТ Документы

- `OfficeReturnPolicy`: отдельный ИТ-флаг `AllowGup2TabBinding`, **выключен по умолчанию и независим от** `AllowGup2OfficeReturn`. Разрешённый endpoint строится из утверждённого внутреннего HTTPS `Gup2DocumentsUrl` и фиксированного суффикса, а не из строки пользователя.
- `Gup2OfficeTabBindingClient`: открывает выбранный DOCX/XLSX только на чтение, вычисляет SHA-256, отправляет **пустой POST** с двумя требуемыми заголовками; запрещает cookies, редиректы, использование доменных учётных данных и HTTP. Строгая проверка ответа (`200`, `bound`, UUID, версия, SHA, тип, номер), ограничение ответа 4096 байт.
- `OfficeBindingPane`: собственная вкладка ГЭТ с выбором сохранённого DOCX/XLSX и одноразовым кодом GUP-2. Код очищается после отправки; нет отдельного окна редактора, автоматического экспорта файла или перехода по ссылке.
- `MainWindow`: команда «Связать с GUP-2» появляется только при включённой политике, закрытие вкладки отменяет незавершённую операцию.
- `EuroOfficeLaunchResolver`: дополнительная защита от ошибочного или подменённого grant — immutable user id в SSO principal обязательно совпадает с `Session.UserId`; неавторизованные обращения не читают хранилище.
- MSTest `Gup2OfficeTabBindingTests` и дополнительные тесты `EuroOfficeLaunchPageTests`: invalid URL, отключённая политика, несовпадение SHA/формата, неверный ответ, редиректы, чужой сотрудник.

### Пример административной политики

Только для безопасного этапа привязки, **без права загрузки рабочей копии**:

```json
{
  "Version": 1,
  "AllowGup2TabBinding": true,
  "AllowGup2OfficeReturn": false,
  "Gup2DocumentsUrl": "https://gup2.intra.example/documents/",
  "MaxOfficeUploadBytes": 157286400
}
```

На стороне GUP-2 дополнительно требуется `GETDOCUMENT_TAB_BIND_ENABLED=True`. ИТ должна зафиксировать внутренний DNS, сертификат организации и файловые ACL места хранения policy.json (Windows ProgramData/GET-Document, Linux /etc/get-document). Не принимать произвольные адреса или самоподписанные сертификаты без доверенной CA.

**Пример содержит условный DNS; подставить реальный разрешённый адрес организации.**

## Граница полномочий (важно)

Успешная привязка говорит: *«SHA-256 открытой рабочей DOCX/XLSX-копии совпадал с текущей редакцией карточки GUP-2 на момент ответа»*.

Она **НЕ**:
- создаёт серверный Euro-Office сеанс или токен JWT;
- даёт право на совместную запись, экспорт чужих документов или доступ к хранилищу GUP-2;
- привязывает файл на постоянной основе без новой проверки ACL/актуальности;
- сохраняет изменения обратно в GUP-2 и не меняет WORM PDF;
- поддерживает PPTX в текущей модели файлов GUP-2: презентации редактируются отдельно до расширения серверного типа.

При закрытии вкладки её метаданные уничтожаются. Для будущей реальной Euro-Office сессии нужен независимый корпоративный `ITrustedEuroOfficeLaunchStore` и серверный revision-sink с повторной проверкой прав до записи. На данном этапе он **по умолчанию DenyAll**.

## Контракт следующих GD-17C.2 / GD-17D

1. GUP-2/SSO: связать browser SSO с внутренним identity principal `NameIdentifier` и выдавать одноразовый `EuroOfficeLaunchId` только для актуальной рабочей редакции (в отличие от metadata-only tab binding). Атомарно списывать grant на backend.
2. Только после корпоративного ACL/Silo backend: реализовать ограниченную по размерам и revocable передачу OOXML к Euro-Office; серверные HTTPS-адреса файлов выдавать по проверенной авторизации, не по полям клиента.
3. Callbacks: проверить JWT подпись Euro-Office, запретить redirects/SSRF, выполнить GUP-2 `upload_intake`, optimistic CAS, аудит, запись новой версии **в файлы рабочей копии**, WORM неизменен.
4. Провести E2E Windows/Astra Linux: вкладки, SSO, 2/5/10 сотрудников, конфликты, отзыв ACL при длительной сессии, русские шаблоны/шрифты, печать через ГЭТ мастер.

## Локальные проверки, обязательные до слияния

```sh
dotnet restore GetDocument.slnx
dotnet build GetDocument.slnx -c Release --no-restore
dotnet test tests/GetDocument.Core.Tests/GetDocument.Core.Tests.csproj -c Release --no-restore
dotnet test tests/GetDocument.Collaboration.Tests/GetDocument.Collaboration.Tests.csproj -c Release --no-restore
```

В доступной среде .NET SDK отсутствует: эти команды **не запускались**. Нужны также негативные сетевые тесты GUP-2 с отключёнными endpoint, ошибкой TLS, истёкшим кодом, конфликтом версии и изменёнными байтами, без повторного использования кода.

Это **частичное завершение GD-17C**: клиентская привязка реализована как исходники, полноценный Euro-Office/SSO/GUP-2 launch и совместная запись не готовы.
