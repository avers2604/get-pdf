# GD-21 — интеграционная подготовка Office → PDF → собственный мастер печати ГЭТ

**Дата:** 26.10.2026. **База:** GD-20 / PR №45. **Состояние:** Draft до локальной компиляции, MSTest и проб на физических МФУ.

## Выполненные инженерные изменения

### 1. Состояния локальной очереди и понятные сообщения

`PrintSpoolFailurePolicy` классифицирует результат передачи задания:

| Источник | Код/условие | Классификация | Повтор |
|---|---|---|---|
| Windows PrintWorker | 2 — некорректный запрос | отказ до отправки | только после исправления |
| Windows PrintWorker | 3 — PDF/принтер изменился | отказ до отправки | после новой проверки |
| Windows PrintWorker | 4 — нет функции драйвера | отказ до отправки | изменить параметры |
| Windows PrintWorker | 5, неизвестный код | исход неопределён | **сначала проверить очередь** |
| Linux CUPS `lp` | ненулевой код | исход неопределён | **сначала проверить очередь** |
| Windows/CUPS | таймаут после запуска рабочего процесса | исход неопределён | **сначала проверить очередь** |
| Windows | бинарный worker отсутствует до запуска | явно не отправлено | проверить установщик |
| Windows/Linux | команда недоступна до старта | явно не отправлено | проверить установку и права |

`PrintSubmissionException` несёт очищенное от путей и драйверного stderr объяснение + признак `MightBeQueued`. UI мастер печати показывает разные причины отказа и, если статус не определён, запрещает повторный submit в той же вкладке. **Положительный ответ spooler означает приём задания в очередь, а не распечатанный документ.**

### 2. Защита от параллельной подготовки Office

`MainWindow.ShowPrintWizard` предотвращает повторный Ctrl+P/двойной щелчок, пока из Office экспортируется PDF. Если сотрудник переключил или закрыл исходную вкладку, устаревший результат экспорта не открывает мастер для другого документа. Временный файл удаляется в `finally` при отмене или ошибке. После успешного открытия владельцем временного PDF становится мастер.

### 3. Безопасное хранение временного Office PDF

`OfficePrintFiles` формирует исключительно имена `office-<32-hex-guid>.pdf` (без имени или пути пользователя), внутри `LocalApplicationData/GET-Document/OfficePrintExports`. Windows использует ACL профиля пользователя; на Unix каталогу ставится `0700`, PDF `0600`. Неизвестные имена, сторонние каталоги и ссылки `ReparsePoint` не рассматриваются как собственные PDF-экспорты. При новом экспорте удаляются только корректно именованные файлы старше 7 суток, чтобы не оставлять копии документов после аварийного завершения.

`OfficeEditorPane.PreparePrintableAsync` проверяет успешное получение ненулевого PDF, ужесточает права и удаляет частично экспортированный файл при ошибке. Удаление исходных DOCX/XLSX/PPTX, PDF и WORM-оригиналов запрещено. Все чтения и отправка в очередь используют приватный `PrintFileSnapshot` из GD-20.

### 4. Обязательная проверка SHA-256 во всех заданиях

- `LocalPrintBroker.SubmitPdfAsync` теперь требует ожидаемый хэш, без необязательного обходного пути.
- `GetDocument.PrintWindows.exe` не принимает запросы без SHA-256; повторно считает хэш по открытым байтам, **до** PDFium / печати.
- На Linux CUPS путь с SHA-проверкой остаётся в общем брокере; после передачи `lp` реальная целостность задания зависит от локальной службы/драйвера.
- Это проверка локальной целостности, **не электронная подпись, не доказательство подлинности от доверенного сервера и не подтверждение физической печати**.

## Тесты

Новые MSTest:
- `PrintSpoolFailurePolicyTests`: коды 2/3/4, 5/неизвестный, CUPS, таймаут, недоступный worker, отсутствие выдуманного сообщения об окончательной печати;
- `OfficePrintFilesTests`: UUID-имена, удаление только служебных копий, защита от чужих файлов, очистка старых и режим Unix 0600;
- `LibreOfficeEditorTests.UnsavedOfficeEditsAreFrozenIntoPdfSnapshotForGetPrintWizard`: реальный редактор открывает DOCX, получает **несохранённые изменения**, экспортирует PDF, создаёт `PrintFileSnapshot`; после новой правки и повторного экспорта первая копия остаётся прежней, исходный DOCX не записывается. Этот тест запустится только на подходящей локальной Windows с рабочим LibreOffice, иначе будет помечен `Inconclusive`.

Дополнительно выполнить локально с установленными драйверами:
1. Windows: worker `printers` и `trays` под правами обычного пользователя; отсутствие бинарного файла, повреждённый PDF, неверный хэш, драйвер без A3, неверный лоток, прерывание при отправке. Убедиться, что возможен **неоднозначный исход**, но двойной тираж не инициируется автоматически.
2. Astra/ALT/РЕД: `lpstat`/`lpoptions`/CUPS доступны в закрытой сети, выявлены ошибки отсутствующей очереди/драйвера/прав; PDF уходит в очередь только после контрольной проверки; Unix ACL приватного каталога проверены.
3. DOCX/XLSX/PPTX: экспорт после несохранённых правок, типографика и кириллица, A4/A3/2-up/4-up/дуплекс/лоток; сверить предпросмотр и физический результат на реальном МФУ.
4. 2× Ctrl+P и переключение вкладки во время экспорта Office не создают более одного открытого мастера; при отмене приватные файлы не сохраняются.
5. WORM и GUP-2: исходный документ и история ревизий не переписываются. Локальная печать **не** реализует серверный Euro-Office export endpoint.

## Euro-Office и дальнейшая интеграция

В отдельном PR №42 Euro-Office объявлен основным **серверным** Office-движком. GD-21 **не подменяет** его локальный HTTP/WOPI-контракт, не открывает входящий URL в CUPS и не обходит GUP-2 ACL/CAS. Для защищённой серверной печати требуется авторизованный export-to-PDF поток с короткоживущим токеном, привязкой к конкретной неизменяемой ревизии и проверкой прав; необходим отдельный PR и изолированный серверный стенд.

### Честный статус

В доступном окружении нет `.NET 10`, `lp/lpoptions`, Windows spooler и реальных принтеров. Новые исходники и тесты добавлены в GitHub, но **не выполнены компиляция, MSTest, аппаратная печать или совместимость с реальным сервером Euro-Office**. Оставить Draft, GitHub Actions не включать, main не менять до результатов приёмки.
