# GD-31J.30 — журнал синтетических reviewed-операций и безопасное обнаружение остатков

**Дата:** 29.10.2026. **База:** Draft PR #101, GD-31J.29. **Статус:** изменения написаны в репозитории, но **сборка, .NET/Python тесты, CEF/Qt и физическая лаборатория не запускались** по предыдущему решению пользователя. Никакого рабочего Save As, автоматического восстановления или WORM-публикации.

## Цель

GD-31J.29 создаёт `reviewed/.gd31j29-pending-<random32>.tmp`, делает `Flush(true)`, затем `File.CreateHardLink` и удаляет **только собственный** временный hardlink. При сбое процесса, отключении питания, отказе диска, ошибке последующей проверки или недоступности hardlink возможны остатки `*.tmp`, отсутствующая конечная запись, или одновременно `pending` + `reviewed`. До GD-31J.30 не было последовательного, отдельно записанного контекста попытки; нельзя было уверенно различить `pending` конкретной попытки и неидентифицированные файлы.

## Новое в коде

`src/GetDocument.Office/EuroOfficeDesktop/EuroOfficeSyntheticSnapshotJournal.cs` — ограниченный лабораторный журнал с методами `Begin`, `Append` (внутренние) и **публичным только по явному разрешению** `Inspect(stagingRoot, labApproved=false)` (только чтение).

Запись каждой попытки создаётся **до временного файла** по имени
`<staging>/reviewed/.gd31j30-intent-<attemptGUID32>.jsonl`.
Формат одной строки:

- `schema=getdoc-synthetic-reviewed-journal/1`;
- `attemptId`, `sessionId`, allowlisted `format` (DOCX/XLSX/PPTX);
- `sha256`, `length` исходного **синтетического** кандидата;
- строго сформированные имена `pendingName` и `finalName`, **без абсолютных путей**;
- `sequence` (1–4) и `stage`.

Разрешена только монотонная цепочка:

| Запись | Когда записывается | Что означает |
|---|---|---|
| `intent` | До появления `pending` | Началась отдельная попытка |
| `pending_flushed` | После записи, `Flush(true)` и SHA-контроля | Проверен временный файл |
| `linked` | После `File.CreateHardLink(destination, pending)` | Возникло конечное имя |
| `completed` | После удаления **собственной** временной ссылки и повторной проверки SHA | Лабораторная операция закончила локальную проверку |

Каждая строка записывается в режиме `FileOptions.WriteThrough` с `Flush(true)`. Изменение предыдущих строк, перескок стадии и дублированный переход запрещены. Записи ограничены размером 8 КиБ и количеством четырёх стадий. **Это НЕ подлинный защищённый журнал:** нет подписи, отдельного доверенного хранилища, fsync каталога, подтверждённой защиты от concurrent writers или гарантий при power loss. После сбоя `linked` мог успеть появиться раньше записи об этом; наблюдатель не делает выводов о транзакционной атомарности из одной строки.

### Обнаружение остатков — исключительно чтение

`Inspect` проверяет только заранее существующий локальный каталог `<staging>/reviewed` без рекурсии, сетевых путей, символьных ссылок и reparse point на проверяемых компонентах. Ограничение: максимум 2048 всех элементов каталога, максимум 256 релевантных журналов или временных файлов. Лимиты превышены — ошибка без изменения данных. Он сопоставляет **только строго именованные** `*.jsonl` и `.gd31j29-pending-*.tmp`. Не сканирует другие каталоги или диск.

Возможные результаты:

| Диагностический результат | Смысл |
|---|---|
| `PendingNeedsReview` | Остался временный файл, конечный не обнаружен |
| `PendingAfterLink` | Обнаружены и временный, и конечный файлы |
| `CompleteObserved` | Есть финальный файл и последовательная запись `completed` |
| `UncertainAfterLink` | Финальный файл есть, но завершение не зафиксировано |
| `NoOutputObserved` | Журнал есть, файлов результата нет |
| `MissingFinal` | Журнал `completed`, но конечный файл исчез |
| `MalformedJournal` | JSON, типы, порядок, ID, формат или ссылки недостоверны |
| `UnknownPending` | Временный файл не связан с валидным журналом |

Ни один из этих результатов **не даёт права на удаление**: `TrustedForDeletion=false`, `AuthorizedForPublication=false`. Отсутствуют `File.Delete`, `File.Move`, `File.Replace`, очистка каталогов, периодические задачи и автоматическое восстановление в коде сканирования. Существующее удаление только **собственного** pending после уже выполненного hardlink в GD-31J.29 остаётся частью обычной операции, а не очисткой аварийных остатков. Даже файл со строго похожим именем может быть подменён; доверять только форме имени нельзя.

## Подготовленные тесты — не исполнялись

`EuroOfficeSyntheticSnapshotJournalTests.cs` описывает положительные и аварийные сценарии: запись `intent` перед появлением файла, отсутствие вмешательства в `pending`, правильную четырёхстадийную последовательность, недопустимые переходы, обнаружение одновременно двух hardlink-имён, неизвестного временного файла, повреждённых JSON и типов, отказ при выключенном лабораторном разрешении, символьном каталоге и переполнении лимита. Дополнен тест GD-31J.29, который после `Commit` ожидает завершённый журнал и отсутствие `*.tmp`.

`test_synthetic_snapshot_journal_contract.py` проверяет связи исходников: `Begin` раньше первого байта, последовательность flush → linked → completed, WriteThrough, отсутствие методов удаления/перемещения в обозревателе и обязательные лимиты. В `scripts/office_acceptance.py` добавлен локальный source gate `cef-synthetic-snapshot-journal-source-tests` и отдельный ручной `eurooffice-gd31j30-journal-crash-orphan-detection-no-cleanup-vm`. GitHub Actions не включаются.

## Перед реальным внедрением

После окончания согласованных улучшений и разрешения на лабораторию нужно отдельно собрать приложение и проверить на **disposable offline** Linux/Wayland и при необходимости Windows/Astra Linux: сбои на каждой фазе, процессное принудительное завершение, сбой накопителя, NTFS/ext4/XFS, hardlink без поддержки, power-loss/barrier/directory fsync, конкурентный подменный файл, доступ по ссылкам, недостаток прав/места. Нужна проверка достоверности исходного SHA, реальная нативная CEF Save As цепочка и независимое открытие тестовых DOCX/XLSX/PPTX.

Журнал **не** является аудитом юридически значимых WORM-операций. Рабочие документы, пути пользователей, Nextcloud, GUP-2, серверные хранилища и UI Save As не затрагиваются. Никаких операций с `main` или GitHub Actions.

**Следующий GD-31J.31:** инструмент ручного разбора найденных остатков (только просмотр, экспорт ограниченного отчёта без путей/контента), отдельный план проверки файловой системы и готовности производственного транзакционного слоя — без преждевременного внедрения в рабочие файлы.
