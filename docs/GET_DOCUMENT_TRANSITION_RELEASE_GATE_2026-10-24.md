# Переход ГЭТ PDF → ГЭТ Документ: интеграционный выпуск и критерии приёмки
Дата: 24.10.2026. Ветка: `feature/get-document-consolidated-20261024`. Статус: **DRAFT / НЕ ГОТОВО К РЕЛИЗУ**.

## 1. Объём перехода

- Один клиент «ГЭТ Документ» с общей «Главной», командами нового DOCX/XLSX/PPTX, едиными вкладками PDF/Office/изображений, «ГЭТ Файлы», шаблонами и будущим модулем «ГЭТ Сканирование». Вторую GUI-сессию при открытии документа не создавать.
- Собственный интерфейс по дизайн-системе ГЭТ; открытый исходный код существующих движков предпочтительнее самостоятельной реализации редактора, без подмены функциональности и необоснованных заявлений о совместимости Microsoft Office.
- Локальная автономная работа там, где возможна; серверные зависимости изолированы в отдельном WOPI host и GUP-2 интеграциях. В закрытом контуре **не обращаться к публичному Интернету**.
- WORM-оригиналы неизменны. Новая редакция = новая сущность с SHA-256, указанием базовой версии, ACL, аудитом и разрешением конкурентных изменений.
- Совместное редактирование **в реальном времени**: Collabora Online / альтернативный проверенный OEM-движок в общей сессии; не имитировать синхронизацию через периодический перенос файлов. Офисный сервер, UI WebView/launch, ACL, GUP-2 storage и корпоративные лицензии ещё предстоит подключить.

## 2. Как собрана ветка

- База: `feature/get-document-local-ipc` (PR #30, основан на PR #28 → #27 → #26 → #23 → #22 → #21 → #20 → #19 → #18 → #16 → #15 → #14 → #11 → #10 → #9 → #8).
- Перенесены изменения PR #29 (WOPI server, host, live gateway, CAS, regression tests, solution и локальные runner scripts). Перенос файлов по GitHub API, **не эквивалент успешно проверенному git merge/сборке**.
- Исторические альтернативные PR #12, #13 и #25 не объединять отдельно без дифф-проверки; соответствующие части кода переиспользованы в основной цепочке PR #14, #18, #29. Не удалять ветки до сводной приёмки.
- Legacy WPF `GetPdf.exe` и `GUP-Scan` не удалены. Сканирующий движок/драйверы остаются в «ГЭТ Сканирование» (отдельный репозиторий).
- Новый per-user script `packaging/register-get-document-capabilities.ps1` регистрирует только *возможность выбора* обработчика, не меняя Windows UserChoice и существующий `GetPdf.PDF`.

## 3. Блокирующие критерии (обязательно до main/release)

| Gate | Что требуется | Состояние на 24.10.2026 |
|---|---|---|
| G1 — Статическая структура | все проекты solution и ссылки существуют; нет конфликтных веток, дублированных определений, запрещённых новых зависимостей | интеграционные файлы собраны; требуется полный независимый review |
| G2 — Локальный build + тесты | `dotnet restore GetDocument.slnx`; `dotnet build GetDocument.slnx -c Release --no-restore`; `bash scripts/verify-get-document-linux.sh` / Windows PowerShell аналог; старый GetPdf тестируется отдельно | **НЕ запускались:** .NET SDK отсутствует в данной среде |
| G3 — Одно окно | 1/2/3 запуска, разные файлы, 2 пользователя Windows, переключение Ctrl+Tab, повтор пути, закрытие несохранённого DOCX/XLSX | не выполнено |
| G4 — PDF parity | многостраничный просмотр, поиск, выделение, OCR, формы, электронная подпись, печать Windows-драйверы, A4/A3/duplex, сравнение, разделение, аннотации, сохранение копии | **не достигнут:** Avalonia пока рендерит по 1 странице и не подключает полноценную печать/редактирование |
| G5 — Office parity | реальные DOCX/XLSX/PPTX, формулы, диаграммы, стили, шаблоны, сложные таблицы, совместимость/roundtrip с Microsoft Office на эталонном наборе | **не достигнут:** локально поддержаны простые сценарии |
| G6 — Real-time | корпоративные Collabora/ONLYOFFICE, HTTPS, pinned discovery, signed POST launch во вкладке, текущее ACL на каждый GetFile/PutFile, 2/5/10 пользователей и конфликты | **не достигнут:** шлюз deny-all по умолчанию, нет trusted enterprise store/сервера |
| G7 — GUP-2 | авторизованный handoff без передачи bearer в командной строке, новая версия с CAS/ACL/WORM, audit/revocation, интеграция тестовых карточек | **частично:** скачивание и локальный IPC; полноценный roundtrip незавершён |
| G8 — Безопасность | DTD/XXE, path traversal, token replay, tampering, zip bombs, 32 MiB bounds, TLS/proxy logs, отказ при сбоях прав, секреты только на сервере, SBOM/licenses | требует локального аудита и испытаний |
| G9 — Упаковка | Windows installer, Linux packages, фирменное название и иконка, ассоциации *по согласию*, миграция профиля и rollback; работа со SMB Windows/Linux | не выполнено |
| G10 — Корпоративная эксплуатация | офлайн-репозиторий NuGet, 5–6-летние ПК, 2 монитора/DPI, проверка UI/UX по брендбуку, руководство и проверка ИБ | не выполнено |

**Запрещено заявлять 100% покрытие, полную совместимость MS Office, юридически значимую проверку КЭП или готовность к релизу до реальных испытаний.**

## 4. Локальный запуск и тестирование

На доверенной Windows/Linux машине с .NET SDK 10, корпоративным пакетом offline NuGet и тестовыми документами:

```sh
dotnet restore GetDocument.slnx
dotnet build GetDocument.slnx -c Release --no-restore
dotnet test tests/GetDocument.Core.Tests/GetDocument.Core.Tests.csproj -c Release --no-restore
dotnet test tests/GetDocument.Office.Tests/GetDocument.Office.Tests.csproj -c Release --no-restore
dotnet test tests/GetDocument.Images.Tests/GetDocument.Images.Tests.csproj -c Release --no-restore
dotnet test tests/GetDocument.Revisions.Tests/GetDocument.Revisions.Tests.csproj -c Release --no-restore
dotnet test tests/GetDocument.Collaboration.Tests/GetDocument.Collaboration.Tests.csproj -c Release --no-restore
dotnet test tests/GetDocument.WopiGateway.Tests/GetDocument.WopiGateway.Tests.csproj -c Release --no-restore
```

На Windows дополнительно `powershell -ExecutionPolicy Bypass -File scripts/verify-get-document-windows.ps1`; на Linux `bash scripts/verify-get-document-linux.sh`. Скрипты проверяют code path, но не заменяют реальные 2-пользовательские GUI/SMB/WOPI и PDF-принтер tests.

## 5. Переход пользователей и откат

1. Собрать и подписать пакет, проверить издателя и зависимости в закрытом контуре; сначала тестовая группа ИТ, затем пилот ПТО.
2. Переносить пользовательские настройки выборочно, без автоматического копирования токенов, паролей, истории открытых чувствительных документов или незавершённых черновиков. Бэкапы отдельно; настройки `GET-PDF` не удалять.
3. Установить «ГЭТ Документ» параллельно legacy. Ассоциации не перехватывать автоматически. На тестовом компьютере добровольно выбрать новый обработчик.
4. Проверить все G1–G10, уязвимости и реальные бизнес-сценарии. Только после этого PR может быть переведён из Draft, рассмотрен, объединён в `main` и помечен релизом.
5. При сбое пользователь возвращает прежнюю ассоциацию «ГЭТ PDF» и установленный WPF-клиент; WORM-оригиналы и неподтверждённые редакции остаются неизменными. Никакой необратимой миграции в этой ветке нет.

## 6. Открытые технические долги

- Перенести нужные WPF PDF операции в кроссплатформенные Core/adapters либо заменить проверенными интегрируемыми библиотеками; приоритет **редактирование и печать в тех же вкладках**, без второго окна.
- Привязать real-time Editor launch к desktop WebView только после проверки корпоративного trust-origin, ACL, sandbox, лицензий, совместимости, собственной оболочки ГЭТ и запрета утечек.
- Подключить trusted GUP-2 revision store / SSO / пользовательские роли / аудит. Не использовать `ImmutableOfficeRevisionStore` в качестве production WORM.
- Завершить интерфейс «ГЭТ Сканирование» через безопасный локальный контракт, не объединять в репозиторий TWAIN/WIA и драйверы.
- Окончательное имя продукта — «ГЭТ Документ»; имя репозитория `get-pdf` сохранить до успешного выпуска, чтобы не ломать старые ссылки и сборочные интеграции.
