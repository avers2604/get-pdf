# GD-15 — масштабирование PDF в общих вкладках

Дата: 25 октября 2026. Статус **Draft / не проверено на Windows/Linux**.

## Реализация

- Stacked на GD-14 (#36): PDF-поиск, PDF-навигация, Office return, GD-12 conflict, GD-12 WOPI/OXML UI остаются без изменений.
- Новая `GetDocument.Core.Preview.PdfViewScale` задаёт пять проверяемых шагов 60/75/100/125/150% относительно базового размера чтения, с ограничениями допустимых растрированных размеров (1..2048 px).
- В `PdfPreviewPane` появляются кнопки уменьшения/увеличения и видимый процент; `Ctrl++`, `Ctrl+-` и `Ctrl+0` работают при активной PDF-вкладке.
- Изменение масштаба корректирует ширину/высоту текущего `Avalonia.Image`; **без нового вызова PDFium**, повторной загрузки файла и нового дискового/сетевого обращения. При переключении страницы выбранный масштаб сохраняется только в памяти **этой вкладки**, не влияет на другие.
- Встроенный `ScrollViewer` допускает прокрутку, когда увеличенная страница шире текущего контейнера. 100% — относительный размер интерфейса, **не** PDF print physical scale/DPI.
- Тесты `PdfViewScaleTests` проверяют исходный масштаб, переходы и граничные шаги, размеры и пропорции, invalid input.

## Предстоящая проверка

```sh
dotnet restore GetDocument.slnx
dotnet build GetDocument.slnx -c Release --no-restore
dotnet test tests/GetDocument.Core.Tests/GetDocument.Core.Tests.csproj -c Release --no-restore
```

Ручной UI smoke — 60/75/100/125/150% на Windows и Linux, смешанный DPI и два монитора, огромные страницы, PDF в двух вкладках, Ctrl++/−/0, ScrollViewer и фокус ввода в поиске, одновременный поиск/навигация/масштаб, работа на старых ПК. Проверить реальный визуальный размер и читаемость; статическое code review их не доказывает.

**Функциональный паритет с legacy ГЭТ PDF ещё не достигнут**: до промышленного переключения остаются выделение глифов, OCR, диалог и драйверы печати, AcroForm, подписи, редактирование и GUP-2/WOPI E2E. Не менять default app/не сливать в main без локальных тестов. GitHub Actions выключены.
