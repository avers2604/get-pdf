# GD-17 — дополнительные параметры собственного мастера печати ГЭТ

**Дата:** 26 октября 2026. Ветка поверх GD-16, PR #39. **Статус:** исходники готовы к локальным испытаниям, не объявлять релизом.

## Поведение в интерфейсе

В шаге 2 мастера печати ГЭТ (внутри существующей вкладки, без системного `PrintDialog`) добавлены:
- **Ориентация:** автоматически (по документу), книжная, альбомная.
- **Цвет:** настройка принтера, цветная, чёрно-белая.
- **Размещение:** одна, две либо четыре страницы на листе.

По умолчанию дополнительные установки **не подменяют** возможности/настройки выбранного устройства. 2/4-up запрещено комбинировать с выбором отдельных страниц: CUPS может трактовать `-P` как номера физических выходных страниц, а не PDF-страниц. Это сознательное защитное ограничение GD-17. Два/четыре-up вместе со **всеми страницами** доступны на устройствах, поддерживающих данную функцию. Итоговый экран показывает ориентировочное число печатных сторон; фактическое количество листов при дуплексе и драйверная компоновка зависят от оборудования.

**Нельзя выполнять скрытый fallback** с цветного режима в чёрно-белый, с альбомного в книжный или с 4-up на 1-up. Если выбранная функция не подтверждена устройством, задание блокируется.

## Backend

- `PrintJobPlan.Create`: новые необязательные типизированные параметры `PrintOrientation`, `PrintColorMode`, `PrintPagesPerSheet`. Старые вызовы с 6 параметрами сохраняют прежний результат.
- `CupsPrintArguments`: аргументы `lp -o orientation-requested=3/4`, `-o print-color-mode=color/monochrome`, `-o number-up=2/4`. Пользовательские строки не попадают в shell. Базовые аргументы и порядок наследуются от GD-16.
- `CupsColorCapabilities`: если запрошен явно цвет или чёрно-белая печать, перед отправкой требуется `lpoptions -p QUEUE -l` с **IPP `print-color-mode`**, в котором присутствует запрошенное значение. Старый `ColorModel` PPD умышленно не приравнивается к IPP: производитель может иначе интерпретировать режим. Драйверы без формально объявленных опций используют режим `Настройка принтера`.
- Windows `GetDocument.PrintWindows.exe`: проверяет `PageOrientationCapability`, `OutputColorCapability`, `PagesPerSheetCapability`; задаёт `PrintTicket.PageOrientation`, `OutputColor` и `PagesPerSheet`. Если функция не опубликована драйвером — отклонение до печати. При Landscape меняет размеры физического листа в `DocumentPaginator`.
- **Защита от дубликатов:** после первой попытки отправки (включая сетевой таймаут и неоднозначный результат) эта вкладка не может отправить задание повторно. Для новой попытки нужно сначала проверить очередь и открыть новый мастер.
- Профиль локального МФУ и настройки `UserChoice` не изменяются, GUP-2/WORM документы не переписываются.

## Проверки, требуемые до merge

Новые MSTest:
- `AdvancedPrintSettingsTests`: совместимость API, проверка неизвестных enum, книжная/альбомная, монохром, CUPS argv, 2/4-up и запрет неполного диапазона.
- `CupsColorCapabilitiesTests`: поведение при объявленных/отсутствующих IPP возможностях, устаревших PPD, некорректном выводе `lpoptions`.

Локально с .NET SDK 10:
```powershell
pwsh -File scripts/verify-get-document-windows.ps1
pwsh -File scripts/windows-build-get-document.ps1
```
На Linux:
```sh
bash scripts/verify-get-document-linux.sh
```
После компиляции и MSTest проверить **реальные принтеры** Windows 11 и Astra Linux: 1/2/4-up, A4/A3, B/W/Color, ориентацию, дуплекс, выбор диапазона, файл 1000 страниц, повтор при обрыве сети, устройство без цветной печати, устройство без 4-up, права на сетевую очередь. Проверить отсутствие системного print dialog и передачу через уже установленные службы/драйверы.

**Ограничения:** лоток бумаги пока не выбирается внутри мастера — нужен безопасный динамический список из реальных возможностей каждого принтера; выбирать произвольный «Лоток 2» на устройстве без второго лотка нельзя. Предпросмотр показывает PDF-страницу, не финальную раскладку и поля принтера. В этом окружении .NET SDK/Windows print spooler/CUPS/физические принтеры отсутствуют: новые тесты написаны, но не запущены.
