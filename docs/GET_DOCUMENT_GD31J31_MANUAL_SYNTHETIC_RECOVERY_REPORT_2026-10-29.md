# GD-31J.31 — ручной просмотр и обезличенный отчёт о синтетических аварийных остатках

**Дата:** 29 октября 2026. **База:** Draft PR #102 (GD-31J.30). **Статус:** исходники и тесты подготовлены; реальные сборки, тесты, Qt/CEF, VM и проверки файловой системы пока **не запускались**. Протокол не предоставляет доступа к пользовательским документам и не является производственным механизмом восстановления.

## Что изменено

Добавлен `EuroOfficeSyntheticRecoveryReport` — явный read-only API для оператора автономной синтетической лаборатории.

`Build(stagingRoot, pageIndex=0, labApproved=false)` переиспользует единственный существующий инспектор `EuroOfficeSyntheticSnapshotJournal.Inspect` из GD-31J.30 и его ограничения: только существующий локальный каталог `<staging>/reviewed`, без обхода вложенных каталогов и символических ссылок; не более 2048 каталоговых записей / 256 соответствующих журналов и pending-файлов / 8 КиБ на журнал. Для вызова требуется явное `labApproved=true`; при пустом, относительном или небезопасном пути, либо при превышении лимитов, операция отказывает без исправления данных.

### Отчёт версии 1

`Page.ToJson()` формирует строго ограниченный JSON **только в памяти**. Встроенной записи файла, отправки по сети или копирования в буфер обмена нет. Пользовательский ввод, содержимое OOXML, текст журнала и имена найденных файлов в JSON не включаются.

- `schema=getdoc-synthetic-recovery-report/1`, `scope=synthetic-offline-reviewed-only`;
- `pageIndex`, `pageCount`, `totalFindings`;
- булевы `readOnly=true`, `manualReviewRequired=true`, `cleanupAuthorized=false`, `authorizedForPublication=false`, `durabilityProven=false`;
- `counts`: суммарные счётчики **всех 8 состояний** независимо от выбранной страницы;
- `findings`: не более 32 записей на страницу со строго перечисленными `state`, `lastStage`, краткой рекомендацией только для ручного анализа и `attemptId` **только для связанного с валидированным журналом GUID**; в случае `UnknownPending` / `MalformedJournal` идентификатор равен null. Любые потенциально враждебные имена и ошибки JSON не переизлучаются.

Максимум 16 384 символа JSON. Максимум восемь страниц (в общей сложности до 256 наблюдений). Неверный индекс страницы — отказ. Пустой отчёт остаётся непривилегированным: отсутствие находок не является доказательством надёжности или целостности файловой системы.

### Классификация и дальнейшие действия оператора

| Статус | Что означает и что разрешено |
|---|---|
| `PendingNeedsReview` | Запись ожидания есть, финальная копия отсутствует. Только изучение в автономном стенде |
| `PendingAfterLink` | Одновременно наблюдаются temporary и final имена. Не удалять и не «чинить» автоматически |
| `CompleteObserved` | Файл и завершённый журнал присутствуют. Это не доказательство сохранности после power loss |
| `UncertainAfterLink` | Конечная запись существует, отметка о завершении отсутствует. Ручная проверка |
| `NoOutputObserved` | Журнал есть, но результата не видно. Ручная проверка |
| `MissingFinal` | Отметка `completed` есть, конечного файла нет. Ручная проверка |
| `MalformedJournal` | Журнал неверный, испорчен или подставлен. Не доверять записям и не использовать для очистки |
| `UnknownPending` | Pending-файл без подтверждённого журнала. Не доверять имени и не удалять автоматически |

Даже корректный `attemptId` является идентификатором технической синтетической операции, а не правом удалять файл, публиковать его, переносить в WORM или считать подписанным. Все рекомендации статические — никаких команд по удалению/копированию данных и автоматических recovery-policy.

## Ограничения безопасности

Этот отчёт **не является** audit-log с юридической силой, достоверной аттестацией целостности, подписанной квитанцией или основанием для удаления. При внешнем изменении каталога в момент сканирования наблюдения могут быть противоречивыми; отсутствие файлов не подтверждает, что их не было или что ФС полностью стабильна. Данные отчёта могут содержать GUID сугубо синтетических попыток и внутренние состояния, поэтому передавать их можно только по отдельной политике лаборатории.

Действия удаления, перемещения, восстановления, импорта, серверной синхронизации, печати и публикации отсутствуют. Программа на рабочем ПК, лаунчер «ГЭТ Документ», GUP-2, Nextcloud, WORM, `main` и GitHub Actions не затрагиваются.
