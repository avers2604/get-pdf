# GD-08 — история редакций, контроль SHA-256, комментарии и DiffPlex

Дата начала: 23 октября 2026. Данный инкремент основан на Draft PR #20
и продолжает утверждённый план в `main`.

## SOURCE-FIRST, изоляция слоёв
- Использованы .NET `System.IO` / `System.Security.Cryptography` /
  `System.Text.Json` для файлового журнала без SQLite, внешней БД
  и облака; **не пишем собственный формат документа и криптографию**.
- Для сравнения текста используется готовый
  [DiffPlex 1.9.0](https://www.nuget.org/packages/DiffPlex/1.9.0)
  с лицензией **Apache-2.0**; в PR зафиксировать NOTICE при поставке.
- Новая независимая библиотека `GetDocument.Revisions` ориентирована
  на `net10.0` и не зависит от WPF или Avalonia.
- Существующие `GetDocument.Core`, `GetDocument.Office`,
  `DocumentWorkspace` и общая Avalonia-панель вкладок переиспользуются,
  второй файловый менеджер не создаётся.

## Функции первого инкремента
1. Сотрудник открывает любой поддерживаемый документ во вкладке и нажимает
   **«История и комментарии»**. Для этого документа создаётся
   отдельная вкладка в текущем окне.
2. Папка хранения метаданных выбирается **явно**, должна существовать
   и иметь подходящие права пользователя/SMB ACL. Приложение
   не создаёт автоматически служебных папок рядом с документом
   (в частности рядом с WORM-оригиналом).
3. **«Добавить существующую редакцию»** регистрирует ссылку на ранее
   сохранённый файл и его SHA-256. Журнал НЕ копирует файлы и
   НЕ занимается сохранением редакций; это выполняют соответствующие
   редакторы через Save As без overwrite.
4. Каждая регистрация и каждый комментарий — отдельный JSON-файл
   в выбранной папке, создаваемый через новый временный файл и
   `File.Move` без перезаписи. Проверка повторного открытия и
   предельного числа записей; чтение повреждённого события прерывается
   ошибкой, а не скрывает запись.
5. Комментарии могут относиться к документу целиком или выбранной
   редакции. **Поля автора вводятся вручную, личность через AD не
   подтверждается**, в UI это обозначено. Версионирования/удаления
   комментария пока нет.
6. «Проверить SHA-256» сравнивает текущие байты зарегистрированной
   редакции с контрольной суммой при регистрации. Это защита от
   **случайных изменений**, не доказательство юридической неизменности:
   атакующий с доступом к метаданным может изменить их вместе с файлом.
7. «Сравнить текст» сравнивает содержимое исходника и выбранной
   редакции построчно через DiffPlex, показывает добавленные/удалённые
   строки. Пока доступно для TXT/MD и **только простых DOCX**
   (через существующий `SimpleDocxTextService`); сложные DOCX
   намеренно отклоняются. PDF, XLSX, PPTX не сравниваются, функции
   их визуального diff остаются на будущий Office/PDF engine.
8. Существует **одна вкладка истории на открытый документ**;
   повторное обращение выбирает существующую, Ctrl+W и крестик
   закрывают её без закрытия самого документа.

## Границы и безопасность
- **Это НЕ серверный журнал аудита и НЕ WORM**:
  нет криптографической подписи журнала, серверного контроля ролей,
  AD-подтверждения автора, санкционирования комментариев, репликации,
  резервного копирования или защиты от удаления через SMB.
  Нельзя ставить флаг «подтверждённая неизменность».
- Записи содержат абсолютные пути к редакциям и комментарии:
  каталог метаданных должен быть защищён **отдельными корректными
  файловыми ACL**, иначе возможна утечка содержимого/имён.
- Привязка документа к журналу в первом прототипе **по хешу полного
  пути исходника**. Подключение того же SMB ресурса под разными
  Windows/Linux путями даёт разные ключи. Для общего серверного журнала
  потребуется стабильный идентификатор документа от сервера/GUP-2.
- Предусмотрен лимит 500 событий/документ и 16 КиБ/событие;
  контрольная сумма вычисляется потоково для файлов до 256 МиБ.
  Это пока не защищает от конкурентного редактирования индекса разными
  пользователями и TOCTOU на SMB; серверные проверки откладывать
  до стадии архитектуры версий GD-08B/интеграции GUP-2.
- В `main` уже закреплена граница: GUP-2 отдельно от GET-system;
  WORM-оригиналы GUP-2 всегда остаются неизменяемыми.
- История не создаёт/не редактирует исходный документ и не меняет
  WPF ГЭТ PDF или отдельный ГЭТ Сканирование.

## Тесты и локальные release gates
В `GetDocument.Revisions.Tests` добавлено **13 MSTest** на регистрацию,
повторное открытие, комментарии, SHA-256, неизменность байт источника,
отсутствующие файлы, запрет чужого RevisionId, контроль JSON,
границы и сравнение кириллицы/пробелов. Тесты добавлены до кода.
**У доступного исполнителя отсутствует `dotnet` SDK, поэтому
компиляция и выполнение тестов не подтверждены.**
На Windows/Linux:
```sh
dotnet restore GetDocument.slnx
dotnet build GetDocument.slnx -c Release --no-restore
dotnet test tests/GetDocument.Revisions.Tests/GetDocument.Revisions.Tests.csproj -c Release --no-restore
```
В локальные `scripts/verify-get-document-windows.ps1` и
`scripts/verify-get-document-linux.sh` добавлены команды этих тестов.

Ручная приёмка: выбрать каталог метаданных на SMB, зарегистрировать
TXT/DOCX/PDF-редакции, перезапустить приложение, открыть историю,
внести комментарий, увидеть контрольные суммы, изменить файл
через Проводник и убедиться в предупреждении об изменении,
проверить отказ при отсутствии прав, закрытие истории и работу
на Astra/ALT/РЕД ОС. Отдельно проверить отказ при повреждённой JSON-записи,
недоступном сервере и переполнении лимита.

**Все новые PR оставить Draft. GitHub Actions не включать и код в `main`
без локальной приёмки не сливать.**
