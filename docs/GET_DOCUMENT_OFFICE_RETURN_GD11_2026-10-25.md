# GD-11 — ГЭТ Документ: ручной защищённый возврат DOCX/XLSX в GUP-2

**Дата:** 25.10.2026. **Статус:** исходники + MSTest для проверки, **не** локально подтверждённая сборка.
**Сервер:** черновой [GUP-2 PR #162](https://github.com/avers2604/Gup-2/pull/162) поверх #159/#156. Никаких GitHub Actions.

## Сценарий сотрудника

1. В «ГЭТ Документ» измените документ, сохраните его **в новый DOCX/XLSX-файл**. Не перезаписывайте WORM/PDF или подписанные исходники.
2. Откройте карточку **черновика** в GUP-2. Если ИТ-служба разрешила native return, нажмите «Получить код возврата в ГЭТ Документ». Код живёт пять минут и расходуется за одну попытку.
3. В программе выберите верхнюю команду **«Отправить в GUP-2»** (отображается только при разрешающей политике), затем выберите локальную/SMB рабочую копию и вставьте полученный одноразовый код. Нажмите **«Отправить рабочую копию в GUP-2»**.
4. Клиент делает один HTTPS POST и показывает успех только после HTTP 201 и правильного JSON-ответа `working_copy_saved` с новой версией карточки и SHA-256. В случае отказа код нужно получить заново. Проверить сохранение в карточке GUP-2.
5. **Это отдельное действие, не автосохранение в GUP-2 и не совместное редактирование.** Результат — новая **рабочая копия** в GUP-2, не юридическая публикация и не изменение WORM.

## Разрешающая корпоративная политика

По умолчанию кнопка скрыта и отправка заблокирована. ИТ-служба, **только после локального теста и разрешения ИБ**, создаёт:
- Windows: `%ProgramData%\GET-Document\policy.json` (ACL: запись только у администраторов, чтение у сотрудников);
- Linux: `/etc/get-document/policy.json` (владелец root, обычным пользователям только чтение).

```json
{
  "Version": 1,
  "AllowGup2OfficeReturn": true,
  "Gup2DocumentsUrl": "https://gup2.example.internal/documents/",
  "MaxOfficeUploadBytes": 157286400
}
```

Здесь домен — **пример**, не адрес реальной инсталляции. Разрешён только утверждённый абсолютный HTTPS URL раздела документов, без username/password/query/fragment, без произвольного пути; при неверном/отсутствующем JSON — закрытый режим. `MaxOfficeUploadBytes` согласовать с GUP-2 `UPLOAD_MAX_BYTES` и прокси; сервер по умолчанию ограничен 150 МиБ. Клиент не запрещает корпоративный системный proxy, но не отключает валидацию PKI.

## Безопасность

- `HttpClientHandler`: нет cookies, автоматических HTTP redirect, preauthentication/default credentials, отсутствует bypass TLS validation.
- Секрет только в `X-GetDocument-Upload-Code`, не в URI, командной строке или file metadata. Поле кода маскируется и очищается при отправке; не вести сетевой debug dump запроса и HTTP-заголовков.
- Файл передаётся потоково (не копируется полностью в оперативную память), максимум размера из корпоративной политики; только DOCX/XLSX. Сервер повторно проверяет оригинал/рабочую копию по SHA, текущую редакцию, пользователя, AV и макросы.
- Подписание/КЭП и регистрация юридической редакции — отдельно. Кнопка не является SSO, не запускает WOPI, не даёт доступ к другим документам. Скачанные ДСП-копии удалять по политике.
- При статусе, отличном от 201, или некорректном JSON возврат не подтверждается. **Не повторять POST автоматически с тем же кодом.**

## Следующие отдельные этапы

- связать текущий таб/документ с серверным UUID и ревизией через доверенный native-open capability, чтобы корректно показывать контекст GUP-2 без ручной проверки;
- полноценная серверная история неизменяемых рабочих версий + понятный 409 conflict UI, retries только через новый код;
- после отдельной оценки — WOPI/Collabora или ONLYOFFICE сервер реального совместного редактирования с настоящими server-side ACL/CAS/PutFile;
- GUP-2 PPTX нельзя разрешать до расширения модели и приёмки сохранения/просмотра.
