# GD-27 — релизная лаборатория и акт физической приёмки печати

Дата подготовки: 27.10.2026. Основа: GD-26 / PR №51.

## Цель раздела

Подготовить проверяемый переход от многочисленных Draft PR к реально собираемому продукту, **не подменяя реальную печать одними модульными тестами**. Этап GD-27 не свидетельствует о прохождении лаборатории: на момент создания настоящие сборки Windows/Astra Linux, .NET MSTest, установка и печать МФУ в доступной среде не выполнены.

## Исправления кода

1. Уточнён документированный синтаксис Microsoft.Testing.Platform для .NET 10: `dotnet test --project ... --results-directory <path> -- --report-trx --report-trx-filename <name>`. Параметры драйвера отделены от параметров тестового приложения.
2. Самотест XML DTD из GD-26 раньше содержал неверную TRX-структуру и мог проходить **не из-за запрета DTD**. Теперь DTD внедрён в полноформатный, в остальных отношениях корректный TRX с обязательными Passed-тестами: тест действительно проверяет блокировку опасного XML.
3. На Windows и Linux добавлены отдельные preflight-скрипты. Проверяются локальный офлайн NuGet feed, отсутствие сетевого mount, .NET SDK >=10 и наличие ключевых частей solution. Выводятся только хэши исходных конфигурационных файлов; персональные документы не читаются. Эти проверки встроены перед restore/build в release runners.
4. ReleaseGate проверяет, что ОС запуска соответствует запрошенной платформе. Итоговый JSON отдельно содержит `AutomatedTestsApproved`, `HardwareAcceptance = NotVerified` и **`ReleaseAuthorized = false`**, даже если TRX от всех проектов получил Passed. Старое поле `Approved` сохранено для совместимости и относится только к автоматическим тестам.

## Локальные команды

### Подготовка лаборатории

Astra Linux / ALT / РЕД:

```bash
bash scripts/check-get-document-lab-linux.sh /srv/get/nuget-feed
```

Windows PowerShell 7:

```powershell
pwsh -File scripts/check-get-document-lab-windows.ps1 -OfflineNuGetFeed 'D:\GET\NuGetOffline'
```

### Реальный запуск после успешного preflight

Astra Linux:

```bash
bash scripts/verify-get-document-release-linux.sh /srv/get/nuget-feed
```

Windows:

```powershell
pwsh -File scripts/verify-get-document-release-windows.ps1 -OfflineNuGetFeed 'D:\GET\NuGetOffline'
```

В обоих случаях обязательно сохранить вывод команд и число Passed/Failed/Inconclusive из TRX; подстановка старых отчётов запрещена. Новые скрипты работают без GitHub Actions и публичного NuGet.

### Протокол испытания

Для каждого реально выполненного пункта локально зафиксировать: дату/время, ОС/версию, модель и драйвер принтера, номер очереди (не идентификатор сотрудника), тип документа, параметры печати, фактические листы, `Passed/Failed/Blocked`, ссылку на защищённый локальный протокол и ответственного испытателя.

Нельзя подменять «Неподдерживаемо данным устройством» статусом Passed. Для функциональности A3 и duplex необходимо устройство, которое их действительно поддерживает.

## Когда разрешать релиз

- На Windows и Linux выполнена реальная сборка всей программы, отработали тесты обязательных проектов, `ReleaseGate --self-test` и получены отчёты без критических Inconclusive.
- Физические W01–S02 проведены на соответствующем оборудовании; известные ограничения и исключения согласованы отдельно.
- Не найдено повреждения WORM-оригиналов, принудительного сохранения Office-документов и утечки закрытых данных.
- Проверены подписи, лицензии, пакеты офлайн NuGet, драйверы и совместимость Astra Linux.
- Только после этого снять Draft и последовательно объединять зависимые PR. Автоматический JSON с `ReleaseAuthorized=false` сам по себе **не разрешает слияние**.

## Статус

В этом исполнении нет установленного .NET SDK и физического доступа к Windows spooler, CUPS и МФУ. Поэтому этап GD-27 **подготовил инфраструктуру лаборатории, но не выполнил её**. Серверный Euro-Office PR №42 остаётся отдельно до прохождения защищённого export-to-PDF с ACL/привязкой к версии документа.
