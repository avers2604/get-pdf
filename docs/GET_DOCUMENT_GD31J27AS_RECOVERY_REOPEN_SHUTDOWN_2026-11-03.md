# GD-31J.27as — повторное открытие документа и закрытие окна с долгой диагностикой

**Статус:** stacked Draft-ветка поверх GD-31J.27ar / PR #157. Реальный Windows/Astra/SMB-стенд, сборка C# и запуск MSTest пока недоступны. Код в существующих .NET 10 / Avalonia-проектах; не меняет `main`, WORM, native SaveAs и GitHub Actions.

## Найдено при проверке

1. При закрытии окна `MainWindow.Closed` освобождал редакторы, файловые сервисы и другие вкладки **раньше**, чем `RecoveryDiagnosticsPane`. Если наблюдение за временными файлами всё ещё исполнялось через медленный файловый или SMB-вызов, отмена поступала поздно.
2. `RecoveryDiagnosticsPane.Dispose()` отменял `_lifetime`, но тут же вызывал `_lifetime.Dispose()` при всё ещё работающей асинхронной проверке, связанной с этим источником. Это лишний риск гонки в жизненном цикле регистрации токенов отмены; важнее корректно завершать обработку **после** выхода задачи, не блокируя само закрытие окна.
3. `AttachedToVisualTree` вызывал `Focus()` даже при `_suspended=true`. При повторном присоединении невидимого содержимого это могло перехватывать клавиатурный фокус у открытого редактора.
4. В `scripts/tests/test_recovery_diagnostics_a11y_contract.py` оставалось устаревшее ожидание вызова `CloseRecoveryDiagnostics(id);`, хотя после GD-31J.27ar безопасное закрытие источника использует `CloseRecoveryDiagnostics(id, restoreSourceSelection: false)`. Исправлен ложный отказ старого source-only контракта.

## Исправлено

**MainWindow.cs**

- В синхронном обработчике `Closed` все открытые диагностические панели получают `Dispose()` **до** освобождения редакторов и остальных вкладок.
- `Closing` продолжает показывать подтверждение при несохранённых изменениях и **не отменяет** диагностику, если пользователь нажал «Вернуться». Отмена срабатывает только в реально завершившемся `Closed`.
- Синхронного `Wait()`, `Task.WaitAll()` или ожидания файловой операции при закрытии окна не добавлено. Поэтому медленный системный вызов не должен задерживать сам обработчик `Closed`.

**RecoveryDiagnosticsPane.cs**

- `Dispose()` немедленно помечает панель закрытой и отменяет текущий `_activeInspection` и общий `_lifetime`, но если `_busy=true`, освобождение общего `CancellationTokenSource` откладывается до `RefreshAsync.finally` после завершения операции.
- `DisposeLifetime()` и `_lifetimeDisposed` гарантируют отсутствие повторного Dispose для общего источника. Этот подход допускает, что зависший SMB-вызов удержит небольшой объект CTS до своего фактического завершения или завершения процесса; **не требует блокировать GUI** и не выдаёт «проверено» при отмене.
- `AttachedToVisualTree` вызывает `Focus()` только если панель не закрыта и не приостановлена. `ResumeInspection()` вызывает `Focus()` для действительно выбранной вкладки; если содержимое ещё не прикреплено, фокус установится при прикреплении.
- Ранее добавленные ограничения остаются: только `InspectIncomplete`, отсутствие чтения содержимого или удаления, отказ показывать stale результат после отмены, один набор кнопок.

**DocumentWorkspaceTests.cs**

- `ReopenedOfficeDocumentGetsNewTabIdentityAndNoStaleSession`: после закрытия и повторного открытия синтетического файла старый Guid вкладки не должен появиться снова; второе открытие уже активного файла переиспользует **новый** Guid.
- `ReopeningOfficeDocumentKeepsOtherOpenTabUnchanged`: повторное открытие A после закрытия не должно затрагивать открытую вкладку B.
- Это **MSTest на модель**, без настоящего ZIP/DOCX, сетевых папок или EuroOffice. Сценарии добавлены, но их исполнение не подтверждено.

## Тесты и приёмка

- `scripts/tests/test_recovery_reopen_shutdown_contract.py` — 6 новых source-only Python проверок: порядок отмены при `Closed`, безопасность отменённого `Closing`, отложенный lifetime CTS Dispose, фокус, два теста модели и инвариант только чтения.
- Исправлено ожидание закрытия вкладки в `test_recovery_diagnostics_a11y_contract.py`.
- `scripts/office_acceptance.py` запускает новый контракт до локального NuGet restore. Ручные Windows и Astra пункты остаются `not-run`, `releaseReady=false`:
  - `gd31j27as-reopen-document-session-windows-manual-e2e`;
  - `gd31j27as-shutdown-long-smb-scan-astra-manual-e2e`.

При разрешённом .NET 10 SDK и локально восстановленных зависимостях необходимо выполнить:

```sh
python3 -m unittest discover -s scripts/tests -p test_recovery_reopen_shutdown_contract.py -v
python3 -m unittest discover -s scripts/tests -p test_recovery_diagnostics_a11y_contract.py -v
dotnet test tests/GetDocument.Core.Tests/GetDocument.Core.Tests.csproj -c Release --no-restore --filter FullyQualifiedName~DocumentWorkspaceTests
dotnet build src/GetDocument.Desktop/GetDocument.Desktop.csproj -c Release --no-restore
```

Для ручной GUI-приёмки: открыть один и два DOCX/XLSX, открыть и закрыть диагностику, закрыть файл и вновь открыть **тот же путь**, убедиться в новом Guid вкладки и отсутствии привязанной старой диагностики. Отдельно на тестовом локальном/SMB хранилище искусственно замедлить чтение атрибутов/каталога: закрыть окно и подтвердить, что GUI не ждёт завершения вызова, закрытая панель не публикует новые данные, файловая операция не изменила ни один файл. При отмене диалога «Закрыть без сохранения?» работа вкладок продолжается.

**Выполнено фактически:** исходники и контракты прочитаны обратно из GitHub, пройдены статические structural checks. **Не выполнены:** C# компиляция, MSTest, реальные UI/Win32/Astra тесты, реальные сбои SMB и запуск Python unittest; не объявлять их пройденными.

## Оставшееся ограничение

Отмена файловой операции кооперативная: `Directory.EnumerateFileSystemEntries` на проблемном SMB может завершиться только после возврата ОС. Данный этап гарантирует **по замыслу кода** неблокирующее закрытие окна и запрет обновлять уже закрытую панель, но не абсолютную остановку фонового системного вызова. Для подтверждения нужен стенд.
