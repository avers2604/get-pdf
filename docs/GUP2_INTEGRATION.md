# ГЭТ PDF ↔ GUP-2: безопасное подключение, этап 1

**Два независимых приложения:** GUP-2 — веб-платформа
`avers2604/Gup-2`, ГЭТ PDF — WPF/Windows из
`avers2604/get-pdf`. ГЭТ System — третий независимый проект.

## Готово в исходниках двух отдельных черновых PR

1. В GUP-2 нормативная карточка документа показывает действие
   **«Скачать для ГЭТ PDF»** возле WORM-оригинала. Оно направлено на
   существующий `documents:file-link` с kind=`original`.
   Django выполняет существующую сессионную авторизацию, ДСП/ОСП,
   WORM/version pinning, аудит и отзыв доступа при передаче файла.
   В браузер не отправляется SILO presigned URL и не создаётся
   обходной публичный API.
2. После скачивания сотрудник открывает PDF в ГЭТ PDF через
   Windows «Открыть с помощью» либо назначает ГЭТ PDF
   приложением по умолчанию для `.pdf`.
   Установка MSI лишь регистрирует возможность выбора, она
   **не** перезаписывает пользовательскую `UserChoice`.
3. Кнопка **«GUP-2 ↗»** в ГЭТ PDF скрыта по умолчанию. Она
   появляется только по корпоративной политике:
   ```json
   {
     "Version": 1,
     "AllowGup2Portal": true,
     "Gup2PortalUrl": "https://gup2.example.internal/documents/"
   }
   ```
   Запишите фактический адрес вашей защищённой инсталляции GUP-2
   в `%PROGRAMDATA%\\GET-PDF\\policy.json`; домен в примере
   **не является** адресом действующего сервера.
   Допускается исключительно абсолютный HTTPS без имени
   пользователя, пароля, query или fragment. Кнопка открывает
   системный браузер с его существующей GUP-2 сессией.
   PDF-приложение не использует cookies, JWT, логины и пароли.

## Чего интеграция НЕ делает

- Не скачивает файлы напрямую по URL из GUP-2 внутри процесса WPF,
  не хранит сессии браузера и не обходит ДСП/ОСП.
- Не перезаписывает WORM-оригинал и не публикует
  изменённый PDF в GUP-2 без отдельной серверной операции.
- Не передаёт PDF или его имя в ГЭТ System.
- Не устанавливает MSI, не требует интернет, не отправляет телеметрию
  и не запускает браузер без нажатия пользователя.

Для записи новой редакции пользователь сохраняет **новую PDF-копию**
и загружает её вручную через существующий workflow GUP-2,
когда имеет соответствующее право. Активный оригинал не правится.

## Далее для настоящей двусторонней интеграции

Нужен согласованный GUP-2 REST/device-auth API с краткоживущими
одноразовыми grant, версионированием, SHA-256, отзывом полномочий
во время stream, защитой от MITM/redirect, аудитом и правилами
загрузки новых черновых редакций. Нельзя использовать
постоянную bearer-ссылку в `getpdf://` или передавать cookie
через командную строку Windows.

Реальные тесты в Windows (а также Django web security integration,
загрузка/удаление/ДСП и MSI ассоциации) **ещё не выполнялись**.
Текущий мост нельзя выдавать за прямое сетевое подключение.
