# GUP-2 → ГЭТ PDF: управляемое открытие одним нажатием

**Статус:** инструкция для лабораторной конфигурации. Не включено
автоматически MSI. Работает только после утверждения администратором
политик браузера и выбора ГЭТ PDF обработчиком `.pdf` в Windows.

## Почему без deep-link с токеном

Сотрудник уже авторизован в GUP-2 **в браузере**. Кнопка
«Скачать для ГЭТ PDF» использует существующий Django
`documents:file-link` для WORM-оригинала: ACL, ДСП/ОСП,
отзыв прав во время потоковой выдачи, WORM pinning и аудит.
Ответ — `Content-Disposition: attachment`, `Cache-Control: no-store`,
без presigned SILO URL в HTML. ГЭТ PDF получает локальный PDF,
не cookies, JWT, URL с bearer-токеном или учётные данные.

**Для одного нажатия** администратор **управляемого** Microsoft Edge
может разрешить автозапуск загруженных PDF только для строго
утверждённого HTTPS-источника GUP-2. Затем при загрузке PDF
Windows запускает выбранное приложение для `.pdf`.
Это настройка **рабочей станции**, не публичное PDF API.

## Контролируемые настройки Edge (Windows)

В `edge://policy` после применения корпоративных политик проверить:

| Политика | Значение |
| --- | --- |
| `AutoOpenFileTypes` | Список содержит `pdf` (без точки) |
| `AutoOpenAllowedForURLs` | Включает только утверждённый HTTPS origin GUP-2, например `https://gup2.corp.example` |
| Ассоциация Windows `.pdf` | ГЭТ PDF назначен пользователем/администратором через поддерживаемую политику Windows |

Пример **только формата значений** (это не реальный адрес ГЭТ):

```json
{
  "AutoOpenFileTypes": ["pdf"],
  "AutoOpenAllowedForURLs": ["https://gup2.corp.example"]
}
```

Обе политики обязательны **вместе**. Если оставить
`AutoOpenAllowedForURLs` пустой, `AutoOpenFileTypes` разрешит
автоматическое открытие PDF, полученных с **любых** сайтов.
Не применяйте такую конфигурацию. Администратор должен учесть
уже существующие правила для других типов файлов: общий список
разрешённых URL может изменить их поведение. Нельзя без согласования
перезаписывать управляемые политики или `UserChoice`.

Edge поддерживает эти политики на управляемых Windows-устройствах;
их фактическое применение, ограничения защит браузера и запуск
внешнего приложения необходимо проверить на рабочем месте.
SmartScreen продолжает проверять загрузки; автозапуск не обязан
срабатывать для заблокированных, подозрительных, незавершённых
или отозванных загрузок.

Справка Microsoft:
- https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/autoopenfiletypes
- https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/autoopenallowedforurls

## Read-only проверка политик

На Windows запустите подготовленный скрипт (адрес замените на
фактический утверждённый HTTPS origin GUP-2):

```powershell
.\\scripts\\windows-check-gup2-oneclick.ps1 -ApprovedOrigin "https://gup2.corp.example"
```

Скрипт читает Edge policy и выбранную Windows-ассоциацию `.pdf`,
но не меняет реестр, не открывает PDF и не передаёт учётные данные.
`ReadyForManualBrowserTest=true` означает только готовность
конфигурации к ручному испытанию, **не** успешную проверку запуска.

## Приёмка на тестовом рабочем месте

1. Пользователь с доступом открывает карточку WORM PDF в GUP-2.
2. Выполняет одно действие «Скачать для ГЭТ PDF».
3. Edge успешно скачивает **полный** файл, Windows открывает его
   в ГЭТ PDF. При 403/404/409/429, отзыве допуска во время stream
   или незавершённом Content-Length загрузка не должна открываться.
4. Сохранённый исходный SHA-256 сверяется с оригиналом GUP-2
   через команду «Сверить SHA-256 с GUP-2…» до редактирования.
5. Новая редакторская копия сохраняется в другой файл и передаётся
   в черновик через защищённую форму GUP-2; исходный WORM неизменен.
6. Проверяются чужой ОСП, ДСП без допуска, Edge не под управлением,
   PDF-обработчик не назначен, SmartScreen блокирует файл, повторная
   отправка той же редакторской копии и revocation в процессе передачи.

## Границы

Эта процедура даёт **условный однокликовый запуск** в управляемой
Windows/Edge-среде, а не универсальный запуск любого браузера.
Она не даёт нативному приложению право самостоятельно скачивать
документы и не создаёт автоматический возврат редакций.
Для полноценного двустороннего API необходим отдельный протокол
короткоживущих грантов с проверкой прав на каждом переходе.
