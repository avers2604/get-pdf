# GD-31F — сводные таблицы и выпадающие списки «ГЭТ Таблицы»

**Дата:** 28.10.2026. **Статус:** черновая реализация для локального Windows LibreOffice/UNO, **не проверена сборкой или полноценным запуском**. Продолжает #59 через stacked PR #64, #63, #62, #60. Основная ветка `main`, EuroOffice server, Nextcloud и GUP-2 не изменяются.

## 1. Сводная таблица (DataPilot)

На панели ГЭТ добавлено действие **«Сводная»**. Сотрудник сначала выделяет **ровно два соседних столбца**, включая строку заголовков, и нажимает кнопку.

Проверки до изменения документа:
- 3+ строк и максимум **10 000 исходных ячеек**;
- первая строка содержит два непустых текстовых заголовка;
- первый столбец содержит непустые категории;
- второй столбец содержит хотя бы одно числовое значение;
- исходный диапазон расположен **на активном листе**;
- не более 80 листов в книге; исходный документ доступен для записи.

Создаётся **новый лист** `ГЭТ Сводная N`. Через `XDataPilotTables.createDataPilotDescriptor` строится сводная: первая колонка — `ROW`, вторая — `DATA/SUM`. Результат располагается начиная с **B2** нового листа. Если движок выдаёт ошибку, вновь созданный лист удаляется; исходные ячейки не перезаписываются. Это намеренно **ограниченный первый сценарий**; настройка нескольких уровней группировки, произвольных агрегатов и фильтров потребует отдельного UI и тестов.

Ограничение: создание нового листа в открытом документе меняет **рабочую копию**. Сохранение оригинала по-прежнему управляется основным механизмом и требует согласованной политики ревизий/WORM до production.

## 2. Пользовательский выпадающий список

На панели ГЭТ добавлена кнопка **«Список…»**. В собственном модальном окне Avalonia можно ввести варианты (по одному в строке):

- от **2 до 20** вариантов, длина каждого — до **40 символов**;
- проверка отсутствия пустых значений и повторов, без учёта регистра;
- общий предел **200 символов формулы** для совместимости с XLSX;
- запрет формульных префиксов `=`, `+`, `-`, `@`, кавычек, точки с запятой и управляющих символов;
- значения проверяются **дважды**: в `OfficeChoiceList` и внутри Python bridge;
- применяется только к текущему выделению активного листа, максимум **50 000 ячеек**, без изменения существующих значений. Предыдущее правило валидации в этих ячейках заменяется.

На уровне UNO используется `ValidationType.LIST`, список литералов, `ShowList=1` и ошибка `STOP` при недопустимом вводе. Пользовательский текст не обрабатывается как произвольный код, URI или внешняя формула. Ограничения C# + bridge применяются при каждом вызове.

**Риск совместимости:** корректность переноса явного списка `Formula1` при сохранении в Microsoft Excel **не подтверждена**. Интеграционный тест проверяет OOXML-элемент `dataValidation`; если преобразование не поддерживается установленным LibreOffice, потребуется перевод на диапазон значений/именованный диапазон, а не скрытое удаление функции.

## 3. Тестовые сценарии и приёмка

- `OfficeChoiceListTests`: кириллица, порядок, пробелы, повторы, ограничения, попытки формульной инъекции, неизменность копии аргументов, read-only, запрет параметров для чужих команд.
- `OfficeFeatureCatalogTests`: новые команды должны быть отражены в общем каталоге и whitelist bridge.
- `CalcPivotAndChoiceListTests`: реальный LibreOffice: создаётся XLSX с числами и категориями, список для C2:C10, сводная по A1:B4, сохранение, повторное открытие OpenXML, проверка исходного листа, второго листа, `dataValidation` и сохранённой части `xl/pivotTables`.

Сборка и тестирование **не запускались в текущем сеансе**. Проведена только статическая сверка: **18/18** идентификаторов C# каталога присутствуют в Python whitelist и собственной панели ГЭТ. Этот результат не доказывает работу UNO API или OOXML round-trip.

Для Windows стенда:

```powershell
dotnet restore GetDocument.slnx
dotnet build GetDocument.slnx -c Release --no-restore
dotnet test tests/GetDocument.Office.Tests/GetDocument.Office.Tests.csproj -c Release --no-restore --filter "FullyQualifiedName~OfficeChoiceListTests|FullyQualifiedName~CalcPivotAndChoiceListTests|FullyQualifiedName~OfficeFeatureCatalogTests"
.\scripts\verify-get-document-windows.ps1
```

Ручная приёмка: XLSX с многолистовой книгой, 2–3 повторяющимися категориями, числами и формулами; сводная сумма; обновление источника и сводной после редактирования; сохранение, открытие в **Microsoft Excel** и проверка редактируемости PivotTable (не только картинки/статичной таблицы), кириллические значения списка, read-only, SMB и WORM; проверить сохранение связей с исходными листами. Отдельно оценить результат с подлинным EuroOffice DesktopEditors, когда его API подтверждён. До этого не переносить UNO вызовы в серверный движок.
