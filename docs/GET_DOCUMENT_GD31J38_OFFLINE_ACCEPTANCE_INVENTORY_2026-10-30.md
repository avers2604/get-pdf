# GD-31J.38 — предсборочная консолидация и воспроизводимая локальная приёмка

**Дата:** 30 октября 2026. **Исходная ветка:** `feature/gd31j37-contract-audit-timeout-manifest` (Draft PR #109, commit `cadadcd2c8678868ddaa61ad10cb0b58c732cf10`). **Режим:** изменения исходников, тестов и плана, **без реальной сборки, выполнения тестов, Native Qt/CEF, VM, сети или операций с рабочими файлами**. Следующий PR — stacked draft, не merge.

## Зачем понадобился GD-31J.38

За GD-31J.29–37 написаны десятки source-only контрактов и регрессионных тестов для `.NET 10`, CEF v1/v2, синтетической OOXML-копии, журнала и read-only диагностического отчёта. `scripts/office_acceptance.py` уже умеет `--plan`, локальную приёмку с explicit NuGet `--source`, проверку чистого Git revision, остановку на первом отказе, атомарный невозвратный JSON отчёт и пометки ручных этапов как `not-run`. Повторять механизм сборки в новом скрипте не нужно.

Обнаруженная недостающая проверка: прежняя `source_preflight` проверяла наличие `GetDocument.slnx`, ряда `*.csproj` и связность LibreOffice catalogue, но **не проверяла весь фактический список `CommandStep`**. Из-за ошибки в названии `test_*.py`, несуществующего Windows-проекта, повторения шага или незаметного изменения `dotnet restore --source` будущая приёмка могла начинаться с запуска инструментов, хотя план исходно неверен.

## Добавленный исходный fail-closed контроль

`validate_step_plan(root, steps)` выполняет **только чтение локальных файлов и проверку аргументов Python**, без процессов, NuGet, сети, установки SDK и filesystem mutations. Непосредственно перед любым `--plan` или обычным запуском вызывается именно этот валидатор, а `source_preflight` предварительно сверяет **обе** конфигурации — Windows и Linux — независимо от текущей ОС.

Условия отклонения:
- нет шагов, есть повторяющееся или пустое название;
- Python-команда не соответствует разрешённому `sys.executable -m unittest discover -s DIR -p test_name.py` либо одному из трёх заранее установленных headless Qt test harness. Обходные пути `../`, абсолютные, несуществующие файлы, wildcard Python маски и symlink, ведущие за пределы Git checkout, запрещены;
- обнаружены shell/URL/внешние команды или неизвестная `dotnet` операция;
- `dotnet restore` не содержит ровно одного explicit `--source` с разрешённым локальным feed, либо включает внешний URL/UNC/неожиданные опции. Для `--plan` разрешён только инертный placeholder `<approved-offline-feed>`, а для фактического запуска — существующий локальный каталог, предварительно проверенный main runner;
- `dotnet build` не содержит точное `-c Release --no-restore`, а `dotnet test` — `-c Release --no-restore --minimum-expected-tests 1`, без совпадения target и `CommandStep.project`;
- target `.slnx` или `.csproj` отсутствует в текущем Git checkout, `solution-build` расположен до `solution-restore`, тест расположен до общей сборки или конкретная сборка не имеет предшествующего локального restore для той же цели.

Это **контроль инвентаря команд**, не песочница. Даже при успешном `validate_step_plan` по-настоящему offline является только стенд с физически/сетевыми правилами запрещённым интернетом и заранее подготовленным доверенным пакетным источником. Скомпрометированные NuGet/SDK, `*.targets` и код тестов способны запускать произвольные действия. Проверка имени файла и аргументов **не доказывает безопасность содержимого**.

## Комплект проверки и требуемые условия

Установить отдельно и заранее **на изолированных ПК**:
- стабильный .NET SDK 10, Python, инструменты Git, локальный утверждённый каталог NuGet-пакетов и необходимые платформенные SDK;
- для Windows: тесты worker печати и `GetPdf.slnx`; для Linux/Astra: исходный `GetDocument.slnx`, CEF/Qt/Wayland стенд для ручных испытаний (нельзя считать обычный `dotnet build` проверкой нативного Qt);
- чистую Git-рабочую копию **точно той ревизии**, для которой создаётся отчёт; сохранение всех предыдущих draft PR в её истории, без зависимостей от интернета, GitHub Actions и доступа к корпоративным документам.

**Фаза 0 — только план, не запускать сейчас:**

```bash
python scripts/office_acceptance.py --plan
```

Команда `--plan` по замыслу проверяет источник и выведет JSON в игнорируемом `artifacts/local-acceptance/<unique>.json`. В нём `status=plan-only`, `automatedChecksPassed=false`, `releaseReady=false`, все шаги/ручные gate `not-run`; перечень шагов включает команды без их исполнения. Эта команда **ещё не запускалась** на рассматриваемом PR.

**Фаза 1 — будущая локальная автоматическая приёмка, только после отдельного разрешения** (пример пути feed, заменить своим реально утверждённым каталогом):

```bash
python scripts/office_acceptance.py --feed /approved/local-nuget
```

На Windows путь к feed задаётся по реальному локальному диску, например `D:\ApprovedNuGet`. Сценарий сначала проверяет чистоту Git tree, файл `global.json`, Python syntax и каталог функций, целостность перечня локальных команд, затем версию .NET SDK; после этого выполняет **локальные Python source gates**, `dotnet restore --source <local-feed>`, `dotnet build --no-restore`, `dotnet test --no-restore` и Windows-only дополнительные цели. Первый отказ блокирует последующие шаги; пропущенные имеют `status=not-run`. `--qt-host-binary` — отдельный opt-in для уже скомпилированной вручную нативной CEF/Qt программы; **не включается автоматически**.

`--feed` не устанавливает package provenance сам по себе: отдельно нужны SHA/подписи и лицензии каждого SDK/пакета, карантин на сторонние зависимости и контроль отсутствия выхода в Internet.

**Фаза 2 — только вручную, на аппаратном стенде:** нормальная работа собственного UI/вкладок, клавиатуры и IME; реальное CEF Save As с дубликатами/тайм-аутами; DOCX/XLSX/PPTX round-trip в EuroOffice/LibreOffice/MS Office; печать A4/A3; реальный SIGKILL/power-loss/NTFS/ext4/XFS и directory fsync; WORM/ACL/SSO; offline installer; лицензии, безопасность и развёртывание Astra/ALT/РЕД. Ничто из этого **не выполнялось**.

## Риски выпуска / стоп-факторы

1. **Ни одно приложение из накопленного PR-стека ещё не собрано и не запущено на платформе пользователя.** Целевой TFM `net10.0`, MSTest 4.5.1, CEF/Qt native ABI, P/Invoke Windows/Linux и NuGet-резолюция требуют настоящей сборки.
2. Синтетические OOXML пакеты не подтверждены MS Office; корректная ZIP/XML структура не равна fidelity.
3. Существует TOCTOU между SHA и hardlink; journal `completed` не доказывает durability/power loss, автоматическое восстановление/удаление остаётся запрещённым.
4. Синтетическая система не подключена к production сохранению, корпоративным WORM оригиналам, Nextcloud/GUP-2/GET-system. Результаты source-only tests **не разрешают** публикацию или релиз.
5. Любой failure будущего preflight блокирует всю дальнейшую автоматическую приёмку; **не снижать** проверки, пока не установлена точная причина.

**Фактический статус на 30.10.2026:** ни одна реальная сборка, .NET/Python тесты, Qt/CEF интеграционные прогоны и Windows/Linux/Astra VM проверки **не выполнялись**. Проверен только код и существование заявленных файлов через GitHub. Нельзя считать статус `plan-only` или корректность inventory доказательством релизной готовности.
