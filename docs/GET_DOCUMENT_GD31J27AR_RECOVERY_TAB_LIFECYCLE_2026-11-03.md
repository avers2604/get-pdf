# GD-31J.27ar — вкладки диагностики: отмена, повторный просмотр и возврат к документу

**Статус:** исходный код в stacked Draft-ветке над GD-31J.27aq / PR #156. Без Windows/Astra GUI-стенда. Не выполнять GitHub Actions, не включать native SaveAs/WORM и не объявлять `releaseReady`.

## Реальные проблемы предыдущей реализации

1. При закрытии диагностической вкладки `CloseRecoveryDiagnostics` сначала удалял `TabItem` из `ObservableCollection`, а **затем** проверял, была ли вкладка выбрана. `TabControl` может автоматически выбрать соседний элемент при удалении, поэтому условие зачастую становилось ложным: оператор попадал на главную или чужой документ, а не на исходный.
2. При закрытии исходного документа диагностическая вкладка могла направлять фокус обратно на **уже закрываемый** документ, поскольку карта `_views` и модель `_workspace` обновлялись после закрытия диагностики.
3. Фоновая `InspectIncomplete` продолжала сканировать локальный/SMB каталог даже тогда, когда оператор уходил в другую вкладку. Результат мог появиться позже без явного возобновления наблюдения.
4. Несколько быстрых переключений «диагностика → документ → диагностика» требовали отмены старого сканирования и **только одного** нового чтения после фактического завершения старой операции. Предыдущее `CancellationTokenSource` было привязано только ко всему жизненному циклу вкладки.

## Исправления

**MainWindow.cs**

- В `SelectionChanged` один выбранный `RecoveryDiagnosticsPane` получает `ResumeInspection()`, а все остальные — `SuspendInspection()`.
- Удалён прямой вызов `_ = pane.RefreshAsync()` при создании вкладки: первичную проверку запускает только переход в неё, так что не создаётся второй параллельный запрос.
- `CloseRecoveryDiagnostics` фиксирует `wasSelected` **до** `_items.Remove(view)`. При ручном закрытии выбранной диагностики возвращает к вкладке именно её исходного документа (`_views[sourceId]`). Если диагностика закрылась в фоне, текущая вкладка не меняется.
- `CloseDocument` сначала удаляет источник из `_views` и обновляет `_workspace.Close(id)`, затем вызывает `CloseRecoveryDiagnostics(id, restoreSourceSelection: false)`. Возвращаться к уже закрываемой вкладке запрещено.
- Для обычного закрытия документа `wasSelected` тоже фиксируется до удаления `TabItem`, чтобы автопереключение не подменяло выбор активного документа.

**RecoveryDiagnosticsPane.cs**

- `_suspended=true` по умолчанию, пока панель реально не выбрана.
- `SuspendInspection` отменяет текущий `CancellationTokenSource` конкретного осмотра, запрещает кнопку, показывает состояние «Проверка приостановлена».
- `ResumeInspection` запускает новую проверку. Если предыдущая ещё отменяется, `_resumePending=true` откладывает её до завершения старой. Повторные события выбора не создают дубликатов.
- `RefreshAsync` использует `CancellationTokenSource.CreateLinkedTokenSource(_lifetime.Token)`. Перед `Render(result)` обязательно проверяются `_disposed`, `_suspended` и `token.IsCancellationRequested`.
- При отмене скрытой вкладки нельзя показывать результат как свежий или заменять состояние «приостановлено» сообщением «нет файлов».
- `Dispose` завершает lifetime-токен, отменяет сканирование и запрещает отложенный повторный запуск.

## Что НЕ изменилось

Только `OfficeRecoveryStore.InspectIncomplete`: один документ, максимум 256 имён по умолчанию, без рекурсии; метаданные обычного файла, отдельная классификация ссылок и недоступных объектов. Ни одна операция просмотра не вызывает `CaptureAsync`, `Discard`, `File.Delete`, `File.Move`, `File.Write`, запуск EuroOffice, обращение к GUP-2 или WORM.

Отмена — кооперативная, не гарантирует немедленного прерывания системного SMB/NTFS вызова, если низлежащая файловая операция блокируется. При переключении результат отвергается после возврата задачи; сама проверка не превращается в доказательство завершения экспорта.

## Новые проверки

`scripts/tests/test_recovery_tab_lifecycle_contract.py` — **7 source-only Python регрессий** на: возврат к источнику, закрытие источника, переход между вкладками, отложенное возобновление, запрет устаревших результатов, отсутствие повторного старта и сохранение текущего фокуса при закрытии чужой диагностики.

Обновлены старые контракты `test_recovery_diagnostics_ui_contract.py` и `test_recovery_diagnostics_a11y_contract.py` под явное `ResumeInspection()` и проверку `_suspended`. Новый тест зарегистрирован в `scripts/office_acceptance.py` до offline restore, а в `scripts/tests/test_office_acceptance.py` добавлено подтверждение невыданных ручных гейтов:

- `gd31j27ar-recovery-tab-cancellation-windows-manual-e2e`;
- `gd31j27ar-recovery-tab-cancellation-astra-manual-e2e`.

**Фактически:** исходники проверены на наличие нужных переходов. C# сборка, GUI, MSTest и прямой запуск Python unittest не выполнялись в данной среде — не подменять их source-only проверкой. Гейты `not-run`, `releaseReady=false`.
