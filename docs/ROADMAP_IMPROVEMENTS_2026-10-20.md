# ГЭТ PDF — дорожная карта согласованных улучшений (20.10.2026)

Репозиторий: `avers2604/get-pdf`. Базовое выделение: draft PR #1 (`split/pdf-only-wpf`). Эта карта отражает согласованное внедрение **всех** предложенных функций. Начальная реализация ведётся отдельно в `feature/pdf-workspace-improvements`; статические проверки не равны PASS на Windows.

## 1. Стабилизация и UI — частично реализовано

- [x] Независимые search UI, Ctrl+F, Enter/F3 без открытия редактора.
- [x] Чистая главная панель просмотра: поиск, открытие PDF, печать; расширенные функции — в редакторе.
- [x] Drag-and-drop и локальная ограниченная история недавних PDF.
- [x] Локальные закладки, полноэкранный режим F11, непрерывный/одностраничный/двухстраничный просмотр.
- [x] Отдельное PDF-оглавление и внутренние /GoTo ссылки без выполнения URI/JS, выбор страницы по Ctrl+G, обратный поиск Shift+F3.
- [x] Исправление выбранной правой страницы в режиме разворота и синхронизация совпадений поиска.
- [x] Реальный WPF TabControl-host с независимыми рабочими областями PDF, управлением вкладками, выносом в окно и user-local восстановлением путей (реализовано в коде).
- [x] Копирование одной страницы между вкладками **в отдельный PDF** на основе `SaveMixed`; новые файлы не изменяют два исходника, при несохранённых редакторских изменениях операция блокируется.
- [x] Из меню «Копировать страницу в другой PDF» можно создать отдельный файл, не изменяя оба открытых документа.
- [x] Перетаскивание миниатюры в другой открытый PDF теперь добавляет страницу в его **приватный черновик** с Undo/Redo; предварительно создаётся и проверяется append-only версия рабочего PDF. Исходный файл не перезаписывается. Источник должен быть без несохранённых правок.
- [ ] Настоящий «переместить» с одновременным удалением страницы из исходного черновика, единым журналом Undo для двух документов и переносом несохранённой разметки; сейчас только копирование, а старый режим «новый PDF» оставлен отдельной командой.
- [ ] Windows-приёмка вставки/отмены/повторения, восстановления черновика после сбоя и сохранения нового PDF.
- [ ] Выполнить UI-приёмку и тесты памяти при 10–16 вкладках; доказать отсутствие потери правок и гонок при закрытии.
- [x] Выделение отдельных глифов PdfPig текущей страницы с Ctrl+C; без OCR-угадывания геометрии. При смене страницы отменяется задача, подсветка рисуется одним StreamGeometry, разрывы строк учитывают высоту символов.
- [ ] Выделение сразу нескольких страниц, сложные повороты/обрезка, правильный порядок колонок и Windows-UI-приёмка геометрии отдельных символов.
- [x] Чтение и отображение вложенного PDF outline; безопасные внутренние переходы /Dest и /GoTo через меню; внешний URI/JavaScript/Launch не запускается.
- [ ] Мышиные активные зоны внутренних PDF-ссылок, сложные именованные назначения и подтверждаемые внешние URL.
- [ ] Нормализация адаптивной панели и полноценные keyboard/accessibility/экранные тесты.

## 2. Печать — частично реализовано

- [x] Предпросмотр реального WPF paginator перед передачей в spooler, включая разметку и штампы.
- [x] Cancel в предпросмотре не вызывает PrintDocument.
- [x] Экспериментальный native PDFium/GDI HDC backend для PDF без наложений (политика по умолчанию false, предварительный просмотр и raster spool сохранены).
- [ ] Проверить, что native GDI действительно даёт необходимый векторный текст/линии с драйверами ГЭТ; аппаратная оценка DPI, A3/A4, драйверов, отмены обязательна.
- [x] Выбор A3/A4, ориентации, числа копий и дуплекса, проверка через PrintCapabilities, сохранение локальных предпочтений (в коде).
- [ ] Аппаратная проверка каждого драйвера МФУ, включая фактическое исполнение настроек и поля страницы.
- [ ] Подтверждённые тесты на физических устройствах, spooler errors, отмена, поля и читаемость мелкого текста.

## 3. Документы и PDF-инструменты — частично реализовано

- [x] Compare text layer: LCS выравнивание добавленных/удалённых/изменённых страниц, явное «сканы не проверены».
- [x] Lossless qpdf optimization только с ИТ-approved SHA-256, строгими проверками, и только отдельная копия.
- [x] Массовая нумерация страниц и независимый экспорт страниц (лимит 200 за операцию).
- [x] Копирование текста текущей страницы по явному действию пользователя.
- [ ] Выделение нескольких страниц, подробный визуальный diff и двусторонний перенос страниц с единым Undo между вкладками.
- [ ] Настоящие водяные знаки с координатами/поворотом/прозрачностью и сохранением структуры PDF.
- [x] Путь заполнения **плоских unsigned text-only AcroForm** (≤32 поля) через Aspose.PDF.FOSS, обязательный Arial и сверка значений в новой PDF-копии. Без записи в исходник.
- [ ] Проверка кириллицы и шрифта во внешних просмотрщиках, виджетов/appearances на Windows; сложные AcroForm и XFA пока не поддерживаются.
- [x] Автономная проверка целостности подписей через Aspose.PDF и системной цепочки сертификатов Windows (`X509Chain`, Offline CRL), fail-closed статус для неподдерживаемых алгоритмов.
- [ ] Полная проверка ЭП/КЭП: RFC 3161/время подписи, GOST/CryptoPro на стенде, политики доверия УЦ, OCSP/CRL в изолированной сети и юридический статус. В UI **не** выводится «КЭП действительна».
- [ ] Проверить качество исходного текстового редактора на шрифтах, кириллице, защите, формах и подписанных PDF.

## 4. Backend и безопасность — частично реализовано

- [x] Bounded PDF text comparison (1000 стр. и 2 млн символов на страницу).
- [x] LRU кеш миниатюр ограничен 12 элементами и оценкой 48 MiB.
- [x] Без сетевого сервиса/обязательных облачных API, локальные папки GET-PDF.
- [ ] Новое viewport-resolution rendering без декодирования полного исходного растра на каждое движение масштаба.
- [x] Ограничен одновременно выполняемый импорт PDFium для всех вкладок: 2; кэш готовых изображений — максимум 3 страницы/32 МиБ на вкладку.
- [x] CancellationToken передаётся из WPF scroll renderer, фоновых миниатюр **и подготовки страниц к печати** в асинхронный импорт PDFium; отменённые результаты не должны попадать в кеш или новую очередь печати.
- [ ] Профилирование UI/рендера (200/500/1000 страниц), native PDFium peak memory и жёсткий нативный memory budget (декодер всё ещё может временно занимать много памяти).
- [ ] Изоляция обработки недоверенных PDF в отдельном процессе и безопасная обработка повреждённых PDF.
- [x] Флаги корпоративной политики `RememberRecentDocuments` и `RestoreTabs`: отключение новой записи и удаление сохранённых путей при старте. Удаление каждого локального кеша независимо, чтобы ошибка одного не блокировала остальные; при отключении `ExportGetSystemStatus` старый JSON также удаляется.
- [ ] Расширенная политика ИТ-службы по закладкам, диагностике, паролям и очистке иных временных данных.
- [ ] Тесты конкурентных операций, восстановления после падения и адекватное покрытие критических веток.

## 5. Выпуск и интеграция — подготовлено, приёмка не завершена

- [x] WiX source для отдельного GetPdf MSI с новым UpgradeCode, ярлыком и Open With без изменения Windows UserChoice.
- [x] Локальный скрипт для restore/build/MSTest/publish/WiX/optional Authenticode и SHA-256 release manifest.
- [ ] Выполнение Windows gate, установка/обновление/удаление на тестовых ПК, контролируемая подпись релиза.
- [x] Ручная предварительная проверка offline MSI: pinned Authenticode сертификат, SHA-256, идентичность MSI, запрет понижения и процедурный флаг приёмки; без запуска MSI.
- [ ] Автоматическое развёртывание, строгий доверенный каталог, восстановление предыдущей версии и испытание обновления в Windows — не реализованы.
- [x] Локальный GET-system handoff JSON schema v1 (только версия, число окон/открытых документов, флаг печати, UTC), запись по явному `ExportGetSystemStatus=true`, по умолчанию выключено; нет путей, личных данных или PDF-текста.
- [x] Первый отдельный мост с GUP-2: кнопка в карточке PDF на GUP-2 использует защищённый Django download route, а GET PDF по opt-in политике открывает HTTPS-портал GUP-2 в системном браузере. Нет общего DB, SILO URL, токенов и прямого автозапуска.
- [x] Возврат подготовленного PDF в GUP-2 через браузер: отдельный POST с исходным WORM SHA-256 и версией карточки, проверка до и после AV, дополнительная проверка действующих прав, запись как неизменяемого WORM-приложения черновика с provenance. Оригинал не заменяется.
- [ ] Реальная one-click выдача GUP-2 → настольный GET PDF через авторизованный клиентский транспорт и автоматическая обратная регистрация юридических редакций; native протокол/API и аудит ещё необходимо согласовать.
- [ ] Двусторонняя авторизованная интеграция с реальным API GET-system и согласование контракта со службой GET-system — **совершенно отдельный этап**, просмотрщик работает автономно.
- [ ] После приёмки: второй PR к GUP-Scan для удаления PDF UI и лишних ассоциаций, **с сохранением экспорта полученных сканов в PDF**.

## Запреты и требования

- Не включать GitHub Actions и не объявлять локальные/hardware тесты пройденными без запуска.
- Не устанавливать scanner workers/TWAIN/WIA в PDF-продукт.
- Не изменять оригинальные документы и выбор пользователя для `.pdf` без явного действия.
- Не выдавать статические проверки подписей, форм или картинок за криптографическую/визуальную проверку.
- Ни PR #1, ни PR с улучшениями не объединять с `main` до Windows gate и согласованной приёмки.
