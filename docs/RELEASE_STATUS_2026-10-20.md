# ГЭТ PDF — принятые/непринятые возможности по выпуску

| Функция | Статус реализации | Что обязательно подтвердить на Windows |
|---|---|---|
| Много PDF во вкладках | Код есть | WPF memory, закрытие и черновики |
| Выделение текста | Посимвольное по реальным PdfPig glyph rectangles текущей страницы, отмена устаревших задач, единый StreamGeometry | Кириллица, колонки, вращение/crop, сканы, UI до 10000 glyphs |
| Заполнение AcroForm | Простые текстовые поля; signed/XFA/JS отказ | Шрифты, appearance, сохранение русских букв на внешних PDF-reader |
| Проверка ЭП | Локальная криптография + локальная цепочка | КЭП, ГOCT/CryptoPro, timestamp, OCSP/CRL, отказ доверия |
| PDF print preview | Raster spool по умолчанию, A3/A4/duplex/copies; отдельно экспериментальный native PDFium → GDI по политике | Windows/.NET build, аппаратный GDI print, сравнение EMF/spool и физическая векторность, отмена/дуплекс |
| Производительность | 2 одновременных native импортера, 32 МиБ bitmap кэша на вкладку; отмена передаётся в импорт | Native peak/CPU на PDF до 1000 стр. и закрытие вкладки во время импорта |
| MSI | Source WiX5 и offline PowerShell gate | Windows build, MSTest, install/upgrade/remove, Authenticode |
| Обновления | Read-only offline MSI preflight с SHA-256 и Authenticode; установка не производится | Проверить PowerShell/WindowsInstaller COM, PKI, реальный rollback |
| GUP-2 | Защищённое скачивание; локальная сверка SHA; обратная отправка PDF как WORM-приложение черновика через защищённый POST с проверкой исходного SHA/версии и AV | Проверить Django/ДСП/ОСП/ревокацию, WORM/SILO, автоматический native handoff и корректный workflow юридической редакции |
| GET-system | Опциональный локальный JSON v1, отключён по умолчанию; при запрете очищается прежний файл статуса | Согласовать reader/ACL и будущий API интеграции на стенде |
| GUP-Scan | Отдельный репозиторий без изменений | Сохранить экспорт сканов в PDF при будущей миграции |

Это **не** протокол успешной приёмки. PR остаётся Draft, пока реальное оборудование и Windows gate не проверены.

## Продолжение этапов 1–2 (21.10.2026)

- **GUP-2 PR #156:** idempotent return-copy под row lock. Одинаковая
  повторная отправка PDF из ГЭТ PDF с тем же WORM-источником не добавляет
  второе приложение; файл из другого происхождения с тем же SHA-256
  отклоняется. Проверка ревизии и прав выполняется до повторной записи.
  Добавлены регрессионные исходники Django tests, ещё не запускались.
- **Один клик — условно:** для управляемых Microsoft Edge и Windows
  описан корпоративный opt-in `AutoOpenFileTypes=pdf` вместе с
  `AutoOpenAllowedForURLs` и ассоциацией ГЭТ PDF; добавлен read-only
  preflight `scripts/windows-check-gup2-oneclick.ps1`.
  По умолчанию нет автоматического открытия и нет нативных JWT.
  См. `docs/GUP2_ONE_CLICK_WINDOWS.md`.
- **Нативная печать:** исправлен отказ для невозможных физических полей
  вместо молчаливого нарушения области печати; добавлены unit tests.
- **Формы:** исключены невидимые управляющие Unicode format-блоки,
  которые позволяют визуально подменить содержимое поля, плюс тест
  отсутствия перезаписи источника.
- **Не сняты release-блокеры:** сборка `dotnet build`, реальные `dotnet test`
  и Django tests с PostgreSQL, Windows UI, MSI, аппаратура печати,
  реальные ЭП/ГОСТ и интеграционный тест managed Edge не выполнены.
  Гарантия 100% покрытия и релизное одобрение не заявляются.

### Продолжение проверок (21.10.2026)

- В `global.json` явно выбран .NET 10 `Microsoft.Testing.Platform`
  для текущего `MSTest.Sdk`. Иначе запуск `dotnet test` по умолчанию
  мог не использовать нужный тестовый движок. Это настройка,
  а не протокол прошедших MSTest.
- Создан `scripts/windows-verify-code.ps1`: отдельно от WiX/MSI
  выполняет восстановление, сборку WPF и MSTest. И эта проверка,
  и MSI gate требуют обнаружения не менее 185 тестовых случаев, чтобы
  пустой/частичный тестовый запуск не прошёл ошибочно.
- Отказ от Unicode bidi/format-символов распространяется и на
  **имена** AcroForm полей; добавлены регрессионные исходники.
- GUP-2 PR #156 дополнительно повторно сверяет SHA-256/размер после AV,
  заново проверяет активную учётную запись до транзакции и корректно
  описывает ожидание WORM promotion после приёма PDF.
- `dotnet build`, `dotnet test`, PostgreSQL/Django tests и физические
  Windows/E2E проверки не выполнялись. Оба PR — Draft.

### Проверка конфликтов принтера (21.10.2026)

После выбора A3/A4, альбомной/книжной ориентации, числа копий и дуплекса
`PdfPrinterSettingsStore.ApplyTo` теперь вызывает штатный Windows
`PrintQueue.MergeAndValidatePrintTicket`. Если драйвер собирается
заменить хотя бы один запрошенный параметр (`ConflictResolved`),
задание отклоняется до печати и пользователь видит предупреждение.
Это защищает от незаметного A4 вместо A3, односторонней печати вместо
дуплекса и подобных несовместимых сочетаний. Добавлен unit-test политики
отказа при конфликте. Физическая проверка на принтерах ГЭТ ещё нужна.

## Первая фактическая Windows-сборка (22.10.2026)

Выполнено на Windows 11 x64, .NET SDK 10.0.402. Это **первый** реальный
прогон `dotnet build`/`dotnet test`; все прежние разделы описывали
только статическую проверку.

- `dotnet build GetPdf.slnx -c Release`: до исправлений не собиралось.
  Исправлено: отсутствующий `RecoverySnapshotRetention` (не перенесён
  из GUP-Scan; восстановлен строгой проверкой имени `recovery-{Guid:N}.png`),
  неоднозначный `ValidationResult` в печати, двойное экранирование
  в `PdfGetSystemStatusTests`, отсутствующий `using System.IO` в тестовом
  проекте, неверное пространство имён `PdfDictionary`/`PdfArray` PDFsharp 6.
- `dotnet test`: **181 из 181 пройдено** (порог обнаружения поднят до 181, включая тесты возврата в GUP-2).
  До исправлений падали 5 тестов, из них один дефект продукта:
  `PdfNativeAnnotationPolicy` отвергал любой PDF с XMP `/Metadata`,
  а PDFsharp 6 записывает XMP в каждый файл — сохранение комментариев
  в новый PDF не работало практически ни для одного документа. Теперь
  обычный XMP допускается, а заявленное соответствие PDF/A (`pdfaid`)
  по-прежнему отклоняется; добавлен регрессионный тест.
- `dotnet publish` self-contained win-x64: `dist\win-x64\GetPdf.exe`,
  без TWAIN/WIA/сканерных воркеров.
- Ручной UI smoke (`windows-smoke-viewer.ps1` + UI Automation): 3 PDF
  во вкладках, рендер кириллицы, миниатюры, поиск «ПРОВЕРКА03» с подсветкой
  и переходом, переход на стр. 20/25, A3 альбомная «Вся страница»,
  системный диалог печати → параметры ГЭТ → предпросмотр → отмена
  (виртуальный «Microsoft Print to PDF»; очередь заданий пуста).
- Найден и исправлен UI-дефект: в «Параметры печати» кнопки
  «Предпросмотр»/«Отмена» обрезались фиксированной высотой окна.

Не проверено и остаётся блокером выпуска: MSI/WiX (не установлен),
физическая печать на МФУ, AcroForm/ЭП на реальных документах, КЭП/ГОСТ,
GUP-2 end-to-end, разные DPI и экранный диктор. `releaseApproved=false`.

## Версия 0.1.1: доработка по замечаниям пользователя (23.10.2026)

- **Печать:** окно предварительного просмотра и собственный диалог «Параметры печати» удалены. Остался стандартный диалог Windows: принтер, бумага, ориентация, копии, двусторонняя печать, «Все / Текущая / Страницы с–по». Альбомная страница на книжном листе (и наоборот) автоматически поворачивается.
- **Прокрутка:** подготовка растров страниц и миниатюр вынесена из UI-потока, `DropShadowEffect` у страниц убран. На 30-страничном скане 300 DPI UI-поток не блокируется дольше ~60 мс.
- **Редактор:** вкладки «Разметка», «Документ» и «Текст» открывали чужие панели (ошибка соответствия индексов) — исправлено. Панели переработаны: заголовок, пояснение, понятные подписи.
- **Нумерация страниц:** вместо красного «штампа» в углу, который затирал штампы, — отдельный номер. Диалог: формат «1» / «1 из N» / «Страница 1 из N», положение, начальный номер, титульный лист без номера. Номер одинаков в просмотре, печати и сохранённом PDF.
- **Разметка:** подсказки при включении режимов; понятное сообщение, если страница повёрнута; кнопка «Убрать» для штампа.
- **Документ:** три пункта печати убраны. Сжатие qpdf и OCR скрыты, пока ИТ не установит утилиту и языковые модели. «Заполнить поля формы» на обычном PDF объясняет, что нужна PDF-форма с полями.
- **Сохранение:** предупреждение «Проверка PDF» показывается только при наличии подписей, полей, комментариев, ссылок или закладок и называет, что именно есть. Убрана приписка «(qpdf не установлен)».
- **Черновик после сбоя:** «Да» — восстановить, «Нет» — удалить черновик, «Отмена» — спросить в следующий раз (раньше вопрос появлялся при каждом открытии).
- **Дизайн:** выпадающие меню и окна сообщений приведены к DS 4.1 (`GetMessageBox` вместо системного `MessageBox`). Иконка программы — инверсный знак на тёмно-синем, у PDF-файлов отдельная иконка.
- Проверено: 185/185 тестов; сквозной сценарий через UI Automation (нумерация → штамп → сохранение, итоговый PDF проверен PdfPig); формы, подписи, состав, сравнение, копирование текста; отрисовка экранов через RenderTargetBitmap.
- Не проверено: обновление 0.1.0 → 0.1.1 на этом ПК (нужно подтверждение UAC), физическая печать, работа OCR и qpdf с утилитами от ИТ.

## Версия 0.1.2: история, избранное, qpdf в комплекте, мастер установки DS (23.10.2026)

- **Стартовый экран:** вместо пустой карточки — «Открыть PDF…», «Избранное» и «Недавние документы»
  (имя, папка, «сегодня, 16:06»). Строку можно открыть, отметить звёздочкой, убрать из истории;
  недоступный файл показан бледным и предлагается убрать его из списка. Пустая панель миниатюр
  без документа больше не показывается.
- **История открытия** включена по умолчанию (раньше была выключена политикой и кнопка часов
  не показывалась). Хранится время открытия; читается и старый формат 0.1.1.
- **Избранное:** звёздочка на панели инструментов (заливается жёлтым DS), до 50 документов,
  `%LOCALAPPDATA%\GET-PDF\favorites.json`. Меню часов показывает «Избранное» и «Недавние».
  ИТ может отключить оба списка в `policy.json` (`RememberRecentDocuments`, `AllowFavoriteDocuments`);
  при отключении сохранённый список удаляется при следующем запуске.
- **qpdf 12.4.2 входит в установку** (официальная сборка, SHA-256 архива закреплён в скрипте).
  Найден и исправлен дефект: код qpdf 3 («есть предупреждения») считался ошибкой, а qpdf
  выдаёт его даже на PDF, сохранённых самой программой, — после установки qpdf каждое сохранение
  сообщало бы «проверка структуры не пройдена», а сжатие и OCR-сборка отказывали бы.
  Сжатие больше не показывает лишнее «Проверка PDF» (qpdf не теряет закладки; подписи, формы и
  аннотации отклоняет PdfStructureGuard) и пишет «163 КБ → 70 КБ (−57 %)».
- **Установщик:** `GetPdf-0.1.2-Setup.exe` — мастер в стиле DS 4.1 поверх MSI; MSI остаётся для ИТ
  и получил DS-картинки в классическом мастере. Подробно — `docs/INSTALLER.md`.
- Проверено: 192/192 тестов; через UI Automation на собранной программе — звёздочка, запись в
  историю, стартовый экран, открытие из списка, сжатие 167 → 71 КБ встроенным qpdf; реальное
  обновление 0.1.0 → 0.1.2 через новый мастер.

## Версия 0.1.3: большие и нестандартные листы (26.10.2026)

- **Дефект:** PDF большого формата (A3–A0, плакаты, чертежи, баннеры) зависал или закрывал программу.
  Каждая страница и каждая миниатюра сначала целиком растрировалась в 300 dpi (лист A0 — около
  140 Мпикс, ~560 МБ на копию, плюс копии WPF) и только потом уменьшалась до экрана: пик памяти
  на A0 — больше 2,2 ГБ, на широком баннере — больше 1,6 ГБ.
- **Исправление:** просмотр и миниатюры рисуются PDFium сразу в нужном размере
  (`PdfPageRasterizer`, те же границы `PdfPreviewBounds` / `PdfThumbnailBounds`, что и раньше, —
  на A4 картинка не изменилась). Нативная библиотека `_win64\pdfium.dll` теперь находится и для
  собственных вызовов (раньше экспериментальная нативная печать получала `DllNotFoundException`).
  Печать и сохранение по-прежнему работают с исходным PDF.
- Проверено: 195/195 тестов (новые — размер A4 не изменился, A0 и лист 200×200 дюймов укладываются
  в границы, реальная отрисовка A0 через PDFium); пик памяти при открытии: A0 (3 стр.) 2,2 ГБ → 159 МБ,
  баннер 14 000×7 000 pt 1,6 ГБ → 151 МБ, плакат A3 12 МБ — 108 МБ, без ошибок в журнале.
- Не проверено: файл пользователя с другого ПК (его нет на этом компьютере); сканы с очень большими
  встроенными JPEG — PDFium по-прежнему один раз декодирует изображение целиком, но копий 300 dpi больше нет.
