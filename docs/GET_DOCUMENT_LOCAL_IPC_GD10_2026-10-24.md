# GD-10 — единое окно и безопасная передача локального файла (24.10.2026)

**Статус:** исходный код в stacked Draft PR; сборка .NET 10, Windows/Linux и E2E **не выполнены**. Не включать в релиз без локальной приёмки. Не включать GitHub Actions.

## Назначение и граница безопасности

Скачивание файла из GUP-2 продолжает выполнять **браузер с обычной сессией GUP-2**, через существующий серверный ACL/DSP/OSP/SHA/WORM-защищённый маршрут. Открытие файла по ассоциации `.pdf`, `.docx`, `.xlsx` или вручную запускает `GetDocument.Desktop <локальный-путь>`.

- Первый экземпляр владеет **именованным каналом ОС на текущий пользовательский профиль** с `PipeOptions.CurrentUserOnly`, без TCP, HTTP/port, открытого сервиса и расширения прав.
- Следующий экземпляр **не показывает ещё одно окно**: передаёт локальные пути первому экземпляру и завершается. Пустой вызов активирует окно.
- Первое окно переключается на уже существующую вкладку или создаёт вкладку в общем `TabControl`. Всё взаимодействие с UI идёт через `Dispatcher.UIThread`.
- В канал не допускаются URI, команды, `--` параметры, токены, сетевые ссылки/URL, неподдерживаемые типы и более 16 файлов за раз. Ограничены размеры сообщения, время ожидания и текущий OS-пользователь. Путь не пишется в серверный журнал; переданные файлы обрабатываются без повышения привилегий.
- Путь к файлу **не удостоверяет его содержимое**: парсер, антивирус на GUP-2, проверка MIME и лимитов должны работать самостоятельно. Уже скачанную локальную копию нельзя отозвать с сервера; выполнять политику ДСП и удаления.
- Без сервиса назначения браузер может только скачать файл. **Автоматическое открытие после скачивания** зависит от официально утверждённой политики браузера, ассоциации файлов, пользовательской системы и ОС. Установка не должна изменять `UserChoice` принудительно.
- Код **не предоставляет** новые сетевые GUP-2 endpoint, токены доступа, прямое сохранение редакций или совместное редактирование. Это следующий этап интеграции и отдельная приёмка.

## Локальный тест

```powershell
dotnet restore tests/GetDocument.Core.Tests/GetDocument.Core.Tests.csproj
dotnet test tests/GetDocument.Core.Tests/GetDocument.Core.Tests.csproj -c Release --no-restore
dotnet build src/GetDocument.Desktop/GetDocument.Desktop.csproj -c Release --no-restore
```

Проверить на Windows и Linux:
1. Первый запуск без аргументов: открывается окно «ГЭТ Документ».
2. Второй запуск без аргументов: существующее окно активируется; нового окна нет.
3. Вызовы с существующими PDF, DOCX, XLSX, PPTX: добавляются вкладки; второй вызов с тем же путём выбирает прежнюю вкладку.
4. Из другого пользователя Windows/Linux, из вредоносного URL и с параметром `--token`: передача не разрешена; окно другого пользователя не активируется.
5. Блокировка канала/зависший клиент, закрытие с несохранёнными данными, старт двух процессов одновременно: приложение не должно зависать и не должно создавать две редактирующие сессии.
6. Открытие файлов из SMB при имеющемся праве, повреждённые файлы, ДСП и конкуренция изменений — отдельные тесты с корпоративными данными.

## Оставшиеся задачи

- Нужна локальная сборка с Avalonia 12/.NET 10 и регрессия на целевых Windows/Linux. При падении IPC второй процесс **не создаёт отдельную сессию**; диагностику отказа/повтор надо добавить в установщик/системные события до выпуска.
- Native GUP-2 download/return: краткоживущий привязанный grant, REST, версия/хеш/CAS, корпоративный TLS/PKI, контроль отзыва, 409, audit, антивирус.
- Для PPTX серверной рабочей копии требуется согласованная модель GUP-2, не только локальная поддержка формата в редакторе.
- Совместная работа онлайн — только через настоящий WOPI gateway, офисный сервер, права на каждый запрос и проверку возвращаемой редакции.
