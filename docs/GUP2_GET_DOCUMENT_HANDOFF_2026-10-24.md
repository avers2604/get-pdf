# ГЭТ Документ ↔ GUP-2: интеграция рабочих копий и серверных редакций

**Дата:** 24.10.2026. **Тип:** совместимая спецификация к GUP-2 PR #159 поверх #156.
**Статус:** ручной Office handoff описан; защищённый native open/return и real-time не введены в эксплуатацию.

## Первый этап без нового сетевого API

- GUP-2 остаётся владельцем карточки документа, ACL/ОСП/ДСП, исходного PDF/WORM, статусов, версий и аудита. Локальная оболочка «ГЭТ Документ» не становится сервером документов.
- GUP-2 PR [#156](https://github.com/avers2604/Gup-2/pull/156): контролируемое скачивание `original` PDF; в черновике подготовлен возврат самостоятельной PDF-копии. Native direct-return скрыт флагом до локальных тестов.
- GUP-2 PR [#159](https://github.com/avers2604/Gup-2/pull/159): существующий контролируемый `documents:file-link` с `editable` передаёт **DOCX/XLSX**, доступные как `NormativeDocument.files_editable`. Запрос выполняет браузер пользователя. В приложение не передаются браузерные cookies, JWT или presigned SILO URL.
- На стороне «ГЭТ Документ» файл открывается через **существующее «Открыть файл»** в едином рабочем окне (`MainWindow.OpenFilesAsync` → `DocumentWorkspace.OpenExisting`); повторное открытие идентичного пути переиспользует таб. Автоперехват браузерной загрузки в уже работающий экземпляр **не реализован**; не имитировать его запуском второго окна.
- Пользователь сохраняет изменения отдельно, затем через штатный GUP-2 `Редактировать` возвращает рабочий DOCX/XLSX **в черновик** после серверных проверок. Утверждённый PDF/WORM не перезаписывается. Никакой скрытой фоновой отправки.
- `.pptx` поддерживается как локальный формат интерфейса ГЭТ Документ, **но не** как `files_editable` в текущей карточке GUP-2. Реальный серверный workflow презентаций — отдельный этап и отдельная миграция.

## Обязательная следующая реализация

1. **Native single instance:** при выборе локально скачанного файла приложение передаёт путь запущенному экземпляру через проверенный IPC со scoped ACL и без доверия к неподтверждённым сетевым источникам. Все типы открываются в верхних вкладках; путь не включать в телеметрию.
2. **Одноразовые capability/grant:** специальный GUP-2 endpoint только после официального согласования контракта, короткий TTL, привязка к пользователю/документу/версии, отзыв права до каждого нового фрагмента потока, HTTPS корпоративного PKI; секреты не включать в URI, процессные аргументы, debug/log.
3. **Версионное сохранение:** только рабочая копия/новая редакция через GUP-2 с проверкой `expected_revision`/SHA-256, АВ, проверками ZIP/macro, возможностью `409 Conflict`, аудитом. Запрет на last-write-wins и изменение WORM-оригинала.
4. **Real-time:** общий room только для *одной проверенной ревизии* DOCX/XLSX/PPTX на принятом локальном офисном сервере. Нужны реальный WOPI host (CheckFileInfo/GetFile/**PutFile**), проверка ACL/AD на каждом запросе, WOPI proof, отзыв прав, корпоративная модель версий, и тест на двух независимых сотрудниках. Код PR [#24](https://github.com/avers2604/get-pdf/pull/24) read-only; PR [#27](https://github.com/avers2604/get-pdf/pull/27) — прототип real-time логики, **не работающая end-to-end служба**.
5. **Локальные tests:** GUP-2 Django/PostgreSQL 16/18 и Windows/Linux .NET 10; форматы и сложные документы; реальный корпоративный сертификат; отзыв доступа во время загрузки; ДСП/ОСП; конфликт двух сохранений; потеря сети; 2/5/10 совместных пользователей.

Сохраняем принятый стек и продуктовые решения: кроссплатформенное Avalonia/Core, собственный UI ГЭТ, source-first, максимальная совместимость с Microsoft Office, существующие PDF-функции, без второго файлового сервера, без дополнительной веб-версии. ГЭТ System остаётся отдельным необязательным будущим потребителем.
