# GD-31J.27ap — экран диагностики аварийных копий (ГЭТ Документ, дизайн 4.1)

**Состояние:** код в отдельной Draft-ветке поверх GD-31J.27ao / PR #154, не подключён к production SaveAs/EuroOffice Native/GUP-2. Сборка C#, GUI и Windows/Astra VM-тесты пока не выполнялись. Дизайн-система 4.1 является ориентиром, фактическая пиксельная/UX приёмка не подтверждена.

## Где находится

`src/GetDocument.Desktop/MainWindow.cs`: на главной странице единого GET-лаунчера добавлен раздел «Диагностика» с плиткой «Аварийные копии». Для открытия необходимо предварительно выбрать сохранённый документ DOCX, XLSX или PPTX в обычной вкладке. При отсутствии активного документа или неподдерживаемом формате выводится сообщение в строке состояния — никаких файловых операций.

Плитка открывает `RecoveryDiagnosticsPane` в **том же TabControl**, не в отдельном окне. Для одного документа создаётся не более одной диагностической вкладки. Повторное нажатие переключает на уже открытый экран. Крестик и Ctrl+W закрывают вкладку; закрытие самого исходного документа автоматически завершает диагностическую вкладку и отменяет поиск. При закрытии всего приложения панель освобождает ресурсы.

## Как выглядит

`src/GetDocument.Desktop/Recovery/RecoveryDiagnosticsPane.cs`: компактный прокручиваемый интерфейс на Avalonia с существующими ресурсами GetTheme.axaml: `title`, `hint`, `section`, `card`, `toolbar` и кистями `GetNavyBrush`, `GetMutedBrush`, `GetRedBrush`.

- Заголовок «Диагностика аварийных копий», предупредительный текст о непроверенности данных;
- имя **только выбранного** документа (без полного абсолютного пути);
- единственная кнопка «Обновить сведения»;
- индикатор обработки и итоговое состояние с доступным для экранного диктора вежливым оповещением;
- карточки обнаруженных объектов: тип, имя, уровень доверия, *лишь для обычных файлов* — размер и время изменения;
- постоянное пояснение, что никаких удалений и автоматического восстановления нет.

Фактический `OfficeRecoveryStore.InspectIncomplete` вызывается через `Task.Run`, чтобы не блокировать Avalonia UI при локальном файловом осмотре. В `RefreshAsync` используется сохранённый `CancellationToken` и отключение кнопки на время работы; закрытие панели отменяет проверку. Исключения доступа или подозрительного корня выводят **отказ** без раскрытия ОС-пути и без утверждений об исправности.

## Семантика состояний

- `RegularUnverified` → «Обнаружен · не проверен». Размер и время — только метаданные, не доказательство сохранности OOXML.
- `UntrustedLinkOrNonFile` → «Недоверенный объект: ссылка или каталог». Метаданные цели не показываются.
- `MetadataUnavailable` → «Метаданные недоступны». Это не считается пустым или безопасным каталогом.
- `Truncated=true` → «Список неполон», даже если найдено ноль подходящих объектов. Ограничение 256 просмотренных элементов (не 256 совпадений).
- Пустой полный результат → «Временные файлы по шаблону не обнаружены», **не** «ошибок нет», «готово к восстановлению» или «очистка безопасна».

Полное имя файла (GUID в служебном имени) показывается как *обычный текст*; HTML/Markdown-интерпретации нет. При смене пользователя источником служит локальный per-user recovery-каталог. Никакого общего сканирования других источников, поиска по сети или раскрытия содержимого JSON/ZIP.

## Гарантии и известные ограничения

- **Не реализовано:** кнопки «Удалить», «Очистить», «Восстановить», открытие копий, автономный запуск EuroOffice, WORM/CAS или редакторские привилегии. UI не делает `File.Read*/File.Write*/File.Delete/File.Move`.
- Проверка наличия имён не подтверждает, что процесс-экспортёр прекратил работу; нельзя считать любой обнаруженный временный файл «мусором». Нет фоновой очистки.
- Путь-основанная проверка не предотвращает враждебные TOCTOU-гонки и не эквивалентна аттестации NTFS/SMB/ext4 или DAC/MAC-политик Astra Linux.
- Сборка текущего Avalonia UI, проверка на DPI 100–200%, экранном дикторе, малых экранах, Windows 10/11 и Astra Linux **не проведена**. Размер карточек и компоновка являются проектным кодом; внешний вид в реальном продукте ещё не подтверждён.
- Прямой `OfficeRecoveryStore` также остаётся лабораторно непроверенным на указанных ОС. Main, Native SaveAs publication, оригиналы и корпоративные файловые связи не затрагиваются.

## Регрессионные контракты и локальная приёмка

`scripts/tests/test_recovery_diagnostics_ui_contract.py` содержит 5 source-only Python тестов: отсутствие действий записи/очистки, ровно одна интерактивная кнопка, честные состояния, повторное использование DS 4.1, вкладка и lifecycle текущего документа. В `scripts/office_acceptance.py` добавлен ранний offline source-check до NuGet restore; `scripts/tests/test_office_acceptance.py` оставляет GUI ручные проверки для Windows и Astra Linux в статусе `not-run`.

После доступности одобренного SDK, **не включая GitHub Actions**:

```sh
python3 -m unittest discover -s scripts/tests -p test_recovery_diagnostics_ui_contract.py -v
dotnet restore src/GetDocument.Desktop/GetDocument.Desktop.csproj --source /path/to/approved/offline-nuget -p:NuGetAudit=false
dotnet build src/GetDocument.Desktop/GetDocument.Desktop.csproj -c Release --no-restore
dotnet test tests/GetDocument.Office.Tests/GetDocument.Office.Tests.csproj -c Release --no-restore --filter FullyQualifiedName~OfficeRecoveryIncompleteInventoryTests
```

После сборки на отдельном GUI-стенде проверить: отображение русских и длинных имён, DPI и скроллинг, закрытие во время обработки, кнопку обновления, отсутствие фонового удаления, озвучивание состояния, Ctrl+W, разделение нескольких документов, доступ к NTFS/SMB/Astra Linux и отмену. До этого `releaseReady=false`.
