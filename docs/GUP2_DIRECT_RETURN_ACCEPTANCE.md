# ГЭТ PDF — защищённый возврат в GUP-2 по одноразовому коду

**Статус:** код Windows-клиента и сервера подготовлен, интеграционные
тесты и включение в эксплуатацию **ещё не выполнены**. GUP-2 и
ГЭТ PDF — независимые репозитории.

## Строгий UX и протокол

1. В браузере пользователь входит в GUP-2 и открывает доступную ему
   карточку **черновика**. При включённом серверном
   `GETPDF_DIRECT_RETURN_ENABLED=1` получает одноразовый код
   через защищённый POST/CSRF. Код 43 URL-safe символа,
   действителен 5 минут и используется однократно.
2. Сохранить PDF отдельно от оригинала (изменённые страницы, форма,
   текстовые комментарии или интерактивные /Square-/Highlight-аннотации).
   Оригинал WORM нельзя перезаписать.
3. На **управляемой** Windows-станции ИТ-служба должна разрешить:
   ```json
   {
     "Version": 1,
     "AllowGup2Portal": true,
     "AllowGup2DirectReturn": true,
     "Gup2PortalUrl": "https://gup2.corp.example/documents/"
   }
   ```
   Адрес — пример, не действующий URL. До приёмки оба флага прямого
   возврата должны быть **выключены**.
4. В ГЭТ PDF: «Документ → Отправить PDF-копию в GUP-2…».
   Ввести выданный код, выбрать **готовую копию** (до 256 МиБ),
   нажать «Отправить через HTTPS».
5. Клиент не читает cookie, JWT или пароль браузера; отправляет
   одноразовый код только в HTTPS-заголовке.
   Проверка системной цепочки TLS обязательна, редиректы запрещены.
   Сервер повторно проверяет ACL, ДСП/ОСП, WORM SHA, edit_version,
   статус пользователя и post-AV SHA. Код сгорает до обработки PDF.
6. HTTP 201 означает **только приём на обработку**.
   Присутствие и готовность новой копии в WORM проверяются в карточке
   GUP-2. Это не юридическая публикация новой редакции.

## Контрольные сценарии

- Верный код и подготовленная новая копия → одно приложение черновика,
  исходный SHA-256 неизменен.
- Дублирующий POST, украденный/просроченный код, неверный document,
  отозванная роль, изменённый auth_version, новый WORM SHA или
  edit_version → отказ до WORM.
- HTTP, кросс-доменный браузерный Origin, неправильный HTTPS-сертификат,
  HTTP 302, отсутствие поля файла, размер 0 или свыше 256 МиБ → отказ.
- Тестировать 2 конкурентных отправки одного кода в PostgreSQL:
  только один поток может его расходовать.
- Прерывание связи/отмена после POST → код может быть уже израсходован;
  получить новый и проверить карточку до повторной отправки.
- Запрет передачи кодов в access-логи reverse proxy, analytics/APM,
  дампы и сервисные журналы; очистка старых грантов.
- Проверить внешнюю печать, визуальное представление аннотаций,
  подписи/КриптоПро и MSI отдельно.

## Что ещё обязательно до включения

Реальная Windows .NET 10 сборка, MSTest, PostgreSQL Django-тесты,
AV/SILO Object Lock, защищённое развёртывание TLS, E2E под нагрузкой.
В текущем окружении эти испытания не выполнялись и флаги выключены.

Детали серверной стороны: `Gup-2/docs/GETPDF_DIRECT_RETURN_SECURITY.md`.
