# GD-31J.20 — локальные рабочие копии EuroOffice Desktop и безопасное «Сохранить копию»

**29 октября 2026** · **База:** Draft PR #89 (GD-31J.19) · **Статус:** исходный код и тесты добавлены, реальная сборка и запуск не проводились.

## Назначение

Это первый кодовый блок для дальнейшего реального сценария «открыть → редактировать → сохранить» в единой вкладке ГЭТ. **Сам EuroOffice Desktop в этот PR не встраивается и через CEF не запускается.** Для настоящего native editor ещё требуется подтверждённый API сохранения, sandbox, OS IME, кроссплатформенная интеграция и GUI E2E.

Добавлен `EuroOfficeOfflineDraftSession`, работающий исключительно с локальными файлами/байтами OOXML и не имеющий ни прямого вызова CEF, ни сетевых полномочий.

## Контракт безопасности

- Вход: явный полный путь DOCX/XLSX/PPTX и **заранее созданный** личный staging root, предоставленный приложением. Произвольный клиент не должен выбирать публичный каталог. Явные UNC/сетевые пути для корня черновиков запрещены (сетевые диски, замаскированные под локальные, должны отклоняться политикой развёртывания). На Linux/macOS новый каталог сессии создаётся с правами `0700` сразу, без промежутка открытого доступа; на Windows применяются унаследованные ACL, которые необходимо проверить при настройке staging root.
- До открытия CEF исходный файл проверяется на отсутствие symlink/reparse, размер до 128 МиБ и **базовую ZIP/OPC структуру**: `[Content_Types].xml`, `_rels/.rels`, основной XML-элемент по расширению. Число элементов, заявленный распакованный размер, дубликаты имён, обход пути и `vbaProject.bin` ограничиваются. Это **не** полный ISO/IEC 29500 validation, не антивирус и не proof of compatibility.
- Создаётся отдельный `working.docx/xlsx/pptx`, вычисляется SHA-256 исходника до/после копирования, проверяется совпадение с рабочей копией. Несовпадение или недоверенная структура прерывают старт.
- `session.json` содержит ID, исходный путь, имя рабочего файла, исходный SHA-256, `state=unverified-native-edit`. Метаданные **не являются** доказательством того, что CEF открыл/изменил/сохранил документ.
- Экспорт доступен через `SaveAsNewCopyAsync(target, userApproved: true)` только по явному действию пользователя. Проверяется неизменность исходника (до и после копирования), рабочая копия, расширение, hash скопированных байтов. Сначала создаётся уникальный временный файл рядом с целью, вызывается `Flush(true)`, затем `File.Move(... overwrite:false)`: **цель/исходник/WORM не перезаписываются**.
- При конфликте исходника, отказе записи, повреждённом ZIP или выключенном разрешении **пользовательский черновик сохраняется в staging**, автоматического удаления рабочих копий нет. Отдельный UI восстановления, политики шифрования/retention и проверка окончания записи нативным редактором — следующий этап.

## Проверяемые сценарии, описанные тестами

1. Побайтово идентичный черновик и неизменность оригинала.
2. Сохранение новой `xlsx` копии после изменения working файла, без перезаписи оригинала.
3. Запрет записи поверх существующего `pptx` и самого источника.
4. Запрет неподтверждённой операции и конфликт при изменении исходного документа.
5. Запрет неверного расширения, повреждённого ZIP, VBA и path traversal.
6. Приём валидных явных каталогов внутри ZIP.
7. Сохранение recovery-копии после успешной записи или ошибки.\n8. Отказ при явном сетевом UNC-каталоге для черновиков.

Тесты в `tests/GetDocument.Office.Tests/EuroOfficeOfflineDraftSessionTests.cs` входят в уже существующий `GetDocument.Office.Tests` и в offline acceptance runner. **Они написаны, но не запущены; это не green test report.**

## Границы подключения к настоящему приложению

Этот компонент **не подключён** к обычной кнопке «Открыть» и не подаёт корпоративные документы в неподтверждённый CEF. Это сознательная мера безопасности: у существующей Wayland CEF-лаборатории только три синтетических файла и нет подтверждённой операции native Save. Не использовать `ASC_MENU_EVENT_TYPE_CEF_ONSAVE` как доказательство fsync, целостности или прохождения round-trip. До upstream API review + isolated lab всё остаётся за изолированной подготовкой.

Далее: сверка pinned Euro-Office desktop-sdk API реального сохранения на staging, явный ACK от редактора, ожидание завершения записи, повторное чтение файла, полномочия, crash recovery UI и потом соединение с GET вкладками. Для Windows/Astra X11 пока сохранить LibreOffice/UNO fallback. Реальные корпоративные файлы в неподтверждённом CEF не открывать.

## Ограничения и долги

- Атомарный rename и `Flush(true)` защищают от типовых неполных копий, но не являются универсальным обещанием сохранности при потере питания или на всех SMB.
- Snapshot hash — обнаружение конфликта, а не блокировка других редакторов и не проверенный серверный CAS. Между последней проверкой хэша и rename возможна гонка изменения источника. Серверный CAS/WORM не подменяется этим кодом.
- Вручную проверить ACL, plaintext at rest, secure staging, пакетные ограничения, конкуренцию и crash recovery на Windows/Astra/ALT/РЕД. Согласовать доступность приватного root и политику хранения.
