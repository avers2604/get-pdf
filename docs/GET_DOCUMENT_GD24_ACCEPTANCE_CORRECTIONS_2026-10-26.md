# GD-24 — исправления по итогам аудита GD-16–GD-23

Дата: 26.10.2026. Основание: PR #48. Статус: Draft — сборка и аппаратные испытания ещё необходимы.

## 1. Переполнение stdout печатающего процесса

В GD-23 ограничили память чтения вывода драйверов, но переполнение stdout для запущенного `lp` или Windows PrintWorker ошибочно классифицировалось как повреждение PDF. Пользователь мог попытаться распечатать ещё раз, хотя задание уже было принято.

Теперь для **запущенного** процесса печати переполнение формирует типизированный `PrintSubmissionException` с `MightBeQueued = true`. Пользователю предлагается проверить очередь, повторное задание в открытом мастере остаётся заблокированным. Для непечатающих команд превышение лимита остаётся ошибкой протокола. Изменён интеграционный тест, имитирующий более 100 КиБ ответа `lp`.

## 2. Приватность сообщений

`PrintWizardPane.InitializeAsync`, `PrintWizardPane.LoadPrintersAsync` и `OfficeEditorPane.PreparePrintableAsync` раньше выводили `ex.Message`. PDFium, драйверы и LibreOffice могут помещать туда реальные пути сетевых документов или имена пользователя. Теперь в этих трёх местах выводятся фиксированные сообщения без деталей драйверов и путей.

## 3. Абсолютно изолированная подмена CUPS в тестах

В GD-22 тестовый `FakeCups` задавал `PATH = fakeDir + originalPath`. При отсутствии одного имитатора могла запуститься системная команда печати. Теперь `PATH` во время теста содержит **только каталог с имитаторами**. Они используют абсолютный `#!/bin/sh` и встроенные shell-команды. После завершения исходный PATH восстанавливается.

Добавлены тесты: тестовый PATH исключает реальный `lp`; отсутствие имитатора `lp` приводит к отказу `TransportUnavailable`, `MightBeQueued = false`, без передачи задания.

## 4. NuGet-источник действительно локальный

- Windows: офлайн-проверка отклоняет UNC, сетевые/mapped-диски, символьные ссылки и junction; разрешает фиксированные и съёмные локальные диски.
- Astra/ALT/РЕД Linux: проверяет `findmnt -T`, отклоняет symlink-каталог и известные сетевые FS (NFS/CIFS/SMB/sshfs/DAVFS/9p/Ceph/GlusterFS/Lustre).
- Оба скрипта восстанавливают зависимости только из явно предоставленного `--source` и запускают build/test с `--no-restore`; `NuGetAudit=false` предотвращает обращение к внешнему сервису аудита пакетов в закрытом контуре.

Это **не сетевая песочница**: на административном стенде необходим физически закрытый Интернет-маршрут; отдельно проверяются хэши, подписи, версии и лицензии пакетов. Глобальный NuGet cache может содержать предварительно загруженные пакеты, поэтому восстановление не доказывает полноту пакета для чистой машины.

## 5. Возвращены регрессионные проверки старого GET PDF

- Windows: дополнительный офлайн `restore/build GetPdf.slnx` и `tests/GetPdf.Tests`, чтобы обновлённый документный модуль не сломал legacy viewer.
- Linux: `packaging/test-register-get-document-linux.sh` включён и в строгий офлайн-скрипт регистрации приложения.

## Команды локальной приёмки

Astra Linux:

```bash
bash scripts/verify-get-document-offline-linux.sh /srv/get/nuget-feed
```

Windows:

```powershell
pwsh -File scripts/verify-get-document-offline-windows.ps1 -OfflineNuGetFeed 'D:\GET\NuGetOffline'
```

Нужно сохранить версию SDK, полный build/test log, Passed/Failed/Inconclusive, результаты PrintWindows, Office, legacy PDF и физической печати на принтерах с A4/A3/дуплексом и разными лотками.

**В доступном окружении `dotnet`, `pwsh` и `lp` отсутствуют.** Исходники и тесты изменены через GitHub, но не исполнялись в .NET; реальные МФУ не тестировались. PR остаётся Draft. Ветка Euro-Office PR #42 остаётся отдельной, GUP-2 ACL, WORM-оригиналы и исходные Office-документы не изменены.
