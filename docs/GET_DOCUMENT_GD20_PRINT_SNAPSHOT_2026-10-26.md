# GD-20 — заморозка PDF перед печатью, SHA-256 и очистка рабочих копий

**Дата:** 26 октября 2026. **Основа:** PR #44 (GD-19). **Статус:** Draft / код не прошёл свежую локальную сборку.

## Исправленная проблема

До GD-20 мастер PDF показывал файл по исходному пути и позднее повторно открывал этот путь для печати. Файл мог измениться между предпросмотром и передачей в очередь (автоматическое сохранение Office, другая программа, изменение сетевой папки). Оператор видел старую версию, но печаталась новая. Особенно важен сценарий Office → Export PDF → мастер печати ГЭТ, включающий несохранённые в редакторе изменения.

После GD-20 один запуск мастера работает с **одной проверяемой PDF-копией**:

1. `PrintFileSnapshot.CreateAsync` проверяет путь, размер до 128 MiB и заголовок `%PDF-`, копирует содержимое в уникальный каталог задания текущего пользователя `LocalApplicationData/GET-Document/PrintJobs/job-{GUID}/document.pdf`, считает SHA-256 по читаемым байтам.
2. Предпросмотр и все дополнительные страницы по запросу читаются только из этой копии, не из оригинального PDF и не из обновляемой сетевой папки. Пользователь видит ровно подготовленную редакцию.
3. При подтверждении печати копия повторно проверяется по длине и SHA-256. `LocalPrintBroker.SubmitPdfAsync` также проверяет хэш **перед** CUPS/Windows submit; параметры, буфер и путь не проходят через shell.
4. На Windows отдельный `GetDocument.PrintWindows.exe` получает ожидаемый хэш в локальном JSON-запросе, самостоятельно сверяет его перед PDFium/PrintQueue. В CUPS файл передаётся в очередь после локальной проверки; удержание и физическая печать далее зависят от службы печати.
5. По завершении/закрытии мастера его приватный каталог удаляется. Если процесс печати на Windows ещё держит файл, удаление может не получиться; это не считается успешной очисткой. Для аварийно оставленных **распознаваемых** заданий предусмотрена осторожная чистка каталогов старше 7 дней при следующем создании снимка. Программа не переходит по symlink/reparse-point и не удаляет чужие или нестандартные папки.
6. Созданный специально для печати документом Office PDF в `Get-Document-print` удаляется после успешной подготовки приватной копии или при закрытии мастера. Удаление разрешено **только при явной метке от `MainWindow` для OfficeEditorPane** и точном соответствии разрешённому каталогу. Исходные документы и WORM-оригиналы никогда не удаляются. Временные PDF изменённого документа `PdfWorkspacePane` остаются под управлением сессии PDF-модуля.

### Безопасность и эксплуатация

- Работа полностью локальная, не требует доступа в Интернет или к серверу GUP-2.
- Unix-каталоги заданий получают `0700`, PDF `0600`. На Windows каталог размещён под локальными данными текущего пользователя; необходима проверка корпоративных ACL.
- SHA-256 — контроль целостности внутри локального процесса, **не электронная подпись**, не аттестация печати и не доказательство того, что документ физически вышел из принтера.
- В случае ошибки записи, недостатка места, PDF большего 128 MiB или неуспешного сравнения SHA печать не продолжается. Ограничения UI, принтерных возможностей, диапазонов страниц, color/duplex/trays наследуются от GD-16..GD-19.
- Невозможность удалить уже принятый драйвером spool job и невозможность гарантировать немедленное удаление занятого файла отражаются в пользовательском статусе и критериях приёмки.
- Для файлов со старым нестандартным заголовком PDF, без `%PDF-` в первых пяти байтах, мастер возвращает ошибку вместо риска неоднозначного определения формата; валидные нетипичные PDF требуют отдельного теста и политики поддержки.

## Тесты и приёмка

`PrintFileSnapshotTests`:
- PDF-предпросмотр/печать не меняются, если исходный файл позднее переписан;
- изменённая приватная копия отклоняется по SHA-256;
- `Dispose` удаляет приватный job-каталог;
- не-PDF или слишком большой PDF не допускается;
- при новом задании удаляется только распознаваемый старый job, посторонняя папка не трогается.

Windows локально:
```powershell
pwsh -File scripts/verify-get-document-windows.ps1
pwsh -File scripts/windows-build-get-document.ps1
```
Linux:
```bash
bash scripts/verify-get-document-linux.sh
```

После сборки обязательно испытать:
- обычный PDF и WORM-оригинал (оба не меняются);
- Office-документ с несохранёнными правками, повторным сохранением после открытия мастера и закрытием обеих вкладок;
- редактируемый PDF `PdfWorkspacePane`, сетевой SMB-файл, изменение источника после открытия;
- подмену приватного PDF перед нажатием «Печать» и между процессами Windows;
- права Linux Astra/ALT/РЕД на `LocalApplicationData`, ошибки «диск заполнен», свободное место для 128 MiB и аварийное завершение;
- 1000-страничный файл, нагрузку на старых ПК, дуплекс/A4/A3/цвет/лотки;
- одно задание без повтора при неоднозначном ответе spooler.

**В среде текущего исполнения нет .NET 10, Windows Print Spooler, CUPS или реальных МФУ. Это написанные исходники/тесты, не проверенная сборка.** PR остаётся Draft до локальной лабораторной проверки; GitHub Actions не включать, main и старый «ГЭТ PDF» не изменять.
