# GD-31J.27an — безопасные аварийные копии и эксклюзивный манифест

**Статус: stacked Draft поверх GD-31J.27am (#152).** Изменение существующего кроссплатформенного .NET 10 модуля OfficeRecoveryStore в ГЭТ Документ. Никаких прав на WORM, настоящие документы, native SaveAs или GitHub Actions не предоставляется.

## Конкретные найденные ошибки

1. До исправления ZipFile.OpenRead и проверка SHA-256 читали временный OOXML-файл, не отвергая символическую ссылку на источник. Это не независимая резервная копия.
2. FindLatest и ReadManifest могли принять уже опубликованную ссылку на другой файл, если его содержимое/JSON совпадало.
3. Каталог восстановления мог быть подменён symlink/junction, включая сценарий Discard.
4. **Критичная ошибка:** File.WriteAllTextAsync для временного JSON-манифеста перезаписывал существующий файл по тому же пути. Экспортер знал случайное имя временной OOXML-копии и мог создать ссылку с соответствующим именем JSON.tmp на посторонний файл. Запись проходила по ссылке до последующих проверок и могла изменить его содержимое.

## Сделано в коде

- Проверка DirectoryInfo.LinkTarget и FileAttributes.ReparsePoint по всем компонентам пути перед созданием каталога, перед записью и перед чтением/удалением; повторение проверки после создания каталога.
- Проверка FileInfo.LinkTarget для временного пакета, опубликованного пакета и JSON-манифеста. Ссылка не предлагается как валидное восстановление.
- Проверка файлов повторно непосредственно перед окончательной публикацией, после SHA-хеширования.
- File.WriteAllTextAsync для манифеста заменён на FileStream в режиме **FileMode.CreateNew**, с FileAccess.Write, FileShare.None и Flush(flushToDisk:true). Уже существующий путь, включая ссылку или hardlink с таким же именем, отвергается до записи. Размер JSON ограничен 2048 байт.
- Сохранены независимая ZIP/XML проверка, хеширование SHA-256, не более трёх обычных версий, запрет перезаписи источника и WORM-ограничения.

## Новые регрессионные тесты

В tests/GetDocument.Office.Tests/OfficeRecoveryStoreLinkSafetyTests.cs добавлено **6 MSTest** на синтетических DOCX:

- подмена временного OOXML символической ссылкой на оригинал;
- подмена JSON.tmp ссылкой на посторонний файл — проверка, что он не меняется;
- подмена опубликованной копии ссылкой с совпадающим SHA;
- подмена манифеста ссылкой на валидный JSON;
- подмена папки восстановления перед CaptureAsync;
- запрет Discard/FindLatest через подменённый корневой каталог при сохранности существующей копии.

Имеющиеся OfficeRecoveryStoreTests.cs сохранены без изменения.

## Ограничения и приёмка

Это защита от **уже присутствующих** ссылок и занятых имён, не доказанная защита от атакующего TOCTOU/подмены файлов после проверки. Жёсткие ссылки на файл под другим именем не определяются через LinkTarget. Flush манифеста не означает гарантии сохранения каталога при сбое питания. Для устойчивой публикации кода враждебного экспортера понадобится проверенный OS-handle-bound broker и независимая приёмка.

В текущем чате **не выполнены** сборка C#, запуск MSTest, Windows/Astra Linux/SMB, реальные сбои питания и тесты редактора. Новые тесты не считать пройденными. После подготовки разрешённого .NET 10 SDK и офлайн NuGet feed:

    dotnet test tests/GetDocument.Office.Tests/GetDocument.Office.Tests.csproj -c Release --no-restore --filter FullyQualifiedName~OfficeRecoveryStore --logger trx

Затем обязательна ручная приёмка на NTFS, Astra Linux и изолированном SMB. Все E2E остаются not-run; main не меняется.
