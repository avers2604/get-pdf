# GD-31J.27f — ограничения native SaveAs v2, явное разрешение оператора и закрытие CEF

Дата: 1 ноября 2026 года. База: Draft PR #118 на PR #117. Состояние: исходники и тестовые сценарии подготовлены; сборка C++, Python/MSTest и реальные испытания Qt/CEF/Wayland намеренно отложены. Это только синтетическая лаборатория, не пользовательский Save As.

## Выявленные проблемы

В предшествующей native v2-ветке счётчики запросов, OnSave и последовательных номеров увеличивались без ограничений. При потоке callback это могло переполнить signed int, хотя валидаторы отвергали превышение порога. Срабатывание обычного 90-секундного тайм-аута не позволяло нормально завершить эксперимент после корректного OnSave. Диалог вооружался автоматически после ready, без явного разрешения оператора. Перед уничтожением CEF view требовалось более строго отсоединять слушателя и не допускать обращений к уничтоженному объекту.

## Что изменилось в GD-31J.27f

1. Новый native_saveas_event_budget.h содержит атомарный CAS TickBounded и пределы: 64 диалога Save As, 64 OnSave, 128 serial событий. При переполнении v2EventBudgetOverflow и v2TerminalAbort становятся терминальными. Помимо трёх общих счётчиков ограничен счётчик валидных запросов в новом v2-режиме. Старый pinned v1 оставляет свою прежнюю логику.

2. Только для команды --open-staged-native-saveas-event-v2-lab показана кнопка «Разрешить один тестовый Save As (только изолированная ВМ)». Она изначально недоступна; становится активной только после cefViewLoaded, onContentReady, modified, bindingSeen, conversionObserved при отсутствии сохранений и ошибок. Нажатие однократно выставляет v2OperatorApproved и немедленно v2DialogArmed на Qt owner thread. Кнопка запрещает второе разрешение и сама ничего не сохраняет. Реальное действие Save As инициируется оператором отдельно через доступное меню/команду редактора на одноразовом стенде; наличие такой команды в текущей сборке SDK ещё не доказано.

3. nativeSaveSettleTimer отслеживает успешную пару: один Save As dialog, один OnSave, правильный порядок 1→2, отсутствие terminal/overflow/cancel, подтверждённый ответ и разрешение оператора. Если эти признаки остаются стабильными 2000 мс, вызывается app.quit до общего 90-секундного safety timeout. Любое нарушение обнуляет часы наблюдения; двухсекундное окно не считается доказательством физической записи на диск.

4. Native observer получает RAII счётчик v2CallbacksInFlight. После завершения Qt event loop выставляется v2CallbacksClosed, запрещаются дальнейшие обновления native лабораторного состояния, и вызывается manager.SetEventListener(nullptr) ДО manager.DestroyCefView(). Затем выполняется ограниченное ожидание активных callback до 500 мс. Если счётчик не обнулился, лабораторный процесс возвращает код 15 без положительной квитанции, без публикации. Объект callback listener намеренно живёт до завершения одноразового ОС-процесса: он размещён в куче и не удаляется при shutdown, чтобы исключить уничтожение при наличии поздних внешних ссылок SDK. Это допустимый лабораторный компромисс, не подход для production-сервиса.

5. Формат getdoc-native-saveas-candidate-lab/1 остаётся отдельным от getdoc-native-saveas-pinned-event-lab/2. Никаких новых production-привилегий: nativeSaveProven, documentVerified, saveVerified и approvedForProduction по-прежнему false. Путь пользователя, WORM, SMB, обычная печать, GUP-2 и GET-system не изменялись.

## Подготовленные проверки

- test_native_saveas_event_budget_contract.py: наличие CAS ограничителей, отказ при превышении, отдельная кнопка оператора, контроль жизненного цикла, порядок отсоединения слушателя, неизменность форматов и запрет предоставления production прав.
- scripts/office_acceptance.py: новый offline pre-restore gate pinned-saveas-event-budget-lifecycle-source-contract-tests.
- Отдельный ручной gate eurooffice-pinned-v2-bounded-callback-shutdown-operator-ui-e2e; зарегистрирован в scripts/tests/test_office_acceptance.py.

### Обязательная матрица для будущей изолированной ВМ

| Сценарий | Ожидаемое поведение |
|---|---|
| Никакого клика оператора | Запрос не вооружён, результат не публикуется |
| Клик до ready или второй клик | Кнопка недоступна, повторного разрешения нет |
| Готовность, явный клик, один запрос и один OnSave | Лишь синтетический кандидат после 2 секунд тишины и независимого OOXML SHA/CRC/canary |
| Второй dialog или второй OnSave | Sticky отказ, никакой публикации |
| 65 диалогов, 65 OnSave или 129 суммарных событий | Счётчики ограничены, выставлен overflow/abort |
| Callback во время закрытия view | Listener sealed, проверка quiescence, отказ при незавершённом callback |
| Отмена, конфликт формата, неверный sender, авария | Нет кандидата |
| Общий 90-секундный тайм-аут без чистой пары | Нет кандидата |
| Повторение DOCX/XLSX/PPTX и старого pinned /1 | Отдельная проверка совместимости, сохранения не подтверждены без стенда |

## Незакрытые вопросы

Эти исходные проверки не удостоверяют Qt/CEF callback threading, реальный SDK menu SaveAs, гарантии SetEventListener(nullptr), подлинность загруженных библиотек, работу в Microsoft Office, совместное редактирование, атомарное fsync и отсутствие фоновых renderer событий. Истинные E2E на одноразовой офлайн Linux/Wayland VM обязательны. Прежний pinned /1 тоже нужно проверить на регрессию изменения порядка отсоединения listener.
