## Консолидировано в GD-28

1. `ReleaseReportEvaluator.cs`: применена проверка из №53 — GUID `TestRun id`, строгий `ResultSummary`, `Counters.executed/notExecuted`, `AreIndependentRuns` и отказ от повторного использования одного TRX как доказательства разных наборов.
2. `Program.cs`: **объединены** проверка независимости `TestRun` из №53 с проверкой фактической ОС и разделением `AutomatedTestsApproved` / `HardwareAcceptance=NotVerified` / `ReleaseAuthorized=false` из №54. Поле `IndependentRuns` публикуется в локальном JSON.
3. `ReleaseGateSelfTests.cs`: объединены тесты поддельных/дублированных TRX ID, неподдерживаемых итоговых статусов и противоречивых счётчиков из №53 с исправленным реальным DTD/XXE fixture из №54. Ни один набор правил не заменяет другой.
4. Сохранены Windows/Astra Linux preflight, офлайн NuGet, MTP CLI, система локальных отчётов и матрица аппаратной приёмки из №54.
5. Сохранена документация №53 рядом с №54 для трассировки происхождения проверок.

Оригинальные ветки №53/54 и Euro-Office №42/52 не перезаписываются и не закрываются. Если для GD-28 создан отдельный интеграционный PR, **использовать именно его для приёмки объединённого кода**, а не параллельно сливать №53 и №54 в `main`.

## Последовательность лаборатории

1. Сверить SHA ветки `integration/get-document-gd28-print-trx` с тестируемой копией репозитория; после каждого изменения кода повторять сборку/тесты.
2. Astra Linux: `bash scripts/verify-get-document-release-linux.sh /srv/get/nuget-feed`. Убедиться в самопроверке ReleaseGate, уникальных TRX GUID и `IndependentRuns=true`.
3. Windows: `pwsh -File scripts/verify-get-document-release-windows.ps1 -OfflineNuGetFeed 'D:\GET\NuGetOffline'`. Помимо GD-28 проверить старый GetPdf и экспорт несохранённых правок Office.
4. Провести физическую приёмку по `docs/GET_DOCUMENT_GD27_RELEASE_LAB_2026-10-27.md`: А4/А3, duplex, N-up, лотки, очередь, подписи/формы PDF, кириллица и WORM.
5. Отдельно обработать собственные коммиты `main` и серверный Euro-Office broker; только затем построить единый релизный кандидат и закрывать/сливать необходимые PR после проверки.

## Прозрачный статус

**Сборка .NET 10, MSTest, проверка настоящих Windows/Astra TRX и аппаратная печать в этой среде не выполнялись.** Интеграция подтверждена чтением и сопоставлением GitHub-файлов; отсутствие конфликтов GitHub не равно результату компиляции. `ReleaseAuthorized` остаётся `false`, GitHub Actions не включать, WORM-оригиналы не изменять.
