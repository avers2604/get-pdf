# ГЭТ PDF (Get PDF)

Отдельное локальное Windows-приложение для работы с PDF в СПб ГУП «Горэлектротранс». Исходная PDF-подсистема перенесена из [GUP-Scan](https://github.com/avers2604/GUP-Scan). **Сканирование, TWAIN/WIA, обнаружение сканеров и драйверов сюда не входят.** Исходный репозиторий сканирования пока сохраняется без разрушительных изменений.

## Возможности

- Просмотр PDF с непрерывной прокруткой, миниатюрами, оглавлением, безопасными внутренними ссылками, поиском, масштабом и клавиатурной навигацией.
- Несколько PDF одновременно: настоящие вкладки в одном окне, Ctrl+Tab, перемещение вкладки и её вынос в отдельное окно; каждый документ хранит собственное состояние и черновик.
- В режиме редактирования: копирование страницы в другой открытый PDF через команду или drag-and-drop миниатюры на вкладку, с сохранением **нового файла** без изменения исходников.
- Печать PDF по Ctrl+P и кнопке «Печать».
- По кнопке «Редактирование»: страницы, объединение и извлечение, разметка, OCR и изменение текста в поддерживаемых документах.
- Локальные черновики и атомарная запись выходного PDF, без сетевого сервиса.
- Независимые настройки и сеансы в каталогах GET-PDF, без пересечения с GUP-Scan. Восстановление путей вкладок и список недавних документов отключаются раздельно через корпоративную политику.

## Улучшения в ветке feature/pdf-workspace-improvements

Ветка содержит **код, ещё не подтверждённый Windows-сборкой**: отдельный поиск (Ctrl+F/F3/Shift+F3), переход к странице (Ctrl+G), недавние PDF, drag-and-drop, закладки, безопасные оглавление и внутренние ссылки, переключение непрерывного/одностраничного/двухстраничного просмотра, F11, сравнение двух PDF по тексту, предварительный просмотр фактических страниц печати, массовую нумерацию, разделение PDF (до 200 страниц за операцию), копирование текстового слоя страницы, ограничение памяти миниатюр и необязательную lossless-оптимизацию через одобренный qpdf.

**Границы текущей реализации:** вкладки реализованы в коде, но не проверены на Windows; сравнение не является визуальным; выделение текста мышью отсутствует; цифровые подписи не проходят криптографическую проверку; поля AcroForm анализируются, но пока не заполняются; нумерация — обычный видимый штамп, не электронная подпись. Остальные обязательные этапы указаны в [дорожной карте](docs/ROADMAP_IMPROVEMENTS_2026-10-20.md).

## Сборка и тесты (Windows/.NET 10)

```powershell
dotnet restore .\src\GetPdf\GetPdf.csproj
dotnet build .\src\GetPdf\GetPdf.csproj -c Release --no-restore
dotnet test .\tests\GetPdf.Tests\GetPdf.Tests.csproj -c Release
dotnet run --project .\src\GetPdf\GetPdf.csproj -- "C:\\Documents\\document.pdf"
```

**Статус проверки:** исходные файлы перенесены через GitHub; полноценный `dotnet build/test`, запуск WPF и печать на принтере требуют Windows/.NET и пока не подтверждены. До релиза провести локальные тесты и проверить PDF-движок, OCR, шрифты и печать. GitHub Actions для тестов не используется. Для локального Windows gate и MSI см. [инструкцию выпуска](docs/WINDOWS_RELEASE_GATE.md).

## Регистрация для Windows «Открыть с помощью»

Для зарегистрированного установленного `GetPdf.exe` выполните **от имени текущего пользователя**:

```powershell
.\packaging\register-pdf-capabilities.ps1 -ExePath "C:\Program Files\GET PDF\GetPdf.exe"
```

Скрипт не меняет выбор пользователя по умолчанию и не изменяет регистрации GUP-Scan. После регистрации выберите «ГЭТ PDF» для `.pdf` в настройках Windows.

## Разделение

`GUP-Scan` должен стать отдельной программой **сканирования**; его PDF-функции и ассоциацию `.pdf` можно удалять лишь после успешной приёмки этой независимой сборки. Ассоциацию Windows не менять без выбора пользователя.
