# ГЭТ Документ / GET Document

**Новая объединённая настольная оболочка документов СПб ГУП «Горэлектротранс»** для закрытого контура Windows/Linux: одно окно, лаунчер, общие вкладки PDF, Word, Excel, презентаций и изображений. Исходный проект «ГЭТ PDF» сохранён как legacy-клиент, пока новый клиент не достигнет паритета.

> **Статус: интеграционная ветка / не релиз.** Настольный интерфейс и часть локальных операций реализованы, но сборка и функциональные испытания в настоящем Windows/Linux окружении **не выполнены**. Базовые Office-редакторы не обеспечивают полной совместимости с Microsoft Office. Collabora/ONLYOFFICE серверное редактирование, сохранение через GUP-2, WORM/SSO и эксплуатационная проверка **не завершены**. Нельзя менять корпоративные ассоциации файлов или выводить из эксплуатации GetPdf.exe до приёмки.

## Что находится в репозитории

| Компонент | Расположение | Реальный статус |
|---|---|---|
| Единый лаунчер, общие вкладки | `src/GetDocument.Desktop` | Avalonia, исходный код; проверить UI на Windows/Linux |
| Файловая маршрутизация, single-instance IPC | `src/GetDocument.Core` | Локальные пути через per-user named pipe; не передавать GUP-2 токены |
| PDF | `src/GetDocument.Desktop/Preview` | Просмотр отдельных растровых страниц; полноценная печать/формы/редактирование остаются в legacy WPF |
| DOCX, XLSX, PPTX | `src/GetDocument.Office` | Создание файлов и ограниченное редактирование простых DOCX/XLSX; не полноценный Office |
| XLS/XLSB, изображения, шаблоны, файлы | `src/GetDocument.Desktop` | Просмотр/базовые операции, ограничения зависят от формата |
| Редакции и комментарии | `src/GetDocument.Revisions` | Локальный прототип, не GUP-2 corporate revision API |
| Совместная работа | `src/GetDocument.Collaboration` | Контракты сессий, конкурентного CAS и неизменяемых редакций |
| WOPI HTTP шлюз | `src/GetDocument.WopiGateway` | Код CheckFileInfo/GetFile/PutFile, default deny; реальный ACL store отсутствует |
| WOPI host | `src/GetDocument.WopiHost` | Отдельный серверный процесс, **по умолчанию deny-all**; не часть desktop |
| Старое приложение «ГЭТ PDF» | `src/GetPdf` | Сохранено без удаления до подтверждения функционального паритета |
| «ГЭТ Сканирование» | отдельный репозиторий | Не встраивать TWAIN/WIA и драйверы в этот репозиторий; интеграция в лаунчере пока заглушка |

## Сборка и локальная проверка

Требуется .NET SDK 10 и предварительно одобренные офлайн NuGet-зависимости. GitHub Actions не включать. Для Linux:
```bash
bash scripts/verify-get-document-linux.sh
dotnet run --project src/GetDocument.Desktop/GetDocument.Desktop.csproj
```

Для Windows PowerShell:
```powershell
.\scripts\verify-get-document-windows.ps1
dotnet run --project .\src\GetDocument.Desktop\GetDocument.Desktop.csproj
```

Ручная проверка перед выпуском: один/два процесса и пользователя, многовкладочность, реальные OOXML, SMB, отсутствие перезаписи WORM, PDF-печать/формы/подписи, безопасное открытие из GUP-2, совместная работа 2/5/10 пользователей и контроль прав. Без успешных результатов **не маркировать release-ready**.

## Совместимость и миграция

Для тестовых Windows-стендов можно **добровольно зарегистрировать** новый клиент в меню «Открыть с помощью», не меняя приложение по умолчанию и старый `GetPdf.PDF`:
```powershell
.\packaging\register-get-document-capabilities.ps1 -ExePath "C:\Program Files\GET Document\GetDocument.Desktop.exe" -OpenSettings
```

Для Linux (Astra/ALT/РЕД и другие desktop-системы) предусмотрена регистрация в пользовательском каталоге приложений **без изменения MIME по умолчанию**:
```bash
bash packaging/register-get-document-linux.sh /opt/get-document/GetDocument.Desktop
bash packaging/test-register-get-document-linux.sh
```
Скрипт требует существующий исполняемый файл и добавляет `get-document.desktop` только для текущего пользователя. Shell smoke-тест выполняется в изолированном временном `XDG_DATA_HOME`. Упаковку и цифровую подпись дистрибутивов выполнить отдельно.

Регистрация не является установщиком, не развёртывает сервер и не включает реальное совместное редактирование. До подписанного релиза сохраняются прежние пользовательские ассоциации и legacy-приложение.

## GD-14 — поиск в PDF и конфликт версий GUP-2 (25.10.2026)

В новой PDF-вкладке добавлен **поиск текстового слоя через существующий PdfPig**, а не внешний просмотрщик: `Ctrl+F`, `Enter`, `F3`, `Shift+F3`, переход между страницами, содержащими искомую фразу. Для полностью отсканированных файлов по-прежнему необходим OCR. **Подсветка отдельных глифов и полноценное редактирование/печать PDF ещё отсутствуют.**

Возврат DOCX/XLSX в GUP-2 теперь различает конфликт редакций `HTTP 409` (логика перенесена из PR #35). При конфликте **нет автоматического повторного отправления или перезаписи**. Копия остаётся у сотрудника.

Исходники и локальная приёмка: [GD-14 PDF text search](docs/GET_DOCUMENT_GD14_PDF_TEXT_SEARCH_2026-10-25.md). Сборка и MSTest ещё не выполнялись; GD-14 Draft.

## GD-16 — собственный мастер печати (25.10.2026)

Кнопка «Печать» и `Ctrl+P` для сохранённого PDF теперь открывают **собственную вкладку «Мастер печати ГЭТ»**, а не системный диалог. Внутри — три шага: выбор установленного принтера, диапазон/копии/A4/A3/дуплекс, подтверждение. Справа предварительно отображается первая PDF-страница.

Передача заданий: Windows — локальный headless WPF/XPS worker `GetDocument.PrintWindows.exe`; Linux — установленный CUPS (`lpstat`/`lp`). Установленные драйверы печати остаются необходимыми. Linux и Windows backends написаны, но на реальных принтерах ещё не проверены; Windows требует публикации worker вместе с desktop. **Это пока печать PDF, а не DOCX/XLSX/PPTX.**

Код, ограничения, сборка Windows и аппаратная приёмка: [GD-16 GET Print Wizard](docs/GET_DOCUMENT_GD16_CUSTOM_PRINT_WIZARD_2026-10-25.md). .NET SDK отсутствует в доступном исполнителе, сборка/MSTest не подтверждены.

## GD-17 — настройки корпоративного мастера печати (26.10.2026)

В мастере ГЭТ добавлены **ориентация, цвет/монохром и 2/4 страницы на листе**. Печатные возможности проверяются на стороне Windows-драйвера; на Linux явно выбранный цвет требует объявленного IPP `print-color-mode`. Для 2/4-up пока разрешён только весь документ, чтобы избежать неправильной интерпретации диапазонов страниц CUPS.

Это остаётся **собственным интерфейсом**, без стандартного PrintDialog. После одной попытки отправки повторное нажатие не создаёт второй тираж. Тесты написаны, **но GD-17 ещё не собран и не проверен на реальных принтерах**. Лотки и полноценная раскладка предпросмотра — отдельные задачи.

[Документация GD-17 и критерии приёмки](docs/GET_DOCUMENT_GD17_PRINT_ADVANCED_2026-10-26.md).

## GD-18 — лотки принтера и предпросмотр 1/2/4 страниц (26.10.2026)

Мастер печати ГЭТ получил выбор **реальных лотков выбранного МФУ**: `InputBinCapability` Windows и `InputSlot`/`media-source` Linux CUPS. Перед печатью лоток повторно проверяется; если принтер не предоставляет список, используется его настройка по умолчанию. Фиктивные лотки не добавляются.

Предпросмотр теперь отображает **реальные первые 1/2/4 страницы PDF** на макете одного листа. Миниатюры ограничены по памяти; перекомпоновка сетки не запускает PDFium заново. Макет приблизительный, не гарантирует точность драйверных полей и выбранного диапазона.

Реализация и критерии проверки: [GD-18 trays + preview](docs/GET_DOCUMENT_GD18_TRAYS_PREVIEW_2026-10-26.md). Новая реализация пока **не собрана и не испытана на принтерах**.

## GD-19 — предпросмотр выбранных PDF-страниц и принтерные поля (26.10.2026)

Собственный мастер печати ГЭТ теперь строит предпросмотр по **выбранному диапазону**, а не всегда от первой страницы PDF. Листы можно пролистывать стрелками; отсутствующие миниатюры подгружаются лениво, а кэш ограничен по памяти. При ошибке диапазона старый макет скрывается.

Дополнительно исправлена команда CUPS: для `number-up=2/4` больше не отправляется `-P`, поскольку CUPS считает *выходные* страницы, что могло бы исказить тираж. В Windows область размещения PDF теперь учитывает `PrintCapabilities(ticket).PageImageableArea` с проверкой геометрии и безопасным резервом. Итоговая сводка показывает оценку физических листов с учётом двусторонней печати.

Путь Office → подготовленный PDF → мастер ГЭТ уже присутствует в GD-16, поэтому повторный компонент не создаётся. [GD-19: изменения, ограничения и приёмка](docs/GET_DOCUMENT_GD19_PRINT_RANGE_PREVIEW_2026-10-26.md).

GD-19 — Draft: новые изменения ещё не собраны и не испытаны на реальных принтерах.

## GD-20 — печать неизменной копии PDF и контроль целостности (26.10.2026)

Мастер печати ГЭТ теперь создаёт **приватную копию выбранной PDF-редакции**; предпросмотр и отправка в очередь используют один и тот же файл, даже если оригинал успел измениться. SHA-256 сверяется перед печатью; Windows-компонент повторно сверяет контрольную сумму у себя. Приватные задания удаляются при закрытии мастера; распознаваемые аварийные копии старше семи дней очищаются при следующем запуске.

PDF, экспортированный исключительно для печати из локального Office-редактора, удаляется после подготовки копии. Исходный DOCX/XLSX/PPTX, PDF и WORM-оригиналы не изменяются.

Подробности, тесты и ограничения: [GD-20 print snapshot](docs/GET_DOCUMENT_GD20_PRINT_SNAPSHOT_2026-10-26.md). Новая реализация остаётся **Draft без подтверждённой сборки/аппаратной печати в этой среде**.

## GD-21 — обработка ошибок печати и проверка Office → PDF → мастер (26.10.2026)

Добавлена классификация отказов Windows PrintWorker и Linux CUPS: достоверное отклонение отличается от таймаута/неоднозначного результата. Оператор получает понятную причину, без утверждения о физической распечатке и без повторного задания при неопределённом исходе.

Ctrl+P во время экспорта Office защищён от параллельных запусков. Временные Office-PDF теперь хранятся в личном каталоге с непрозрачными именами, удаляются при ошибке/закрытии мастера и проверяются по обязательному SHA-256 в брокере и Windows worker. Исходные документы и WORM остаются неизменными.

Добавлены тесты классификации отказов, владения временными PDF, а также интеграционный LibreOffice-тест с несохранёнными правками → PDF → `PrintFileSnapshot`. **Новые тесты написаны, но в текущем окружении ещё не запущены**. [GD-21 — реализация и план локальной приёмки](docs/GET_DOCUMENT_GD21_PRINT_INTEGRATION_2026-10-26.md).

## GD-22 — тестовая печать без принтера и проверка приёма в очередь (26.10.2026)

Проверка печати на Linux теперь включает **реальный код `LocalPrintBroker` с поддельными командами `lpstat/lpoptions/lp`**. Изолированные тесты проверяют аргументы, SHA-256, исчезновение очереди, отказ принтера и варианты A3/дуплекса — ни один из них не отправляет документы на физическое устройство.

CUPS дополнительно проверяет поддержку **A3 и двусторонней печати** по опубликованным драйвером возможностям; неподдерживаемые настройки отклоняются до отправки. После вызова `lp` требуется настоящая квитанция с номером задания выбранной очереди; Windows-worker подтверждается точным `submitted`. Наличие номера не означает физически завершённую печать.

Локальная команда `bash scripts/verify-get-document-cups-simulator.sh`, также добавлена в `scripts/verify-get-document-linux.sh` и solution. [GD-22 — описание, тестовая матрица и аппаратная приёмка](docs/GET_DOCUMENT_GD22_PRINT_CUPS_SIMULATOR_2026-10-26.md).

**Shell-имитаторы проверены; C#-сборка/MSTest и реальные МФУ — пока не проверены** (нет .NET SDK/устройств в доступной среде).

## GD-23 — аудит цепочки печати и строго офлайн-проверяемая сборка (26.10.2026)

Аудит PR №39–47 выявил и исправил три проблемы: отсутствие проверки **one-sided** при явно объявленном IPP `sides`, неограниченный объём `stdout/stderr` процессов Windows/CUPS и возможность запуска `dotnet restore` с внешними NuGet-источниками при обычной приёмке.

Добавлен `BoundedProcessOutput` с максимальным объёмом памяти 64 КиБ для stdout и 8 КиБ для stderr; фиктивная CUPS-очередь теперь проверяет ответ более 100 КиБ. Добавлены регрессионные MSTest для API и режимов CUPS. Для закрытого контура предусмотрены **отдельные строгие** команды сборки без публичного feed:

```bash
bash scripts/verify-get-document-offline-linux.sh /srv/get/nuget-feed
```

```powershell
pwsh -File scripts/verify-get-document-offline-windows.ps1 -OfflineNuGetFeed 'D:\GET\NuGetOffline'
```

Список зависимостей PR и критерии release gate: [GD-23 — аудит и инструкция локальной приёмки](docs/GET_DOCUMENT_GD23_STACK_AUDIT_2026-10-26.md). **Новая реализация не собрана в текущем окружении: отсутствует .NET 10 SDK.** PR остаётся Draft.

## GD-24 — исправления итогового аудита печати (26.10.2026)

Исправлены три важных случая: большой ответ CUPS/Windows не должен считаться повреждением PDF, диагностические сообщения не показывают пути закрытых документов, а тестовые имитаторы `lp/lpstat/lpoptions` не могут случайно обратиться к системным принтерам из-за чужого `PATH`.

Офлайн-проверка Windows/Linux теперь отбрасывает сетевые источники NuGet, а Windows дополнительно собирает и тестирует старый `GetPdf.slnx`. Linux выполняет проверку регистрации приложения. ## GD-26 — самопроверка релизного контроля и строгая проверка TRX (26.10.2026)

Релизный модуль `GetDocument.ReleaseGate` теперь сам проверяет себя через `--self-test` на искусственных корректных и вредоносных TRX-отчётах. Он блокирует ложные имена тестов, непрошедшие дубликаты обязательных сценариев, несовпадающие счётчики, ошибки `ResultSummary`, повреждённый XML и внешние XML-сущности. ## GD-27 — подготовка лаборатории Windows/Astra Linux и акт физической печати (27.10.2026)

Перед `restore/build/test` теперь запускаются отдельные preflight-скрипты, которые проверяют .NET 10+, локальный NuGet feed и состав решения. Исправлен порядок аргументов `dotnet test` для MTP: `--results-directory` перед `--`, а `--report-trx` после него.
